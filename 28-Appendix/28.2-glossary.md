# Appendix 28.2 - Glossary

This is your one-stop dictionary for every important term in the book. When a word in a chapter trips you up, jump here for a plain-language reminder, then follow the arrow back to the chapter that explains it properly. Definitions are deliberately short; the real teaching lives in the linked sections.

## A

**Abbe error**, Position error that appears when the thing you measure is offset from the axis you measure along, multiplied by any angular wobble. A core idea in precision machine design. → see [30.3 Mechanical Engineering for Fab Tools](../30-Fab-Engineering/30.3-mechanical-engineering-for-fab-tools.md)

**ACID**, The four guarantees a reliable transaction makes: Atomicity, Consistency, Isolation, Durability. They ensure your data stays correct even when things crash mid-operation. → see [07.2 Design, Indexing, Transactions](../07-Databases/07.2-design-indexing-transactions.md)

**Activation function**, A small nonlinear function (like ReLU or sigmoid) applied to a neuron's output so a network can learn curves, not just straight lines. → see [14.2 Deep Learning](../14-ML-DL/14.2-deep-learning.md)

**ADR (Architecture Decision Record)**, A short document capturing one important design decision, why you made it, and what you traded off, so future-you remembers the reasoning. → see [27.2 Testing and Architecture](../27-Software-Engineering/27.2-testing-and-architecture.md)

**Agent (AI)**, An LLM-powered system that can plan, call tools, and act in a loop toward a goal, instead of just answering one prompt. → see [20.4 Agentic AI](../20-AI/20.4-agentic-ai.md)

**Amortized analysis**, Averaging the cost of an operation over a long run, so an occasional expensive step (like resizing an array) still counts as cheap per operation. → see [01.4 Complexity and Big-O](../01-Foundations/01.4-complexity-and-big-o.md)

**Array**, A contiguous block of memory holding elements you index by position; O(1) access, but resizing or inserting in the middle is costly. → see [02.1 Arrays](../02-Data-Structures/02.1-arrays.md)

**Assembly**, Human-readable mnemonics that map almost one-to-one onto a CPU's machine instructions. The lowest level you'll usually write by hand. → see [25.2 Assembly Programming](../25-Architecture/25.2-assembly-programming.md)

**Asymmetric encryption**, Encryption using a key pair: a public key anyone can use to encrypt (or verify), and a private key only the owner holds to decrypt (or sign). → see [12.1 Cryptography](../12-Security/12.1-cryptography.md)

**AST (Abstract Syntax Tree)**, A tree representation of source code's structure that a compiler or interpreter walks to understand and execute the program. → see [24.1 Lexing, Parsing, ASTs](../24-Compilers/24.1-lexing-parsing-asts.md)

**Attention**, The transformer mechanism that lets each token decide how much to "look at" every other token when building its representation. → see [14.2 Deep Learning](../14-ML-DL/14.2-deep-learning.md)

**Availability**, The fraction of time a system is up and serving requests, often quoted in "nines" (99.9% = three nines). → see [09.1 Scalability Fundamentals](../09-System-Design/09.1-scalability-fundamentals.md)

## B

**Backpropagation**, The algorithm that computes how much each weight in a neural net contributed to the error, by applying the chain rule backward through the layers. → see [14.2 Deep Learning](../14-ML-DL/14.2-deep-learning.md)

**Backpressure**, A signal from an overloaded consumer telling producers to slow down, so queues don't grow unbounded and crash the system. → see [09.5 Message Queues](../09-System-Design/09.5-message-queues.md)

**Backtracking**, A brute-force-with-pruning technique: try a choice, recurse, and undo it if it leads to a dead end. The engine behind solving mazes and Sudoku. → see [03.6 Greedy and Backtracking](../03-Algorithms/03.6-greedy-and-backtracking.md)

**Base subobject**, The complete base-class byte region embedded at the start of a derived C++ object; inheritance is containment at the byte level. → see [29.5 Classes and Object Layout](../29-Cpp/29.5-classes-and-object-layout.md)

**Bayes' theorem**, A formula for updating the probability of a hypothesis given new evidence: posterior ∝ likelihood × prior. → see [16.1 Statistics and Probability](../16-Data/16.1-statistics-and-probability.md)

**BFS (Breadth-First Search)**, Graph traversal that explores all neighbors at the current distance before going deeper; finds shortest paths in unweighted graphs. → see [03.4 Graph Algorithms](../03-Algorithms/03.4-graph-algorithms.md)

**Bias-variance tradeoff**, The tension between a model too simple to fit the data (high bias) and one too sensitive to noise (high variance). → see [14.1 ML Foundations](../14-ML-DL/14.1-ml-foundations.md)

**Big-O notation**, A way to describe how an algorithm's cost grows with input size, ignoring constants. O(n) scales linearly, O(n²) much worse. → see [01.4 Complexity and Big-O](../01-Foundations/01.4-complexity-and-big-o.md)

**Binary search**, Finding an item in a sorted array by repeatedly halving the search range; O(log n). → see [03.3 Searching](../03-Algorithms/03.3-searching.md)

**Binary Search Tree (BST)**, A tree where every left child is smaller and every right child is larger than its parent, giving O(log n) search when balanced. → see [02.5 Trees](../02-Data-Structures/02.5-trees.md)

**Bit**, The smallest unit of information: a single 0 or 1. → see [01.1 Data Representation](../01-Foundations/01.1-data-representation.md)

**Bytecode**, A compact, portable instruction set that an interpreter or virtual machine executes, sitting between source code and machine code. → see [24.2 Interpreters and VMs](../24-Compilers/24.2-interpreters-and-vms.md)

**Byte**, A group of 8 bits, the standard unit for addressing memory and encoding a character. → see [01.1 Data Representation](../01-Foundations/01.1-data-representation.md)

**B-tree**, A balanced, multi-way tree optimized for disk: shallow and wide so databases find rows in few page reads. The backbone of most SQL indexes. → see [07.2 Design, Indexing, Transactions](../07-Databases/07.2-design-indexing-transactions.md)

## C

**CAC (Customer Acquisition Cost)**, The total sales and marketing spend divided by the number of new customers it won. → see [21.1 Software Company](../21-Business/21.1-software-company.md)

**Cache**, A fast, small store of recently used data placed close to where it's needed, so repeat lookups skip the slow path. → see [09.2 Caching and CDN](../09-System-Design/09.2-caching-and-cdn.md)

**Cache line**, The fixed-size chunk (often 64 bytes) the CPU moves between memory and cache at once; touching one byte pulls in its whole line. → see [25.1 Computer Architecture](../25-Architecture/25.1-computer-architecture.md)

**Calling convention**, The agreed rules for how functions pass arguments, return values, and preserve registers across a call. → see [25.2 Assembly Programming](../25-Architecture/25.2-assembly-programming.md)

**Cap table**, The ledger of who owns what slice of a company: founders, investors, and option holders. → see [21.1 Software Company](../21-Business/21.1-software-company.md)

**CAP theorem**, In a distributed system facing a network partition, you can keep Consistency or Availability but not both at once. → see [07.4 Sharding, Partitioning, Replication](../07-Databases/07.4-sharding-partitioning-replication.md)

**Capex / Opex**, Capital expenditure (buying hardware up front) versus operating expenditure (renting it monthly, like cloud). → see [22.1 Mac Minis and Server Farms](../22-Infrastructure/22.1-mac-minis-and-server-farms.md)

**Cardinality**, The number of distinct values a field or label can take; high-cardinality labels (like user IDs) can blow up metrics storage. → see [13.1 Observability](../13-Observability/13.1-observability.md)

**CDN (Content Delivery Network)**, A network of edge servers worldwide that cache content near users to cut latency. → see [09.2 Caching and CDN](../09-System-Design/09.2-caching-and-cdn.md)

**Central Limit Theorem**, The averages of many independent samples tend toward a normal distribution, regardless of the original distribution's shape. → see [16.1 Statistics and Probability](../16-Data/16.1-statistics-and-probability.md)

**Churn**, The rate at which customers cancel or stop paying over a period; the enemy of recurring revenue. → see [21.1 Software Company](../21-Business/21.1-software-company.md)

**CI/CD**, Continuous Integration (auto-build and test every change) and Continuous Delivery/Deployment (auto-ship it), keeping software releasable at all times. → see [10.3 CI/CD and Deployment](../10-Cloud-DevOps/10.3-cicd-and-deployment.md)

**CISC**, A CPU design with many complex, multi-step instructions (e.g., x86), contrasting with RISC's lean instruction set. → see [25.1 Computer Architecture](../25-Architecture/25.1-computer-architecture.md)

**CMOS gate**, A logic gate built from complementary pairs of P-type and N-type transistors; draws almost no power while idle. → see [01.2 Boolean Logic](../01-Foundations/01.2-boolean-logic.md)

**CNN (Convolutional Neural Network)**, A network that slides learnable filters over data (especially images) to detect local patterns like edges and textures. → see [14.2 Deep Learning](../14-ML-DL/14.2-deep-learning.md)

**Code smell**, A surface symptom in code (a giant function, duplicated logic) that hints at a deeper design problem worth refactoring. → see [27.1 Clean Code and Design Patterns](../27-Software-Engineering/27.1-clean-code-and-design-patterns.md)

**Compare-exchange (CAS)**, The atomic "replace this value only if it has not changed" instruction; the primitive under lock-free algorithms and optimistic retry loops. → see [29.7 Concurrency, Atomics and the Memory Model](../29-Cpp/29.7-concurrency-atomics-memory-model.md)

**Concurrency**, Structuring a program so multiple tasks make progress in overlapping time periods, whether or not they run truly simultaneously. → see [05.2 Concurrency](../05-Systems/05.2-concurrency.md)

**Confidence interval**, A range that, under repeated sampling, would contain the true value a stated percentage of the time (e.g., 95%). → see [16.1 Statistics and Probability](../16-Data/16.1-statistics-and-probability.md)

**Consensus**, Getting a group of distributed nodes to agree on a single value or order of events despite failures. → see [26.2 Consensus and Replication](../26-Distributed-Systems/26.2-consensus-and-replication.md)

**Container**, A lightweight, isolated package of an app plus its dependencies that shares the host OS kernel; smaller and faster than a VM. → see [10.1 Docker](../10-Cloud-DevOps/10.1-docker.md)

**Context manager**, A Python object used with `with` that guarantees setup and cleanup (like opening and closing a file) happen reliably. → see [04.1 Python Deep Dive](../04-Programming-Mastery/04.1-python-deep-dive.md)

**Context-free grammar**, A set of rules describing nested, recursive structure (like balanced parentheses) that regular expressions can't capture. → see [23.1 Automata and Languages](../23-Theory-of-Computation/23.1-automata-and-languages.md)

**CORS**, Cross-Origin Resource Sharing: browser rules and HTTP headers that control which other origins may call your API. → see [08.3 Auth and Permissions](../08-Web/08.3-auth-and-permissions.md)

**Cpk**, Process capability index: min(USL−μ, μ−LSL)/3σ. Measures whether a stable process fits inside its spec limits, penalizing off-center processes. → see [30.4 CMP Process Engineering](../30-Fab-Engineering/30.4-cmp-process-engineering.md)

**Cross-validation**, Estimating model performance by repeatedly training on part of the data and testing on the held-out part, then averaging. → see [14.1 ML Foundations](../14-ML-DL/14.1-ml-foundations.md)

**CRTP**, Curiously recurring template pattern: a class inherits from a base template instantiated with itself, getting interface-style dispatch at compile time with no vtable. → see [29.6 Templates and Compile-Time C++](../29-Cpp/29.6-templates-and-compile-time-cpp.md)

**CSRF**, Cross-Site Request Forgery: tricking a logged-in user's browser into sending an unwanted authenticated request; blocked with tokens and SameSite cookies. → see [12.3 Web App Security](../12-Security/12.3-web-app-security.md)

## D

**Data race**, Two threads touching the same memory location, at least one writing, with no synchronization. In C++ this is undefined behavior, not just a stale read. → see [29.7 Concurrency, Atomics and the Memory Model](../29-Cpp/29.7-concurrency-atomics-memory-model.md)

**Datapath**, The hardware components (registers, ALU, buses) that data flows through inside a CPU as instructions execute. → see [25.1 Computer Architecture](../25-Architecture/25.1-computer-architecture.md)

**Deadlock**, When two or more threads each wait forever for a resource the other holds, so none can proceed. → see [05.2 Concurrency](../05-Systems/05.2-concurrency.md)

**Decidability**, Whether some problem can be solved by an algorithm that always halts with a yes/no answer; some problems (like the halting problem) are undecidable. → see [23.2 Computability and Complexity](../23-Theory-of-Computation/23.2-computability-and-complexity.md)

**Decorator**, A Python function that wraps another to add behavior (logging, timing, caching) without changing the wrapped function's code. → see [04.1 Python Deep Dive](../04-Programming-Mastery/04.1-python-deep-dive.md)

**Dependency injection**, Passing a component's collaborators in from outside rather than having it create them, making code easier to test and swap. → see [27.2 Testing and Architecture](../27-Software-Engineering/27.2-testing-and-architecture.md)

**Derivative**, The instantaneous rate of change of a function; the slope of its curve at a point. → see [18.1 Calculus for CS](../18-Math/18.1-calculus-for-cs.md)

**DFA (Deterministic Finite Automaton)**, A simple machine with a fixed set of states and exactly one transition per input symbol; recognizes regular languages. → see [23.1 Automata and Languages](../23-Theory-of-Computation/23.1-automata-and-languages.md)

**DFS (Depth-First Search)**, Graph traversal that plunges as deep as possible down one path before backtracking; great for cycle detection and topological sort. → see [03.4 Graph Algorithms](../03-Algorithms/03.4-graph-algorithms.md)

**Dijkstra's algorithm**, Finds shortest paths from a source in a graph with non-negative edge weights, using a priority queue to always expand the closest node. → see [03.4 Graph Algorithms](../03-Algorithms/03.4-graph-algorithms.md)

**Dilution**, The shrinking of existing owners' percentage stakes when a company issues new shares. → see [21.1 Software Company](../21-Business/21.1-software-company.md)

**Dishing**, CMP over-polish that scoops the center of soft features (like wide copper lines) below the surrounding surface. → see [30.4 CMP Process Engineering](../30-Fab-Engineering/30.4-cmp-process-engineering.md)

**Distribution (probability)**, A description of how likely each possible value of a random variable is. → see [16.1 Statistics and Probability](../16-Data/16.1-statistics-and-probability.md)

**Divide and conquer**, Solving a problem by splitting it into smaller subproblems, solving those, and combining the results (e.g., mergesort). → see [03.1 Recursion](../03-Algorithms/03.1-recursion.md)

**Docker**, The most popular tool for building and running containers from declarative images. → see [10.1 Docker](../10-Cloud-DevOps/10.1-docker.md)

**DOE (design of experiments)**, Running a planned set of experiments (like a 2^k factorial) that varies factors together, so you can measure main effects and interactions instead of being fooled by one-factor-at-a-time. → see [30.4 CMP Process Engineering](../30-Fab-Engineering/30.4-cmp-process-engineering.md)

**DOM (Document Object Model)**, The browser's live, tree-shaped representation of a web page that JavaScript reads and mutates. → see [08.1 Frontend](../08-Web/08.1-frontend.md)

**Doping**, Deliberately adding impurity atoms to silicon to give it extra electrons (N-type) or holes (P-type), the basis of all transistors. → see [17.1 Semiconductor Physics](../17-Semiconductors/17.1-semiconductor-physics.md)

**Dot product**, Multiplying two vectors element-wise and summing; measures how aligned they are and underlies similarity and projection. → see [18.2 Linear Algebra and Eigenvalues](../18-Math/18.2-linear-algebra-and-eigenvalues.md)

**Drift**, When the live data a model sees diverges over time from what it was trained on, quietly degrading accuracy. → see [20.2 ML Engineering and MLOps](../20-AI/20.2-ml-engineering-and-mlops.md)

**DNS**, The Domain Name System: the internet's phone book, translating human names like example.com into IP addresses. → see [06.2 HTTP, DNS, TLS](../06-Networking/06.2-http-dns-tls.md)

**Dynamic programming**, Solving problems by breaking them into overlapping subproblems and reusing stored answers instead of recomputing. → see [03.5 Dynamic Programming](../03-Algorithms/03.5-dynamic-programming.md)

## E

**Eigenvalue**, A scalar telling how much a matrix stretches a particular vector (its eigenvector) without changing that vector's direction. → see [18.2 Linear Algebra and Eigenvalues](../18-Math/18.2-linear-algebra-and-eigenvalues.md)

**Eigenvector**, A special vector that a matrix only scales, not rotates; paired with its eigenvalue. → see [18.2 Linear Algebra and Eigenvalues](../18-Math/18.2-linear-algebra-and-eigenvalues.md)

**Embedding**, A dense vector that represents a word, image, or item so that similar things sit close together in space. → see [20.3 Generative AI and LLMs](../20-AI/20.3-generative-ai-and-llms.md)

**Energy**, The capacity to do work; conserved overall, it shifts between forms like kinetic and potential. → see [19.1 Physics for CS](../19-Physics/19.1-physics-for-cs.md)

**Entanglement**, A quantum link where two qubits' states are correlated, so measuring one instantly constrains the other. → see [19.2 Modern Physics and Quantum Computing](../19-Physics/19.2-modern-physics-and-quantum-computing.md)

**Erosion (CMP)**, Thinning of the dielectric between densely packed features during CMP, dragging a whole array below the open field surface. → see [30.4 CMP Process Engineering](../30-Fab-Engineering/30.4-cmp-process-engineering.md)

**Error budget**, The allowed amount of unreliability (1 minus your SLO) you can "spend" on risky changes before you must slow down. → see [13.1 Observability](../13-Observability/13.1-observability.md)

**EUV (Extreme Ultraviolet lithography)**, Chipmaking that uses 13.5 nm light to print features only a few nanometers wide. → see [17.5 Semiconductor Manufacturing](../17-Semiconductors/17.5-semiconductor-manufacturing.md)

**Eventual consistency**, A guarantee that, given no new writes, all replicas will converge to the same value in time, though reads may be stale briefly. → see [26.2 Consensus and Replication](../26-Distributed-Systems/26.2-consensus-and-replication.md)

## F

**False sharing**, Independent variables that happen to share one 64-byte cache line, forcing CPU cores to fight over it. Fixed with alignment/padding, not locks. → see [29.7 Concurrency, Atomics and the Memory Model](../29-Cpp/29.7-concurrency-atomics-memory-model.md)

**Feature**, An input variable a model learns from (e.g., square footage when predicting house price). → see [14.1 ML Foundations](../14-ML-DL/14.1-ml-foundations.md)

**FinFET**, A 3D transistor whose channel rises like a fin so the gate wraps it on multiple sides, improving control at tiny scales. → see [17.2 Transistor and Logic](../17-Semiconductors/17.2-transistor-and-logic.md)

**FLP impossibility**, A theorem that no deterministic protocol can guarantee consensus in an asynchronous network if even one node may fail. → see [26.1 Foundations](../26-Distributed-Systems/26.1-foundations.md)

**FPGA**, A chip whose logic you reconfigure after manufacturing by loading a hardware description, blending software flexibility with hardware speed. → see [17.3 From Transistors to Chips](../17-Semiconductors/17.3-from-transistors-to-chips.md)

**Function**, A rule mapping each input to exactly one output; the fundamental object of calculus and programming alike. → see [18.1 Calculus for CS](../18-Math/18.1-calculus-for-cs.md)

## G

**Garbage collection**, Automatic memory management that finds and frees objects a program can no longer reach. → see [05.1 Memory](../05-Systems/05.1-memory.md)

**Generator**, A Python function using `yield` that produces values lazily, one at a time, without building the whole sequence in memory. → see [04.1 Python Deep Dive](../04-Programming-Mastery/04.1-python-deep-dive.md)

**GIL (Global Interpreter Lock)**, CPython's lock that lets only one thread run Python bytecode at a time, limiting CPU-bound multithreading. → see [04.1 Python Deep Dive](../04-Programming-Mastery/04.1-python-deep-dive.md)

**Gradient**, The vector of partial derivatives pointing in the direction of steepest increase of a function. → see [18.1 Calculus for CS](../18-Math/18.1-calculus-for-cs.md)

**Gradient descent**, The optimization loop that nudges parameters opposite the gradient to minimize a loss function. → see [14.1 ML Foundations](../14-ML-DL/14.1-ml-foundations.md)

**Graph**, A set of nodes (vertices) connected by edges, modeling relationships like networks, maps, and dependencies. → see [02.7 Graphs](../02-Data-Structures/02.7-graphs.md)

**GraphQL**, An API query language that lets clients ask for exactly the fields they need in one request, avoiding over- and under-fetching. → see [08.2 Backend APIs](../08-Web/08.2-backend-apis.md)

**Greedy algorithm**, Making the locally best choice at each step, hoping it yields a global optimum; works for some problems (like Huffman coding), not all. → see [03.6 Greedy and Backtracking](../03-Algorithms/03.6-greedy-and-backtracking.md)

**Ground loop**, An unintended circuit created by grounding a signal's return at both ends; ground potential differences then drive current that adds offset and noise to the reading. → see [30.1 Electrical Engineering for the Fab Floor](../30-Fab-Engineering/30.1-electrical-engineering-for-the-fab.md)

**gRPC**, A high-performance RPC framework using HTTP/2 and Protocol Buffers for fast, typed service-to-service calls. → see [06.3 WebSockets, RPC, Polling](../06-Networking/06.3-websockets-rpc-polling.md)

## H

**Halting problem**, The classic undecidable problem: no program can determine, for every program-and-input pair, whether it will eventually stop. → see [23.2 Computability and Complexity](../23-Theory-of-Computation/23.2-computability-and-complexity.md)

**Happens-before**, The C++ memory model's ordering guarantee: when an acquire load reads a release store, everything written before the store is visible after the load. → see [29.7 Concurrency, Atomics and the Memory Model](../29-Cpp/29.7-concurrency-atomics-memory-model.md)

**Hash (cryptographic)**, A one-way function that maps any input to a fixed-size fingerprint; easy to compute, infeasible to reverse. → see [12.1 Cryptography](../12-Security/12.1-cryptography.md)

**Hash table**, A structure that maps keys to values via a hash function, giving average O(1) lookup, insert, and delete. → see [02.4 Hash Tables](../02-Data-Structures/02.4-hash-tables.md)

**Hazard (pipeline)**, A situation where an instruction can't execute in its scheduled pipeline stage because it depends on an as-yet-unfinished one. → see [25.1 Computer Architecture](../25-Architecture/25.1-computer-architecture.md)

**Heap (data structure)**, A tree-based priority queue where the min (or max) is always at the root; backs scheduling and Dijkstra. → see [02.6 Heaps](../02-Data-Structures/02.6-heaps.md)

**Heap (memory)**, The region of memory for dynamically allocated objects whose lifetime isn't tied to a function call. → see [05.1 Memory](../05-Systems/05.1-memory.md)

**Hexadecimal**, Base-16 notation (0-9, A-F) that compactly represents bytes, since two hex digits equal one byte. → see [01.1 Data Representation](../01-Foundations/01.1-data-representation.md)

**HMAC**, A keyed-hash message authentication code that proves a message is both untampered and from someone who holds the shared secret. → see [12.1 Cryptography](../12-Security/12.1-cryptography.md)

**Home lab**, A personal collection of servers and gear at home for self-hosting, experimenting, and learning ops hands-on. → see [22.1 Mac Minis and Server Farms](../22-Infrastructure/22.1-mac-minis-and-server-farms.md)

**HTTP**, The request/response protocol of the web, defining methods (GET, POST), status codes, and headers. → see [06.2 HTTP, DNS, TLS](../06-Networking/06.2-http-dns-tls.md)

## I

**IaC (Infrastructure as Code)**, Defining servers, networks, and cloud resources in version-controlled files so environments are reproducible. → see [10.3 CI/CD and Deployment](../10-Cloud-DevOps/10.3-cicd-and-deployment.md)

**Idempotency**, A property where doing an operation many times has the same effect as doing it once, so safe retries don't cause damage. → see [09.4 Rate Limiting](../09-System-Design/09.4-rate-limiting.md)

**IEEE 754**, The standard for representing floating-point numbers in binary using sign, exponent, and mantissa. → see [01.1 Data Representation](../01-Foundations/01.1-data-representation.md)

**Image (container)**, A read-only, layered snapshot of a filesystem and config from which containers are launched. → see [10.1 Docker](../10-Cloud-DevOps/10.1-docker.md)

**Index (database)**, An auxiliary structure (often a B-tree) that lets the database find rows fast without scanning the whole table. → see [07.2 Design, Indexing, Transactions](../07-Databases/07.2-design-indexing-transactions.md)

**Integral**, The accumulation of a quantity over an interval; geometrically, the area under a curve. → see [18.1 Calculus for CS](../18-Math/18.1-calculus-for-cs.md)

**IP**, The Internet Protocol that addresses and routes packets between hosts across networks. → see [06.1 TCP/IP](../06-Networking/06.1-tcp-ip.md)

**ISA (Instruction Set Architecture)**, The contract between hardware and software: the instructions, registers, and behaviors a CPU promises to support. → see [25.1 Computer Architecture](../25-Architecture/25.1-computer-architecture.md)

**Isoelectric point**, The pH at which a surface's net charge is zero. Slurries lose their electrostatic stabilization and agglomerate when pH drifts toward the abrasive's isoelectric point. → see [30.2 Chemical Engineering for CMP](../30-Fab-Engineering/30.2-chemical-engineering-for-cmp.md)

**Isolation level**, How strictly a database keeps concurrent transactions from interfering, trading consistency for performance (e.g., Read Committed, Serializable). → see [07.2 Design, Indexing, Transactions](../07-Databases/07.2-design-indexing-transactions.md)

## J

**JOIN**, A SQL operation that combines rows from two or more tables based on a related column. → see [07.1 Relational and SQL](../07-Databases/07.1-relational-and-sql.md)

**JWT (JSON Web Token)**, A signed, self-contained token carrying claims (like user ID), letting servers verify identity without storing session state. → see [08.3 Auth and Permissions](../08-Web/08.3-auth-and-permissions.md)

## K

**Kubernetes**, An orchestrator that schedules, scales, heals, and networks containers across a cluster of machines. → see [10.2 Kubernetes](../10-Cloud-DevOps/10.2-kubernetes.md)

## L

**Lambda (AWS)**, A serverless service that runs your function on demand without you managing servers, billed per invocation. → see [10.4 AWS](../10-Cloud-DevOps/10.4-aws.md)

**Lamport clock**, A simple logical counter that orders events across distributed processes without synchronized wall clocks. → see [26.1 Foundations](../26-Distributed-Systems/26.1-foundations.md)

**Latency**, How long a single operation takes from request to response. → see [09.1 Scalability Fundamentals](../09-System-Design/09.1-scalability-fundamentals.md)

**Leader election**, The process by which distributed nodes agree on one node to coordinate, often after the previous leader fails. → see [26.2 Consensus and Replication](../26-Distributed-Systems/26.2-consensus-and-replication.md)

**UPW (ultrapure water)**, Water purified to about 18.2 MΩ·cm resistivity with almost nothing dissolved in it; the fab's universal rinse and one of its hungriest solvents. → see [30.2 Chemical Engineering for CMP](../30-Fab-Engineering/30.2-chemical-engineering-for-cmp.md)


## V

**Variance**, A measure of how spread out a set of numbers is from their mean; the square of standard deviation. → see [16.1 Statistics and Probability](../16-Data/16.1-statistics-and-probability.md)

**Vector**, An ordered list of numbers representing a point, direction, or feature set. → see [18.2 Linear Algebra and Eigenvalues](../18-Math/18.2-linear-algebra-and-eigenvalues.md)

**Vector clock**, A per-process array of counters that captures causal ordering between distributed events, beating a single Lamport clock at detecting concurrency. → see [26.1 Foundations](../26-Distributed-Systems/26.1-foundations.md)

**Verilog**, A hardware description language for specifying digital circuits at the register-transfer level. → see [17.4 Chip Design Flow and HDL](../17-Semiconductors/17.4-chip-design-flow-and-hdl.md)

**VFD (variable frequency drive)**, The power electronics that rectify AC to a DC bus and synthesize new AC at any frequency, giving smooth speed control of ordinary induction motors. → see [30.1 Electrical Engineering for the Fab Floor](../30-Fab-Engineering/30.1-electrical-engineering-for-the-fab.md)

**Virtual machine (compilers)**, A software CPU that executes bytecode, providing portability across real hardware. → see [24.2 Interpreters and VMs](../24-Compilers/24.2-interpreters-and-vms.md)

**Virtual memory**, The OS illusion that each process has its own large, contiguous address space, mapped onto physical RAM and disk. → see [05.1 Memory](../05-Systems/05.1-memory.md)

**Vtable**, The per-class table of virtual function pointers that makes C++ dynamic dispatch work; each polymorphic object carries one hidden pointer to its class's table. → see [29.5 Classes and Object Layout](../29-Cpp/29.5-classes-and-object-layout.md)


## W

**Wafer**, A thin, polished disc of silicon on which hundreds of chips are fabricated together. → see [17.5 Semiconductor Manufacturing](../17-Semiconductors/17.5-semiconductor-manufacturing.md)

**WebSocket**, A protocol giving a persistent, two-way connection between browser and server for real-time messaging. → see [06.3 WebSockets, RPC, Polling](../06-Networking/06.3-websockets-rpc-polling.md)

**WIWNU**, Within-wafer nonuniformity: how much removal or thickness varies across a single wafer, reported as a percent of the mean. → see [30.4 CMP Process Engineering](../30-Fab-Engineering/30.4-cmp-process-engineering.md)


## X

**XSS (Cross-Site Scripting)**, Injecting malicious scripts into pages other users view; prevented by escaping output and a content security policy. → see [12.3 Web App Security](../12-Security/12.3-web-app-security.md)

## Y

**Yield (manufacturing)**, The percentage of chips on a wafer that work; the key economic lever in semiconductor fabs. → see [17.5 Semiconductor Manufacturing](../17-Semiconductors/17.5-semiconductor-manufacturing.md)

## Z

**Zeta potential**, The effective electrical charge of a suspended particle at its slipping plane; the practical predictor of whether a colloid stays dispersed or crashes. → see [30.2 Chemical Engineering for CMP](../30-Fab-Engineering/30.2-chemical-engineering-for-cmp.md)
