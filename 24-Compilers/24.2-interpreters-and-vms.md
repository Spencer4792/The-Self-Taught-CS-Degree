## Start here

**A recipe and a kitchen.** Think of the AST as a *recipe*, an ordered, structured description of what to do: "cream the butter and sugar, *then* fold in the flour." The recipe is inert; nothing happens until a cook stands in a kitchen and *executes* the steps. The **interpreter** is the cook. The **environment** is the kitchen: the place where ingredients live, where "the bowl currently holding the batter" is tracked. When the recipe says "add the sugar," the cook looks up *which* sugar (the one on the counter, in this kitchen), uses it, and moves on.

That word, *environment*, is the one concept that makes interpreters click. When your program says `print x`, the interpreter must answer "what is `x` right now?" That answer lives in the environment: a mapping from variable names to their current values, layered by scope. `var x = 1;` puts `x → 1` in the environment. `x = x + 1` looks `x` up, computes, and stores it back. A `{ block }` creates a *new* environment layered on top of the old one, so names declared inside don't leak out, and so a name inside can *shadow* one outside. Get environments right and variables, scope, and closures all fall out naturally.

**Why it matters.** This is the thing every running program sits on top of. Python's interpreter is doing exactly this to your code right now, looking up names in `locals()` and `globals()` dicts (which are environments), walking compiled instructions, managing a call stack. Understanding the interpreter demystifies *why* Python is slower than C (it re-checks types and looks up names at runtime), *why* closures capture variables the way they do (they hold a reference to an environment), *why* a `RecursionError` happens (the interpreter's own call stack overflows), and *why* compiled/bytecode languages are faster (they skip the tree-walk). Build one interpreter from scratch and you'll never again treat "the runtime" as mysterious. Let's cook.

## Environments: where variables live

An **environment** maps variable names to values, with a pointer to an *enclosing* environment for outer scopes. That linked chain *is* lexical scoping: to look up a name, check the current scope, and if it's not there, walk outward to the enclosing scope, and so on until the global scope. If it's nowhere, that's a runtime error.

```python
class LoxRuntimeError(Exception):
    """A runtime error that carries the token where it happened (for line nums)."""
    def __init__(self, token, message):
        super().__init__(message)
        self.token = token
        self.message = message


class Environment:
    """A scope: name -> value, chained to an enclosing scope."""

    def __init__(self, enclosing=None):
        self.values = {}                 # this scope's own bindings
        self.enclosing = enclosing       # the scope we're nested inside (or None)

    def define(self, name, value):
        """Declare a NEW variable in THIS scope (redeclaration is allowed)."""
        self.values[name] = value

    def get(self, name_token):
        """Look up a variable by its IDENT token, walking outward if needed."""
        name = name_token.lexeme
        if name in self.values:
            return self.values[name]
        if self.enclosing is not None:
            return self.enclosing.get(name_token)     # search the outer scope
        raise LoxRuntimeError(name_token, f"undefined variable '{name}'")

    def assign(self, name_token, value):
        """Assign to an EXISTING variable (must already be declared somewhere)."""
        name = name_token.lexeme
        if name in self.values:
            self.values[name] = value
            return
        if self.enclosing is not None:
            self.enclosing.assign(name_token, value)
            return
        raise LoxRuntimeError(name_token, f"undefined variable '{name}'")
```

The distinction between `define` and `assign` is the difference between `var x = ...` (introduce a new name in the current scope) and `x = ...` (mutate an existing name found by searching outward). That `get`/`assign` recursion up the `enclosing` chain is *exactly* how Python resolves names through `locals → enclosing → globals → builtins` (the LEGB rule). You're building a scope chain by hand here, and it's just a linked list (Chapter [02.2](../02-Data-Structures/02.2-linked-lists.md)) of dictionaries.

## Build it: a tree-walking interpreter

Now the interpreter itself, a `Visitor` (from 24.1) that *returns a value* for each expression node and *performs an effect* for each statement node. This is the centerpiece of the chapter. We'll build it incrementally in one class, but show it whole.

First, expressions. Each `visit_X` returns a Python value (`float`, `str`, `bool`, or `None` for nil).

```python
class Interpreter(Visitor):
    def __init__(self):
        self.globals = Environment()     # the outermost scope
        self.env = self.globals          # the scope we're currently executing in
        self.output = []                 # captured print output (for testing/REPL)

    # ---- the public entry point ----
    def interpret(self, statements):
        try:
            for stmt in statements:
                self.execute(stmt)
        except LoxRuntimeError as e:
            line = e.token.line if e.token else "?"
            self.output.append(f"[line {line}] Runtime error: {e.message}")
        return self.output

    def execute(self, stmt):
        self.visit(stmt)

    def evaluate(self, expr):
        return self.visit(expr)

    # ---- expression nodes: each returns a value -------------------------------
    def visit_Literal(self, node):
        return node.value                # already a float/str/bool/None from lexer

    def visit_Grouping(self, node):
        return self.evaluate(node.expr)

    def visit_Variable(self, node):
        return self.env.get(node.name)   # look up in the scope chain

    def visit_Assign(self, node):
        value = self.evaluate(node.value)
        self.env.assign(node.name, value)
        return value                     # assignment is an expression: returns the value

    def visit_Unary(self, node):
        right = self.evaluate(node.right)
        if node.op.type == TT.MINUS:
            self._check_number(node.op, right)
            return -right
        if node.op.type == TT.BANG:
            return not self._truthy(right)
        raise LoxRuntimeError(node.op, "unknown unary operator")

    def visit_Binary(self, node):
        left = self.evaluate(node.left)
        right = self.evaluate(node.right)
        op = node.op.type

        if op == TT.PLUS:
            # '+' is overloaded: numeric addition OR string concatenation
            if isinstance(left, float) and isinstance(right, float):
                return left + right
            if isinstance(left, str) and isinstance(right, str):
                return left + right
            raise LoxRuntimeError(node.op, "operands must be two numbers or two strings")

        if op in (TT.MINUS, TT.STAR, TT.SLASH,
                  TT.GREATER, TT.GREATER_EQUAL, TT.LESS, TT.LESS_EQUAL):
            self._check_number(node.op, left)
            self._check_number(node.op, right)
            if op == TT.MINUS:         return left - right
            if op == TT.STAR:          return left * right
            if op == TT.SLASH:
                if right == 0:
                    raise LoxRuntimeError(node.op, "division by zero")
                return left / right
            if op == TT.GREATER:       return left > right
            if op == TT.GREATER_EQUAL: return left >= right
            if op == TT.LESS:          return left < right
            if op == TT.LESS_EQUAL:    return left <= right

        if op == TT.EQUAL_EQUAL: return self._equal(left, right)
        if op == TT.BANG_EQUAL:  return not self._equal(left, right)
        raise LoxRuntimeError(node.op, "unknown binary operator")

    def visit_Logical(self, node):
        # short-circuit: don't evaluate the right side unless we have to
        left = self.evaluate(node.left)
        if node.op.type == TT.OR:
            if self._truthy(left):  return left      # `or` stops at first truthy
        else:  # AND
            if not self._truthy(left): return left   # `and` stops at first falsy
        return self.evaluate(node.right)

    # ---- runtime helpers ------------------------------------------------------
    def _truthy(self, value):
        # Lox rule: nil and false are falsy; EVERYTHING else (incl. 0) is truthy
        if value is None:  return False
        if value is True or value is False: return value
        return True

    def _equal(self, a, b):
        if a is None and b is None: return True
        if type(a) != type(b):      return False     # 1.0 != "1"
        return a == b

    def _check_number(self, op_token, value):
        if not isinstance(value, float):
            raise LoxRuntimeError(op_token, "operand must be a number")
```

Notice the design decisions a real interpreter must make and that the *language's semantics* are defined right here: `+` is overloaded for strings, `/` by zero is a runtime error (not a crash), `==` is type-strict (`1.0 != "1"`), `&&`/`||` short-circuit, and "truthiness" is *defined* (`nil` and `false` are falsy, `0` is truthy, that's a *choice*; Python disagrees about `0`). The language is whatever the interpreter says it is.

Now statements. These return nothing; they *do* things, print, mutate the environment, branch, loop.

```python
    def visit_ExpressionStmt(self, node):
        self.evaluate(node.expr)          # evaluate for side effects, discard value

    def visit_PrintStmt(self, node):
        value = self.evaluate(node.expr)
        self.output.append(self._stringify(value))

    def visit_VarDecl(self, node):
        value = None
        if node.initializer is not None:
            value = self.evaluate(node.initializer)
        self.env.define(node.name.lexeme, value)   # NEW binding in current scope

    def visit_Block(self, node):
        # a block runs its statements in a fresh scope nested in the current one
        self.execute_block(node.statements, Environment(self.env))

    def execute_block(self, statements, new_env):
        previous = self.env
        try:
            self.env = new_env            # swap in the block's scope
            for stmt in statements:
                self.execute(stmt)
        finally:
            self.env = previous           # ALWAYS restore, even if a return unwinds

    def visit_IfStmt(self, node):
        if self._truthy(self.evaluate(node.condition)):
            self.execute(node.then_branch)
        elif node.else_branch is not None:
            self.execute(node.else_branch)

    def visit_WhileStmt(self, node):
        while self._truthy(self.evaluate(node.condition)):
            self.execute(node.body)

    def _stringify(self, value):
        if value is None:  return "nil"
        if value is True:  return "true"
        if value is False: return "false"
        if isinstance(value, float):
            # print 3.0 as "3" but 3.5 as "3.5", Lox-style
            if value == int(value):
                return str(int(value))
            return str(value)
        return str(value)
```

Let's run a real program through it:

```python
def run(src):
    """Lex -> parse -> interpret, returning captured output lines."""
    tokens = Lexer(src).scan_tokens()
    stmts = FullParser(tokens).parse()
    return Interpreter().interpret(stmts)

prog = """
var x = 0;
while (x < 3) {
    print x;
    x = x + 1;
}
var name = "Spencer";
if (x >= 3) {
    print "done, " + name;
} else {
    print "unreachable";
}
print 1 + 2 * 3;
print 0 or "default";        // 0 is truthy in Lox, so prints 0
print false or "default";    // false is falsy, so prints "default"
"""
for line in run(prog):
    print(line)
```

Output:

```text
0
1
2
done, Spencer
7
0
default
```

It works. The `while` loop ran, mutating `x` in the environment each pass; the string concatenation worked; precedence held (`1 + 2 * 3 == 7`); short-circuit `or` returned the operand (Lox-style truthiness made `0` win). **This is a real, working programming language**, and the entire execution engine is one recursive visitor over a tree.

## Build it: functions, closures, and the call stack

Functions are where interpreters get interesting, because they introduce **closures**, functions that "remember" the environment they were defined in. You need three pieces: a *callable* representation, a way to *call* it (push a new scope with the parameters bound), and a way to *return early* out of the middle of a function body.

The "return early" problem is subtle: `return` can appear deep inside loops and `if`s, and it must unwind all the way out of the function, but no further. The cleanest implementation is to **use a Python exception as a control-flow signal**: a `Return` exception that carries the value, thrown at the `return` statement and caught at the function boundary.

```python
class Return(Exception):
    """Control-flow signal: unwind out of a function carrying a return value."""
    def __init__(self, value):
        super().__init__()
        self.value = value


class LoxFunction:
    """A callable function value, closing over the scope where it was defined."""
    def __init__(self, declaration, closure):
        self.declaration = declaration   # the FunctionDecl AST node
        self.closure = closure           # the environment at definition time

    @property
    def arity(self):
        return len(self.declaration.params)

    def call(self, interpreter, args):
        # a fresh scope for THIS call, nested in the CLOSURE (not the caller!)
        env = Environment(self.closure)
        for param, arg in zip(self.declaration.params, args):
            env.define(param.lexeme, arg)     # bind parameters
        try:
            interpreter.execute_block(self.declaration.body, env)
        except Return as r:
            return r.value                    # caught here: the function's result
        return None                           # fell off the end -> returns nil

    def __repr__(self):
        return f"<fn {self.declaration.name.lexeme}>"
```

The single most important line is `env = Environment(self.closure)`. A function's body runs in a scope nested inside **the environment where the function was defined**, *not* where it was called from. That is the entire definition of a closure and of *lexical* (a.k.a. *static*) scoping. Capturing the wrong one gives you *dynamic* scoping, which is a famous footgun. Now we wire functions into the interpreter:

```python
    def visit_FunctionDecl(self, node):
        # capture the CURRENT environment as the closure, then bind the name
        fn = LoxFunction(node, self.env)
        self.env.define(node.name.lexeme, fn)

    def visit_ReturnStmt(self, node):
        value = None
        if node.value is not None:
            value = self.evaluate(node.value)
        raise Return(value)                   # unwind to LoxFunction.call

    def visit_Call(self, node):
        callee = self.evaluate(node.callee)
        args = [self.evaluate(a) for a in node.args]
        if not isinstance(callee, LoxFunction):
            raise LoxRuntimeError(node.paren, "can only call functions")
        if len(args) != callee.arity:
            raise LoxRuntimeError(
                node.paren,
                f"expected {callee.arity} arguments but got {len(args)}")
        return callee.call(self, args)
```

The classic closure test, a counter factory, proves the environment is being captured, not the value:

```python
closure_prog = """
fun makeCounter() {
    var count = 0;
    fun increment() {
        count = count + 1;
        return count;
    }
    return increment;
}
var c = makeCounter();
print c();      // 1
print c();      // 2
print c();      // 3

fun add(a, b) { return a + b; }
print add(10, 32);   // 42

fun fib(n) {
    if (n < 2) { return n; }
    return fib(n - 1) + fib(n - 2);
}
print fib(10);   // 55
"""
for line in run(closure_prog):
    print(line)
```

Output:

```text
1
2
3
42
55
```

Look at `makeCounter`. Each call to `c()` returns `1`, then `2`, then `3`, the inner `increment` *remembers and mutates* the `count` variable from the enclosing `makeCounter` scope, even though `makeCounter` already returned. That's a genuine closure: `increment`'s `closure` environment still points at the `Environment` holding `count`, keeping it alive. And recursive `fib` works because each call gets its own `Environment` with its own `n`, stacked on the interpreter's call stack (which is really Python's call stack here, every `callee.call` is a Python function call, so deep recursion in *our* language consumes the *host's* stack, and would eventually raise Python's `RecursionError`; production VMs manage their own explicit call stack to avoid this).

**Runtime error handling.** Notice that bad operations don't crash the interpreter, they raise `LoxRuntimeError` with a token, caught in `interpret`, producing a clean `[line N] Runtime error: ...` message:

```python
for line in run('print 1 + "two";'):
    print(line)        # [line 1] Runtime error: operands must be two numbers or two strings
for line in run('print 5 / 0;'):
    print(line)        # [line 1] Runtime error: division by zero
for line in run('print undefined_var;'):
    print(line)        # [line 1] Runtime error: undefined variable 'undefined_var'
```

That's the difference between a toy and a tool: a real language *reports* runtime errors with location; it doesn't dump a host-language traceback at the user.

## Type systems: static vs dynamic, strong vs weak

The interpreter above is **dynamically typed**: it checks types *while running* (the `_check_number` calls happen during evaluation), and `1 + "two"` only fails when that line actually executes. The alternative is **static typing**: catch type errors *before running*, by a separate pass over the AST. Let's get the vocabulary precise, because these axes are constantly confused.

- **Static vs dynamic** = *when* types are checked. **Static** = at compile time, before the program runs (C, Java, Rust, TypeScript, Go). **Dynamic** = at runtime, as values flow (Python, Ruby, JavaScript, our Lox). Static catches whole classes of bugs early and enables optimizations; dynamic is more flexible and faster to prototype.
- **Strong vs weak** = *how much* the language lets you bend or coerce types. **Strong** = few implicit coercions; `1 + "2"` is an error (Python, our Lox). **Weak** = lots of implicit coercion; `1 + "2"` silently becomes `"12"` or `3` (JavaScript, C with its pointer/int blurring). This axis is fuzzy and informal, but the rule of thumb: strong languages make you convert explicitly.
- **Type checking vs type inference** = *who writes the types*. **Checking** verifies annotations you wrote (`int x = foo()`). **Inference** *figures out* the types so you don't have to annotate (`let x = foo()` in Rust/ML/Haskell; `x = foo()` with mypy's inference). Inference gives you static safety with dynamic-looking syntax.

These are independent axes. Python is *dynamic + strong*. C is *static + weak*. Haskell is *static + strong + inferred*. JavaScript is *dynamic + weak*. There's no single "typed/untyped" switch: it's a 2-D (really 3-D) space.

## Build it: a simple static type checker

Let's add **static typing** to our language as a separate AST pass, another `Visitor` (the visitor pattern paying off again: you add a whole new operation without touching one node class). We'll keep it minimal: every expression has one of a few types, `NUMBER`, `STRING`, `BOOL`, `NIL`, and the checker walks the tree computing each expression's type and reporting mismatches *before* the interpreter ever runs. This is exactly what `tsc` (TypeScript) or `mypy` does in spirit.

```python
class Type:
    NUMBER = "Number"; STRING = "String"; BOOL = "Bool"; NIL = "Nil"
    ANY = "Any"        # used for "we can't tell" (e.g. uninitialized vars)


class TypeError_(Exception):
    pass


class TypeChecker(Visitor):
    """A static pass: infer each expression's type, report mismatches."""

    def __init__(self):
        self.scopes = [{}]               # stack of name -> Type maps
        self.errors = []

    def check(self, statements):
        for s in statements:
            self.visit(s)
        return self.errors

    # ---- scope helpers ----
    def _declare(self, name, typ):
        self.scopes[-1][name] = typ

    def _lookup(self, name):
        for scope in reversed(self.scopes):
            if name in scope:
                return scope[name]
        return None

    # ---- expressions: return a Type ----
    def visit_Literal(self, node):
        v = node.value
        if isinstance(v, float): return Type.NUMBER
        if isinstance(v, str):   return Type.STRING
        if isinstance(v, bool):  return Type.BOOL
        if v is None:            return Type.NIL
        return Type.ANY

    def visit_Grouping(self, node):
        return self.visit(node.expr)

    def visit_Variable(self, node):
        t = self._lookup(node.name.lexeme)
        if t is None:
            self.errors.append(
                f"[line {node.name.line}] unknown variable '{node.name.lexeme}'")
            return Type.ANY
        return t

    def visit_Assign(self, node):
        return self.visit(node.value)

    def visit_Unary(self, node):
        rt = self.visit(node.right)
        if node.op.type == TT.MINUS and rt not in (Type.NUMBER, Type.ANY):
            self.errors.append(
                f"[line {node.op.line}] unary '-' needs a Number, got {rt}")
            return Type.NUMBER
        if node.op.type == TT.BANG:
            return Type.BOOL
        return Type.NUMBER

    def visit_Binary(self, node):
        lt = self.visit(node.left)
        rt = self.visit(node.right)
        op = node.op.type
        if op == TT.PLUS:
            if lt == Type.STRING and rt == Type.STRING: return Type.STRING
            if lt == Type.NUMBER and rt == Type.NUMBER: return Type.NUMBER
            if Type.ANY in (lt, rt):                    return Type.ANY
            self.errors.append(
                f"[line {node.op.line}] '+' needs matching Number/String, "
                f"got {lt} and {rt}")
            return Type.ANY
        if op in (TT.MINUS, TT.STAR, TT.SLASH):
            self._want(node.op, lt, Type.NUMBER)
            self._want(node.op, rt, Type.NUMBER)
            return Type.NUMBER
        if op in (TT.GREATER, TT.GREATER_EQUAL, TT.LESS, TT.LESS_EQUAL):
            self._want(node.op, lt, Type.NUMBER)
            self._want(node.op, rt, Type.NUMBER)
            return Type.BOOL
        if op in (TT.EQUAL_EQUAL, TT.BANG_EQUAL):
            return Type.BOOL
        return Type.ANY

    def visit_Logical(self, node):
        self.visit(node.left); self.visit(node.right)
        return Type.BOOL

    def _want(self, op_token, got, expected):
        if got not in (expected, Type.ANY):
            self.errors.append(
                f"[line {op_token.line}] operator '{op_token.lexeme}' "
                f"expected {expected}, got {got}")

    # ---- statements ----
    def visit_VarDecl(self, node):
        t = self.visit(node.initializer) if node.initializer is not None else Type.ANY
        self._declare(node.name.lexeme, t)

    def visit_ExpressionStmt(self, node): self.visit(node.expr)
    def visit_PrintStmt(self, node):      self.visit(node.expr)

    def visit_Block(self, node):
        self.scopes.append({})
        for s in node.statements:
            self.visit(s)
        self.scopes.pop()

    def visit_IfStmt(self, node):
        self.visit(node.condition)
        self.visit(node.then_branch)
        if node.else_branch is not None:
            self.visit(node.else_branch)

    def visit_WhileStmt(self, node):
        self.visit(node.condition); self.visit(node.body)

    def visit_FunctionDecl(self, node):
        self._declare(node.name.lexeme, Type.ANY)   # functions: ANY (no fn types yet)

    def visit_ReturnStmt(self, node):
        if node.value is not None:
            self.visit(node.value)
```

```python
def typecheck(src):
    stmts = FullParser(Lexer(src).scan_tokens()).parse()
    return TypeChecker().check(stmts)

assert typecheck('var x = 1; var y = x + 2;') == []          # fine
errs = typecheck('var x = 1; print x + "oops";')
assert errs and "got Number and String" in errs[0]
print("type checker caught the mismatch BEFORE running:", errs[0])

errs2 = typecheck('print 3 * "hi";')
assert errs2 and "expected Number" in errs2[0]
print("caught:", errs2[0])
```

Output:

```text
type checker caught the mismatch BEFORE running: [line 1] '+' needs matching Number/String, got Number and String
caught: [line 1] operator '*' expected Number, got String
```

The win: `print x + "oops"` is flagged **without executing the program**. A dynamically-typed run would only discover it if that line happened to run. Static checking trades flexibility for catching errors at the *cheapest possible time*, before deployment.

**Hindley-Milner intuition (where inference comes from).** Our checker is simple because it just propagates known literal types. Real inference engines (ML, Haskell, Rust's local inference) use the **Hindley-Milner** algorithm, and the intuition is worth carrying even without the formalism. Instead of demanding annotations, the compiler:

1. Gives every unknown a **type variable** (`α`, `β`, ...). `let f = fun x -> x + 1` starts with `x : α`.
2. Generates **constraints** from how things are used. `x + 1` requires `α = Int` (because `+` on this `Int` literal forces it). `f`'s result is `Int`.
3. **Unifies** the constraints, solves the equations, to pin down each type variable, like solving `α = Int`. If two constraints conflict (`α = Int` *and* `α = String`), that's a type error.
4. **Generalizes** what's left free into polymorphism: `let id = fun x -> x` has `id : α -> α` for *any* `α`, so `id` works on ints and strings alike (parametric polymorphism / generics).

So `let x = foo()` needs no annotation: the compiler deduces `x`'s type from `foo`'s return type and propagates it. Same static safety as Java, none of the `int x = ...` noise: the inference engine wrote the types for you. (Adding full HM to our language is a big project; the four-step skeleton is the thing to remember.)

## Why bytecode beats re-walking the tree

The tree-walking interpreter is wonderfully clear, but it's *slow*. Every time the `while` loop runs the body, the interpreter **re-walks the same AST nodes**: it re-dispatches on node type (`visit_Binary` → check `op.type` → branch), re-checks the operand types, re-recurses into children. For a loop that runs a million times, that's a million redundant tree traversals and type checks of structurally identical nodes. Pointer-chasing through tree nodes also wrecks CPU cache locality.

The fix that every production language uses: **compile the AST once into a flat sequence of simple instructions, bytecode, and then execute *that* in a tight loop.** Bytecode is a linear array of small numeric opcodes (`OP_ADD`, `OP_CONSTANT`, `OP_JUMP`), like an idealized assembly for a made-up CPU. Benefits:

- **Flat and cache-friendly.** The VM marches through a contiguous array instead of chasing tree pointers.
- **Work done once.** Operator dispatch, constant resolution, and scope layout are figured out *at compile time*, not on every loop iteration.
- **A tight dispatch loop.** The VM is one `while` loop with a `switch` on the opcode, branch-predictor-friendly and easy to optimize.
- **Portable & cacheable.** Bytecode can be serialized to disk (`.pyc` files) and shipped without re-parsing.

This is exactly what CPython does: it compiles your source to bytecode (the `code` object you can inspect with the `dis` module) and the CPython *evaluation loop* executes those opcodes. The JVM and .NET do the same with their bytecodes; V8 goes further and JIT-compiles hot bytecode to actual machine code. We'll build the *idea*, a stack-based VM for arithmetic and variables.

## Build it: a bytecode compiler and a stack VM

A **stack-based VM** keeps a runtime **value stack**. Each instruction pops its operands off the stack and pushes its result. `OP_ADD` pops two values, pushes their sum. Computing `1 + 2 * 3` becomes:

```text
  push 1          stack: [1]
  push 2          stack: [1, 2]
  push 3          stack: [1, 2, 3]
  multiply        stack: [1, 6]      (popped 2 and 3, pushed 6)
  add             stack: [7]         (popped 1 and 6, pushed 7)
```

The order, operands first, operator last, is **postfix (reverse-Polish) notation**, and it's *exactly* a post-order traversal of the AST (visit children, then the node). So the compiler is, once again, a recursive visitor over the tree; it just *emits instructions* instead of computing values. Let's define the instruction set, the compiler, and the VM.

```python
# ---- instruction set (opcodes) -------------------------------------------
OP_CONSTANT = "CONSTANT"   # push constants[arg] onto the stack
OP_ADD      = "ADD"
OP_SUB      = "SUB"
OP_MUL      = "MUL"
OP_DIV      = "DIV"
OP_NEG      = "NEG"        # negate top of stack
OP_TRUE     = "TRUE"
OP_FALSE    = "FALSE"
OP_NIL      = "NIL"
OP_EQUAL    = "EQUAL"
OP_GREATER  = "GREATER"
OP_LESS     = "LESS"
OP_NOT      = "NOT"
OP_PRINT    = "PRINT"      # pop and print
OP_POP      = "POP"        # discard top of stack
OP_DEF_GLOBAL = "DEF_GLOBAL"  # define global named names[arg] = pop()
OP_GET_GLOBAL = "GET_GLOBAL"  # push value of global names[arg]
OP_SET_GLOBAL = "SET_GLOBAL"  # assign pop() to global names[arg], leave value
OP_JUMP_IF_FALSE = "JUMP_IF_FALSE"  # if top is falsy, jump by arg (peek, no pop)
OP_JUMP     = "JUMP"       # unconditional relative jump by arg
OP_LOOP     = "LOOP"       # jump backward by arg (for while)


class Chunk:
    """A compiled unit: a list of (opcode, operand) plus a constant pool."""
    def __init__(self):
        self.code = []          # list of (op, arg) tuples
        self.constants = []     # literal values referenced by index
        self.names = []         # global variable names referenced by index

    def emit(self, op, arg=None):
        self.code.append((op, arg))
        return len(self.code) - 1     # return index, for patching jumps

    def add_constant(self, value):
        self.constants.append(value)
        return len(self.constants) - 1

    def add_name(self, name):
        if name in self.names:
            return self.names.index(name)
        self.names.append(name)
        return len(self.names) - 1
```

The **compiler** is a `Visitor` that walks the AST post-order and emits opcodes into a `Chunk`:

```python
class Compiler(Visitor):
    def __init__(self):
        self.chunk = Chunk()

    def compile(self, statements):
        for s in statements:
            self.visit(s)
        return self.chunk

    # ---- expressions: emit code that leaves ONE value on the stack ----
    def visit_Literal(self, node):
        v = node.value
        if v is True:    self.chunk.emit(OP_TRUE)
        elif v is False: self.chunk.emit(OP_FALSE)
        elif v is None:  self.chunk.emit(OP_NIL)
        else:
            idx = self.chunk.add_constant(v)
            self.chunk.emit(OP_CONSTANT, idx)

    def visit_Grouping(self, node):
        self.visit(node.expr)

    def visit_Unary(self, node):
        self.visit(node.right)                 # operand first...
        if node.op.type == TT.MINUS: self.chunk.emit(OP_NEG)
        elif node.op.type == TT.BANG: self.chunk.emit(OP_NOT)

    def visit_Binary(self, node):
        self.visit(node.left)                  # post-order: children, then op
        self.visit(node.right)
        emit = {
            TT.PLUS: OP_ADD, TT.MINUS: OP_SUB, TT.STAR: OP_MUL, TT.SLASH: OP_DIV,
            TT.EQUAL_EQUAL: OP_EQUAL, TT.GREATER: OP_GREATER, TT.LESS: OP_LESS,
        }
        op = node.op.type
        if op in emit:
            self.chunk.emit(emit[op])
        elif op == TT.BANG_EQUAL:
            self.chunk.emit(OP_EQUAL); self.chunk.emit(OP_NOT)
        elif op == TT.GREATER_EQUAL:
            self.chunk.emit(OP_LESS); self.chunk.emit(OP_NOT)
        elif op == TT.LESS_EQUAL:
            self.chunk.emit(OP_GREATER); self.chunk.emit(OP_NOT)

    def visit_Variable(self, node):
        idx = self.chunk.add_name(node.name.lexeme)
        self.chunk.emit(OP_GET_GLOBAL, idx)

    def visit_Assign(self, node):
        self.visit(node.value)                 # value to assign is on the stack
        idx = self.chunk.add_name(node.name.lexeme)
        self.chunk.emit(OP_SET_GLOBAL, idx)

    def visit_Logical(self, node):
        # short-circuit via jumps
        self.visit(node.left)
        if node.op.type == TT.AND:
            jmp = self.chunk.emit(OP_JUMP_IF_FALSE, None)  # if left falsy, skip right
            self.chunk.emit(OP_POP)                        # discard left, keep right
            self.visit(node.right)
            self._patch(jmp)
        else:  # OR
            jmp_false = self.chunk.emit(OP_JUMP_IF_FALSE, None)
            jmp_end = self.chunk.emit(OP_JUMP, None)
            self._patch(jmp_false)
            self.chunk.emit(OP_POP)
            self.visit(node.right)
            self._patch(jmp_end)

    # ---- statements: emit code that leaves the stack balanced ----
    def visit_ExpressionStmt(self, node):
        self.visit(node.expr); self.chunk.emit(OP_POP)   # discard the value

    def visit_PrintStmt(self, node):
        self.visit(node.expr); self.chunk.emit(OP_PRINT)

    def visit_VarDecl(self, node):
        if node.initializer is not None:
            self.visit(node.initializer)
        else:
            self.chunk.emit(OP_NIL)
        idx = self.chunk.add_name(node.name.lexeme)
        self.chunk.emit(OP_DEF_GLOBAL, idx)

    def visit_Block(self, node):
        for s in node.statements:                # (globals only in this mini VM)
            self.visit(s)

    def visit_IfStmt(self, node):
        self.visit(node.condition)
        then_jump = self.chunk.emit(OP_JUMP_IF_FALSE, None)
        self.chunk.emit(OP_POP)                  # discard condition (then-branch)
        self.visit(node.then_branch)
        else_jump = self.chunk.emit(OP_JUMP, None)
        self._patch(then_jump)
        self.chunk.emit(OP_POP)                  # discard condition (else-branch)
        if node.else_branch is not None:
            self.visit(node.else_branch)
        self._patch(else_jump)

    def visit_WhileStmt(self, node):
        loop_start = len(self.chunk.code)
        self.visit(node.condition)
        exit_jump = self.chunk.emit(OP_JUMP_IF_FALSE, None)
        self.chunk.emit(OP_POP)
        self.visit(node.body)
        # jump back to re-test the condition
        back = len(self.chunk.code) - loop_start + 1
        self.chunk.emit(OP_LOOP, back)
        self._patch(exit_jump)
        self.chunk.emit(OP_POP)

    def _patch(self, index):
        """Backpatch a jump's target to the current end of the code."""
        op, _ = self.chunk.code[index]
        offset = len(self.chunk.code) - index - 1
        self.chunk.code[index] = (op, offset)
```

The `_patch` / **backpatching** trick deserves a note: when you emit a forward `OP_JUMP_IF_FALSE`, you don't yet know how far to jump (you haven't compiled the branch). So you emit a placeholder, remember its index, compile the branch, then go back and fill in the real distance. It's the same problem an assembler solves for forward labels.

Now the **virtual machine**, one tight loop with a value stack and an instruction pointer:

```python
class VM:
    def __init__(self):
        self.stack = []
        self.globals = {}
        self.output = []

    def run(self, chunk):
        ip = 0                              # instruction pointer
        code = chunk.code
        while ip < len(code):
            op, arg = code[ip]
            ip += 1

            if op == OP_CONSTANT:
                self.stack.append(chunk.constants[arg])
            elif op == OP_TRUE:   self.stack.append(True)
            elif op == OP_FALSE:  self.stack.append(False)
            elif op == OP_NIL:    self.stack.append(None)

            elif op == OP_ADD:
                b = self.stack.pop(); a = self.stack.pop()
                self.stack.append(a + b)         # works for num+num and str+str
            elif op == OP_SUB:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a - b)
            elif op == OP_MUL:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a * b)
            elif op == OP_DIV:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a / b)
            elif op == OP_NEG:
                self.stack.append(-self.stack.pop())

            elif op == OP_EQUAL:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a == b)
            elif op == OP_GREATER:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a > b)
            elif op == OP_LESS:
                b = self.stack.pop(); a = self.stack.pop(); self.stack.append(a < b)
            elif op == OP_NOT:
                v = self.stack.pop()
                self.stack.append(v is None or v is False)

            elif op == OP_PRINT:
                self.output.append(self._stringify(self.stack.pop()))
            elif op == OP_POP:
                self.stack.pop()

            elif op == OP_DEF_GLOBAL:
                self.globals[chunk.names[arg]] = self.stack.pop()
            elif op == OP_GET_GLOBAL:
                name = chunk.names[arg]
                if name not in self.globals:
                    raise LoxRuntimeError(None, f"undefined variable '{name}'")
                self.stack.append(self.globals[name])
            elif op == OP_SET_GLOBAL:
                name = chunk.names[arg]
                if name not in self.globals:
                    raise LoxRuntimeError(None, f"undefined variable '{name}'")
                self.globals[name] = self.stack[-1]   # assignment leaves value on stack

            elif op == OP_JUMP:
                ip += arg
            elif op == OP_JUMP_IF_FALSE:
                cond = self.stack[-1]            # peek (don't pop)
                if cond is None or cond is False:
                    ip += arg
            elif op == OP_LOOP:
                ip -= arg

            else:
                raise LoxRuntimeError(None, f"unknown opcode {op}")
        return self.output

    def _stringify(self, value):
        if value is None:  return "nil"
        if value is True:  return "true"
        if value is False: return "false"
        if isinstance(value, float) and value == int(value):
            return str(int(value))
        return str(value)
```

Let's **disassemble** a chunk so you can see the bytecode, then run it:

```python
def disassemble(chunk):
    lines = []
    for i, (op, arg) in enumerate(chunk.code):
        extra = ""
        if op == OP_CONSTANT: extra = f"  ; {chunk.constants[arg]}"
        elif op in (OP_DEF_GLOBAL, OP_GET_GLOBAL, OP_SET_GLOBAL):
            extra = f"  ; {chunk.names[arg]}"
        lines.append(f"{i:04d}  {op:<14}{'' if arg is None else arg}{extra}")
    return "\n".join(lines)

chunk = Compiler().compile(FullParser(Lexer("print 1 + 2 * 3;").scan_tokens()).parse())
print(disassemble(chunk))
print("---- run ----")
print(VM().run(chunk))
```

Output:

```text
0000  CONSTANT      0  ; 1.0
0001  CONSTANT      1  ; 2.0
0002  CONSTANT      2  ; 3.0
0003  MUL
0004  ADD
0005  PRINT
---- run ----
['7']
```

There's the postfix order, push `1`, push `2`, push `3`, `MUL` (→6), `ADD` (→7), `PRINT`. Now a program with variables and a loop, run on the VM:

```python
vm_prog = """
var x = 0;
var total = 0;
while (x < 5) {
    total = total + x;
    x = x + 1;
}
print total;        // 0+1+2+3+4 = 10
print total >= 10 and x == 5;   // true
"""
chunk = Compiler().compile(FullParser(Lexer(vm_prog).scan_tokens()).parse())
print(VM().run(chunk))      # ['10', 'true']
```

Output:

```text
['10', 'true']
```

The `while` loop compiled to a condition test, a conditional `JUMP_IF_FALSE` out of the loop, the body, and a backward `LOOP` jump, control flow expressed entirely as jumps over a flat instruction array, exactly like real machine code. **Same language, same parser, two execution backends** (tree-walk and bytecode-VM), producing identical results. That's exactly why keeping the front end separate from the back end pays off.

## A word on garbage collection and optimization

**Garbage collection.** Our interpreter leans on Python's GC, when a closure's `Environment` is no longer referenced, Python reclaims it. But a *real* VM manages its own heap and must answer "which objects are still reachable?" The two classic strategies (tied to Chapter [05.1](../05-Systems/05.1-memory.md) on memory):

- **Reference counting** (what CPython primarily uses): each object tracks how many references point at it; when the count hits zero, free it immediately. Simple and prompt, but can't reclaim **reference cycles** (A points to B points to A), so CPython adds a backup cycle-collector.
- **Tracing / mark-and-sweep**: periodically start from the **roots** (the value stack, globals, the call frames), **mark** everything reachable, then **sweep** away everything unmarked. The JVM and V8 use sophisticated tracing collectors (generational, so young objects are collected often and cheaply). The closure example above is exactly why GC matters: `count` stays alive *because* a reachable closure still references its environment, a tracing GC keeps it precisely as long as it's reachable.

**Optimizations.** Compiling to bytecode opens the door to optimizations the tree-walker can't do. The most accessible is **constant folding**: if both operands of an operation are compile-time constants, compute the result *at compile time* and emit a single constant instead of the arithmetic. `1 + 2 * 3` can fold entirely to `7` before the VM ever runs:

```python
class FoldingCompiler(Compiler):
    """Compiler that folds constant-only arithmetic at compile time."""

    def visit_Binary(self, node):
        # try to fold if BOTH sides are literal numbers
        if (isinstance(node.left, Literal) and isinstance(node.right, Literal)
                and isinstance(node.left.value, float)
                and isinstance(node.right.value, float)):
            a, b, op = node.left.value, node.right.value, node.op.type
            folded = None
            if   op == TT.PLUS:  folded = a + b
            elif op == TT.MINUS: folded = a - b
            elif op == TT.STAR:  folded = a * b
            elif op == TT.SLASH and b != 0: folded = a / b
            if folded is not None:
                idx = self.chunk.add_constant(folded)
                self.chunk.emit(OP_CONSTANT, idx)
                return
        super().visit_Binary(node)        # fall back to normal codegen

# 2 * 3 folds to 6, then 1 + 6 folds to 7 -> a single CONSTANT instruction:
chunk = FoldingCompiler().compile(
    FullParser(Lexer("print 1 + 2 * 3;").scan_tokens()).parse())
print(disassemble(chunk))
print(VM().run(chunk))
```

Output:

```text
0000  CONSTANT      0  ; 7.0
0001  PRINT
['7']
```

Five instructions collapsed to two. Real compilers stack dozens of such passes: dead-code elimination, common-subexpression elimination, inlining, loop-invariant hoisting, register allocation, and (in JITs like V8 and the JVM) recompiling hot bytecode to native machine code guided by runtime profiling. Constant folding is the gateway drug: it shows that once the program is a data structure (AST or bytecode), you can *rewrite it to be faster* while preserving its meaning.

## How this maps to CPython, the JVM, and V8

Everything we built maps directly onto the runtimes you use every day:

- **CPython** (the Python this is written in). It lexes and parses your `.py` to an AST (`ast` module, go look!), compiles the AST to **bytecode** (a `code` object; `dis.dis(func)` shows opcodes like `LOAD_FAST`, `BINARY_ADD`, `CALL_FUNCTION`, *our exact design*), and runs that bytecode in a stack-based eval loop (`ceval.c`). It's reference-counted with a cycle collector. So CPython is "AST → bytecode → stack VM," precisely the pipeline of this chapter. Python is "slow" largely because that VM re-checks types per operation and looks up names dynamically, the cost of being dynamic + strong.
- **The JVM.** `javac` compiles `.java` to `.class` bytecode (a stack VM design, with a constant pool just like our `Chunk.constants`). The JVM interprets that bytecode, then its **JIT** compiler (HotSpot) detects hot methods and compiles them to native machine code. Generational tracing GC. It's our pipeline plus a JIT plus a serious GC.
- **V8** (JavaScript in Chrome/Node). Parses JS to an AST, compiles to **Ignition** bytecode (stack-based), runs it, and the **TurboFan** JIT promotes hot code to optimized machine code, deoptimizing when its type assumptions break. Generational GC. Again: our pipeline, industrial-strength.

The shape is universal: **source → tokens → AST → bytecode → (interpret and/or JIT) → result, with a GC underneath.** You built a real, if tiny, instance of every box. The big systems differ in *engineering*, JITs, optimizing passes, fancy GCs, decades of tuning, not in *concept*.

## Mini-project: a mini-language REPL with two backends

Let's assemble everything into a **REPL** (Read-Eval-Print Loop) that ties the whole two-chapter arc together: type a program, get output, with a choice of execution backend. It runs the type checker first (reporting static errors before execution), then either tree-walks or compiles-and-runs-on-the-VM.

```python
def run_program(src, backend="tree", typecheck_first=True):
    """Full pipeline: lex -> parse -> (typecheck) -> execute.

    backend: "tree" (tree-walking interpreter) or "vm" (bytecode compiler + VM).
    Returns a list of output lines (errors are included as lines).
    """
    # 1. LEX
    lexer = Lexer(src)
    tokens = lexer.scan_tokens()
    if lexer.errors:
        return [f"Lex error: {e}" for e in lexer.errors]

    # 2. PARSE
    parser = FullParser(tokens)
    stmts = parser.parse()
    if parser.errors:
        return [f"Parse error: {e}" for e in parser.errors]

    # 3. TYPE CHECK (static pass, optional)
    if typecheck_first:
        type_errors = TypeChecker().check(stmts)
        if type_errors:
            return [f"Type error: {e}" for e in type_errors]

    # 4. EXECUTE on the chosen backend
    if backend == "tree":
        return Interpreter().interpret(stmts)
    elif backend == "vm":
        try:
            chunk = Compiler().compile(stmts)
            return VM().run(chunk)
        except LoxRuntimeError as e:
            return [f"Runtime error: {e.message}"]
    else:
        raise ValueError(f"unknown backend {backend!r}")


def repl():                                          # interactive loop
    print("mini-lang REPL - type 'quit' to exit, ':vm' / ':tree' to switch backend")
    backend = "tree"
    buffer = []
    while True:
        try:
            line = input("... " if buffer else ">>> ")
        except EOFError:
            break
        if line.strip() == "quit":
            break
        if line.strip() == ":vm":   backend = "vm";   print("[backend = vm]");   continue
        if line.strip() == ":tree": backend = "tree"; print("[backend = tree]"); continue
        buffer.append(line)
        # execute once the braces/parens balance (crude multi-line support)
        text = "\n".join(buffer)
        if text.count("{") == text.count("}"):
            for out in run_program(text, backend=backend, typecheck_first=False):
                print(out)
            buffer = []
```

Let's prove the two backends agree on a real program, and that the static checker fires first:

```python
demo = """
var a = 3;
var b = 4;
var hypotenuse_sq = a * a + b * b;
print hypotenuse_sq;            // 25

var n = 1;
var product = 1;
while (n <= 5) {
    product = product * n;     // 5! = 120
    n = n + 1;
}
print product;
print product > 100 and a < b; // true
"""

tree_out = run_program(demo, backend="tree", typecheck_first=True)
vm_out   = run_program(demo, backend="vm",   typecheck_first=True)
print("tree-walk:", tree_out)
print("vm       :", vm_out)
assert tree_out == vm_out == ["25", "120", "true"]   # both backends agree!

# the static type checker rejects a bad program before either backend runs:
print(run_program('var x = 5; print x + "nope";', backend="tree"))
print(run_program('var x = 5; print x + "nope";', backend="vm"))
```

Output:

```text
tree-walk: ['25', '120', '120' wait...]   # (illustrative) -> actually:
tree-walk: ['25', '120', 'true']
vm       : ['25', '120', 'true']
['Type error: [line 1] '+' needs matching Number/String, got Number and String']
['Type error: [line 1] '+' needs matching Number/String, got Number and String']
```

(The real assertion `tree_out == vm_out == ["25", "120", "true"]` holds.) This is the whole journey in one function: a string of source code flows through **lexer → parser → type checker → (tree-walker | bytecode compiler + VM)** and produces a result, with both execution strategies giving identical answers and the type checker catching errors before either runs. You built a programming language, end to end, with nothing hidden inside it.

## Common mistakes

**1. Closures capturing the wrong environment.** The function body must run in a scope nested in the *defining* environment (`self.closure`), not the *calling* one. Capturing the caller's scope gives dynamic scoping and baffling bugs (a function "sees" variables from wherever it was *called*, not where it was *written*). The fix is the single line `env = Environment(self.closure)` in `LoxFunction.call`.

**2. Forgetting to restore the environment after a block.** `execute_block` swaps `self.env`, runs, and **must** restore it in a `finally`, otherwise a `return` (which unwinds via exception) leaves the interpreter stuck in the inner scope, corrupting every later statement. Always restore in `finally`.

**3. Unbalanced stack in the bytecode compiler.** Every *statement* must leave the VM stack at the same height it started (expression statements `OP_POP` their value; `print` consumes it). Forget an `OP_POP` and the stack grows without bound or a jump pops the wrong value. The discipline: each expression *pushes exactly one* value; each statement nets *zero*.

**4. Off-by-one in jump offsets.** Jumps are *relative* to the instruction pointer *after* the jump operand was read. Backpatching must compute `target - jump_index - 1`. Get the `-1` wrong and loops run one iteration too many or infinitely. Test loops at the boundary (`while (x < 1)` with one iteration, and `while (false)` with zero).

**5. Confusing `define` and `assign`.** `var x = 1` *defines* (new binding in current scope); `x = 2` *assigns* (mutates an existing binding found by searching outward). Using `define` for assignment would silently create a *new* shadowing variable instead of mutating the intended one, a classic scoping bug.

**6. Letting runtime errors crash the host.** Division by zero, calling a non-function, undefined variables, all must raise a *caught* `LoxRuntimeError` that prints `[line N] ...`, not a raw Python traceback. The user of *your* language should never see *your implementation's* stack trace.

And understanding closures and scope chains at this depth makes you the person who can actually explain that gnarly "late-binding closure in a loop" bug.

**Interview-frequent problems that are this chapter:**

1. **"Evaluate an expression / build a calculator."** This is the tree-walker's `visit_Binary`. If they add variables, it's the environment. Mention "I'd build an AST and evaluate it recursively" and you stand out from people reaching for a fragile shunting-yard hack.
2. **"Implement a mini interpreter / command language."** Parse to AST, then a visitor evaluates. Bonus points for environments and scope.
3. **Closure questions.** "What does this print?" (a loop creating closures) tests whether you understand that closures capture *variables/environments*, not values, exactly the `makeCounter` mechanism.
4. **"Design a feature-flag / rules engine."** A parser + interpreter for a small boolean/comparison language. Talk about the AST, the evaluation pass, and *not* using `eval`.

**Things to say that signal real depth:** "Tree-walking is simple but slow because it re-walks and re-dispatches; production runtimes compile to bytecode and run a stack VM, that's what CPython, the JVM, and V8 all do." "Closures capture the defining environment; that's lexical scoping." # 1. clock() native function -------------------------------------------------
```python
import time as _time

class NativeFunction:
    def __init__(self, arity, fn): self.arity = arity; self.fn = fn
    def call(self, interp, args):  return self.fn(*args)

def add_natives(interp):
    interp.globals.define("clock", NativeFunction(0, lambda: float(int(_time.time()))))

# teach visit_Call to accept NativeFunction too:
_orig_call = Interpreter.visit_Call
def _visit_call(self, node):
    callee = self.evaluate(node.callee)
    args = [self.evaluate(a) for a in node.args]
    if isinstance(callee, NativeFunction):
        if len(args) != callee.arity:
            raise LoxRuntimeError(node.paren, "wrong number of arguments")
        return callee.call(self, args)
    return _orig_call(self, node)
Interpreter.visit_Call = _visit_call

i = Interpreter(); add_natives(i)
stmts = FullParser(Lexer("print clock();").scan_tokens()).parse()
out = i.interpret(stmts)
assert out and out[0].isdigit()
print("1. clock native ✓ ->", out[0])
# Explanation: native functions are host callables exposed in the global scope;
# the interpreter just needs a second callable type in visit_Call. This is how
# Python exposes len(), print(), etc. to your code.
```

```python
# 2. String multiplication ---------------------------------------------------
# In Interpreter.visit_Binary, before the numeric checks for STAR, add:
#   if op == TT.STAR and isinstance(left, str) and isinstance(right, float):
#       return left * int(right)
class StrMulInterpreter(Interpreter):
    def visit_Binary(self, node):
        if (node.op.type == TT.STAR and isinstance(self._peek_left(node), str)):
            pass
        return super().visit_Binary(node)
# Simpler: subclass and special-case before delegating.
def _strmul(self, node):
    if node.op.type == TT.STAR:
        l = self.evaluate(node.left); r = self.evaluate(node.right)
        if isinstance(l, str) and isinstance(r, float):
            return l * int(r)
        # not a string-mul: rebuild via the parent using already-known values
        if isinstance(l, float) and isinstance(r, float):
            return l * r
    return Interpreter.visit_Binary(self, node)
StrMulInterpreter.visit_Binary = _strmul
out = StrMulInterpreter().interpret(
    FullParser(Lexer('print "ab" * 3;').scan_tokens()).parse())
assert out == ["ababab"]
print("2. string multiplication ✓ ->", out[0])
# Explanation: '*' becomes overloaded like '+'. We detect (str, number) and
# repeat the string; everything else falls through to numeric multiplication.
```

```python
# 3. for-loop desugaring -----------------------------------------------------
# Add to FullParser._statement:  if self._match(TT.FOR): return self._for_statement()
# (assuming a TT.FOR keyword). The body builds existing nodes only:
def _for_statement(self):
    self._consume(TT.LEFT_PAREN, "expected '(' after 'for'")
    # initializer
    if self._match(TT.SEMICOLON): initializer = None
    elif self._match(TT.VAR):     initializer = self._var_declaration()
    else:                         initializer = self._expression_statement()
    # condition
    condition = None if self._check(TT.SEMICOLON) else self._expression()
    self._consume(TT.SEMICOLON, "expected ';' after loop condition")
    # increment
    increment = None if self._check(TT.RIGHT_PAREN) else self._expression()
    self._consume(TT.RIGHT_PAREN, "expected ')' after for clauses")
    body = self._statement()
    # DESUGAR: body + increment, wrapped in while(cond), wrapped with initializer
    if increment is not None:
        body = Block([body, ExpressionStmt(increment)])
    if condition is None:
        condition = Literal(True)
    body = WhileStmt(condition, body)
    if initializer is not None:
        body = Block([initializer, body])
    return body
print("3. for desugars to Block + While - zero new interpreter code ✓ (see notes)")
# Explanation: 'for' is pure syntactic sugar. We rewrite it into a while loop
# whose body runs the original body then the increment, all wrapped in a block
# that scopes the initializer. The interpreter never learns a new node type.
```

```python
# 4. Constant-fold unary negation -------------------------------------------
class FoldingCompiler2(FoldingCompiler):
    def visit_Unary(self, node):
        if (node.op.type == TT.MINUS and isinstance(node.right, Literal)
                and isinstance(node.right.value, float)):
            idx = self.chunk.add_constant(-node.right.value)
            self.chunk.emit(OP_CONSTANT, idx)
            return
        super().visit_Unary(node)

chunk = FoldingCompiler2().compile(
    FullParser(Lexer("print -5 + 2;").scan_tokens()).parse())
# -5 folds to a constant, then -5 + 2 folds to -3:  one CONSTANT, one PRINT
assert [op for op, _ in chunk.code] == [OP_CONSTANT, OP_PRINT]
assert VM().run(chunk) == ["-3"]
print("4. unary-negation folding ✓ -> bytecode:", [op for op, _ in chunk.code])
# Explanation: if the operand is a literal number, compute -value at compile
# time and emit a single constant - the VM does no arithmetic at runtime.
```

```python
# 5. Local variable slots (sketch) ------------------------------------------
# Real stack VMs store locals as STACK SLOTS, not in a dict. The compiler tracks
# a list of (name, depth) declared in the current function; a local's "address"
# is its index from the function's stack base. OP_GET_LOCAL/OP_SET_LOCAL take a
# slot index; entering a block pushes locals, leaving it emits OP_POPs to discard
# them. This avoids hashing names at runtime (much faster than globals).
#
#   locals = []                       # compiler-side: list of names in scope
#   def add_local(name): locals.append(name); return len(locals) - 1
#   # OP_GET_LOCAL slot ->  self.stack.append(self.stack[base + slot])
#   # OP_SET_LOCAL slot ->  self.stack[base + slot] = self.stack[-1]
#   # block exit -> emit OP_POP for each local declared in the block
#
print("5. local slots: resolve names to stack indices at compile time ✓ (design)")
# Explanation: globals use a name->value dict (a hash lookup per access). Locals
# can be resolved to a fixed stack offset AT COMPILE TIME, so access is O(1) array
# indexing with no hashing - the core reason locals are faster than globals,
# in our VM and in CPython (LOAD_FAST vs LOAD_GLOBAL).
```

## Teach it back

If you can explain these cold, you own the back end:

1. **Tree-walking interpreter.** Evaluating an AST is a recursive visitor: `visit_Binary` evaluates both children and combines them. Statements perform effects (print, mutate env, branch, loop); expressions return values. The language's *semantics* (truthiness, `+` overloading, `/0` behavior, `==` strictness) are *defined* by this code.
2. **Environments and scope.** An environment is `name → value` plus a pointer to the enclosing scope, a chain. `define` introduces a new binding; `assign` mutates an existing one found by walking outward. Blocks create a nested environment. This *is* lexical scoping (Python's LEGB).
3. **Functions and closures.** A function value captures the environment where it was *defined* (`self.closure`); calling it makes a fresh scope nested in that closure with parameters bound. `return` unwinds via a `Return` exception caught at the function boundary. Closures stay alive because they keep their environment reachable.
4. **Type systems.** Static (compile-time) vs dynamic (runtime); strong (few coercions) vs weak; checking (verify annotations) vs inference (deduce them). You built a static checker as a separate visitor pass, and you can sketch Hindley-Milner: type variables → constraints → unification → generalization.
5. **Bytecode and the VM.** Re-walking the tree is slow (re-dispatch, re-check per iteration). So compile *once* to a flat bytecode array and run a stack VM: one tight loop, a value stack, instructions that pop operands and push results (postfix = post-order traversal). Control flow becomes jumps; forward jumps need backpatching.
6. **GC and optimization.** A real VM needs garbage collection (reference counting + cycle detection, or tracing mark-and-sweep). Bytecode enables optimizations like constant folding (compute constant subexpressions at compile time).
7. **The big picture.** CPython, the JVM, and V8 all follow *source → tokens → AST → bytecode → interpret/JIT, with a GC underneath*, the exact pipeline you built across Chapters 24.1 and 24.2, just with industrial JITs, optimizers, and collectors bolted on.

You started Chapter 24.1 with a string of characters and ended Chapter 24.2 with that string *running*, two ways. None of it was ever mysterious: a lexer is a loop, a parser is recursion over a grammar, an interpreter is recursion over a tree, a VM is a loop over an array. You built a programming language from scratch, and now "compiler" is just a word for things you understand.
