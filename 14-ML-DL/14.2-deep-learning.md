## Start here - the on-ramp (neural nets without the mystique)

If 14.1's logistic regression was "draw one line to separate the dots," a neural network is **"draw many lines and then bend them into a curve."** That's the whole idea. Let's unpack it with no jargon.

**A neuron is a tiny decision-maker.** It takes some inputs, multiplies each by a weight (how much it cares about that input), adds them up, and then passes the total through a "should I fire?" function. That's it: `weighted sum → squash → output`. Logistic regression *is* a single neuron.

**A layer is a row of neurons** all looking at the same inputs but caring about different combinations. **A network is layers stacked**, where each layer's outputs become the next layer's inputs. Early layers learn simple things (in an image: edges); later layers combine those into complex things (shapes, then faces). It's an assembly line that builds understanding in stages.

**Why does stacking help?** Imagine trying to cut a wiggly shape out of paper with one straight scissor cut, impossible. But with many cuts, each straight, you can approximate any outline. Each neuron is one straight cut; the nonlinearity (the "squash") is the hinge that lets you *combine* cuts into curves. Without the squash, ten layers of straight cuts collapse back into one straight cut (we prove this below). The nonlinearity is non-negotiable, it's what makes depth mean anything.

**How does it learn?** Same loop as everything in 14.1: make a prediction (**forward pass**), measure how wrong it is (**loss**), and figure out which direction to nudge every weight to reduce the error (**backpropagation**), then take a small step (**gradient descent**). Backprop sounds scary but it's just the chain rule from calculus applied over and over, "if the final error changes when you wiggle this weight, by how much?" We derive it fully and implement it in raw NumPy before touching a library.

**Why this matters:** every modern AI system, image recognition, ChatGPT, voice assistants, self-driving perception, is this same forward/loss/backward/step loop, scaled up with clever architectures (CNNs for images, Transformers for text). Master the loop on a 4-example XOR problem and you understand the machinery behind all of it. The rest is engineering. Keep the "many cuts bent into a curve" picture in mind as we make it precise.

## From logistic regression to neural networks

Logistic regression is a single neuron: `\hat y = σ(w^\top x + b)`. A linear transform followed by a nonlinearity. Its limit: it can only carve the input space with a single hyperplane. It **cannot** solve XOR, no straight line separates `{(0,0),(1,1)}` from `{(0,1),(1,0)}`.

A **neuron** is exactly that unit: `a = φ(w^\top x + b)`, where `φ` is an activation function. Stack neurons into a **layer**, stack layers into a **network**:

$$a^{[l]} = \phi\big(W^{[l]} a^{[l-1]} + b^{[l]}\big), \qquad a^{[0]} = x$$

### Why depth and nonlinearity add power

If `φ` were the identity, then `W^{[2]}(W^{[1]}x) = (W^{[2]}W^{[1]})x`, a product of matrices is just another matrix. Stacking linear layers collapses to a single linear layer. **Nonlinearity is what makes depth meaningful.** With a nonlinearity between layers, the network composes simple curved boundaries into arbitrarily complex ones.

**Universal approximation theorem (intuition):** a feedforward net with a single hidden layer and a nonlinear activation can approximate any continuous function on a compact set, given enough hidden units. So even shallow nets are universal *in principle*. But "enough units" can be astronomically large for a shallow net, whereas **depth** lets the network build hierarchical, reusable features (edges → shapes → objects), reaching the same expressiveness with far fewer parameters. Depth is about efficiency of representation, not raw possibility.

## Activations: why ReLU won

- **Sigmoid** `σ(z) = 1/(1+e^{-z})`, range (0,1). Saturates: for large `|z|`, `σ' = σ(1−σ) ≈ 0`. Gradients vanish.
- **Tanh** `= 2σ(2z) − 1`, range (−1,1), zero-centered (better than sigmoid) but still saturates.
- **ReLU** `= max(0, z)`. Derivative is `1` for `z>0`, `0` otherwise. No saturation on the positive side → gradients flow → deep nets actually train. Cheap to compute. The default.
- **Leaky ReLU** `= max(αz, z)` (small `α`, e.g. 0.01), fixes "dying ReLU" where a neuron stuck at `z<0` gets zero gradient forever and never recovers.
- **GELU / SiLU**, smooth ReLU variants, standard in modern Transformers.

**The vanishing gradient problem.** Backprop multiplies derivatives layer by layer (chain rule). With sigmoid/tanh, each factor is `≤ 0.25` (sigmoid) or `≤ 1` and usually `<1`. Multiply many such factors through a deep net and the gradient at early layers `≈ 0`, they stop learning. ReLU's derivative is exactly `1` on the active path, so the product doesn't decay. **That's why ReLU enabled deep learning.** (Skip connections / residuals and normalization help too, covered below.)

## Forward pass and backpropagation, derived

Take a two-layer net (one hidden layer), binary classification with cross-entropy loss. Notation: `z` = pre-activation, `a` = activation, `[l]` = layer.

**Forward pass:**

$$
z^{[1]} = W^{[1]} x + b^{[1]}, \quad a^{[1]} = \text{ReLU}(z^{[1]})
$$
$$
z^{[2]} = W^{[2]} a^{[1]} + b^{[2]}, \quad \hat y = a^{[2]} = \sigma(z^{[2]})
$$
$$
J = -\big[y \log \hat y + (1-y)\log(1-\hat y)\big]
$$

**Backward pass, apply the chain rule layer by layer.** We derived in 14.1 that for sigmoid + cross-entropy, `\frac{\partial J}{\partial z^{[2]}}` simplifies nicely (the `\hat y(1-\hat y)` cancels):

$$\delta^{[2]} \equiv \frac{\partial J}{\partial z^{[2]}} = \hat y - y$$

Now propagate. Gradients for the output layer's parameters:

$$\frac{\partial J}{\partial W^{[2]}} = \delta^{[2]} (a^{[1]})^\top, \qquad \frac{\partial J}{\partial b^{[2]}} = \delta^{[2]}$$

(Because `z^{[2]} = W^{[2]}a^{[1]} + b^{[2]}`, so `\partial z^{[2]}/\partial W^{[2]} = a^{[1]}`.)

Push the error back into the hidden layer. The chain rule routes `δ^{[2]}` through `W^{[2]}`, then through the ReLU's derivative:

$$\delta^{[1]} = \big({W^{[2]}}^\top \delta^{[2]}\big) \odot \text{ReLU}'(z^{[1]})$$

where `⊙` is elementwise and `ReLU'(z) = 1[z>0]`. Then:

$$\frac{\partial J}{\partial W^{[1]}} = \delta^{[1]} x^\top, \qquad \frac{\partial J}{\partial b^{[1]}} = \delta^{[1]}$$

**The pattern (this is all of backprop):**
1. Compute the error `δ` at the output (`\hat y - y`).
2. Move backward: each layer's error = (next layer's weight transpose times next error) ⊙ this layer's activation derivative.
3. Each weight's gradient = (its layer's error) × (its input activation).

Backprop is just the chain rule, organized to reuse the `δ`'s so you compute each gradient once. That reuse is *dynamic programming on the computation graph*, exactly what autograd automates.

### Worked example - a full forward + backward pass by hand

Tiny net so you can check every number on paper. Input `x = [1, 2]`, one hidden ReLU neuron, one sigmoid output, label `y = 1`.

Weights: `W¹ = [0.5, -0.3]` (hidden neuron's weights on the two inputs), `b¹ = 0.1`; `W² = 0.8`, `b² = 0.0`.

**Forward.**
- `z¹ = W¹·x + b¹ = 0.5·1 + (-0.3)·2 + 0.1 = 0.5 - 0.6 + 0.1 = 0.0`.
- `a¹ = ReLU(0.0) = 0.0`. *(Borderline, a dead-ish neuron. Let's bump the bias to make it informative: set `b¹ = 0.4`.)*
- Redo: `z¹ = 0.5 - 0.6 + 0.4 = 0.3`, `a¹ = ReLU(0.3) = 0.3`.
- `z² = W²·a¹ + b² = 0.8·0.3 = 0.24`. `ŷ = σ(0.24) = 1/(1+e^{-0.24}) ≈ 0.560`.
- Loss `J = -log(ŷ) = -log(0.560) ≈ 0.580`.

**Backward.**
- Output error (sigmoid + cross-entropy shortcut): `δ² = ŷ - y = 0.560 - 1 = -0.440`.
- Output-layer grads: `∂J/∂W² = δ²·a¹ = -0.440·0.3 = -0.132`; `∂J/∂b² = δ² = -0.440`.
- Hidden error: `δ¹ = (W²·δ²)·ReLU'(z¹) = (0.8·-0.440)·1 = -0.352` (ReLU' = 1 since `z¹ = 0.3 > 0`).
- Hidden grads: `∂J/∂W¹ = δ¹·x = -0.352·[1,2] = [-0.352, -0.704]`; `∂J/∂b¹ = δ¹ = -0.352`.

**Update** with `α = 1.0` (large just to see movement):
- `W² ← 0.8 - 1.0·(-0.132) = 0.932`; `b² ← 0 - (-0.44) = 0.44`.
- `W¹ ← [0.5,-0.3] - [-0.352,-0.704] = [0.852, 0.404]`; `b¹ ← 0.4 - (-0.352) = 0.752`.

**Did the loss drop?** New forward: `z¹ = 0.852·1 + 0.404·2 + 0.752 = 0.852 + 0.808 + 0.752 = 2.412`, `a¹ = 2.412`; `z² = 0.932·2.412 + 0.44 = 2.248 + 0.44 = 2.688`; `ŷ = σ(2.688) ≈ 0.936`. Loss `= -log(0.936) ≈ 0.066`. Down from 0.580 to 0.066 in **one** step: the hand-computed backprop reduced the loss. Every gradient above came straight from the boxed formulas, no library. This is exactly what the NumPy code in the next section automates over a batch.

## Build it: a fully-connected net + backprop from scratch (XOR)

XOR, the problem a single neuron can't solve. If your from-scratch net learns it, the backprop is correct.

```python
import numpy as np
rng = np.random.default_rng(42)

# XOR dataset
X = np.array([[0,0],[0,1],[1,0],[1,1]], dtype=float)   # (4, 2)
y = np.array([[0],[1],[1],[0]], dtype=float)            # (4, 1)

def sigmoid(z): return 1/(1+np.exp(-z))
def relu(z):    return np.maximum(0, z)
def d_relu(z):  return (z > 0).astype(float)

# Architecture: 2 -> 8 (ReLU) -> 1 (sigmoid). He-init for ReLU.
n_in, n_hid, n_out = 2, 8, 1
W1 = rng.normal(0, np.sqrt(2/n_in),  (n_in, n_hid))
b1 = np.zeros((1, n_hid))
W2 = rng.normal(0, np.sqrt(2/n_hid), (n_hid, n_out))
b2 = np.zeros((1, n_out))

lr = 0.5
for epoch in range(5000):
    # ---- forward ----
    z1 = X @ W1 + b1;  a1 = relu(z1)
    z2 = a1 @ W2 + b2; yhat = sigmoid(z2)

    # ---- loss (binary cross-entropy) ----
    eps = 1e-9
    loss = -np.mean(y*np.log(yhat+eps) + (1-y)*np.log(1-yhat+eps))

    # ---- backward (the derivation, vectorized over the batch) ----
    m = X.shape[0]
    d2 = (yhat - y) / m              # δ² = ŷ - y  (sigmoid+CE shortcut)
    dW2 = a1.T @ d2                  # ∂J/∂W² = a¹ᵀ δ²
    db2 = d2.sum(axis=0, keepdims=True)
    d1 = (d2 @ W2.T) * d_relu(z1)    # δ¹ = (W²ᵀδ²) ⊙ ReLU'(z¹)
    dW1 = X.T @ d1                   # ∂J/∂W¹ = xᵀ δ¹
    db1 = d1.sum(axis=0, keepdims=True)

    # ---- gradient descent update ----
    W2 -= lr*dW2; b2 -= lr*db2
    W1 -= lr*dW1; b1 -= lr*db1

    if epoch % 1000 == 0:
        print(f"epoch {epoch:4d}  loss {loss:.4f}")

print("\nPredictions:", np.round(sigmoid(relu(X@W1+b1)@W2+b2).ravel(), 3))
# -> ~[0, 1, 1, 0]  - XOR solved by hand-rolled backprop
```

It learns XOR, proof the chain-rule derivation and the vectorized backward pass are correct. Every gradient came from the formulas above, no library.

## Losses, optimizers, regularization - the practical machinery

### Loss functions
- **MSE** for regression (Gaussian-noise MLE, from 14.1).
- **Binary cross-entropy** for 2-class, **categorical cross-entropy** + **softmax** for multiclass. Softmax `\text{softmax}(z)_k = e^{z_k}/\sum_j e^{z_j}` turns logits into a probability distribution; paired with cross-entropy its gradient is again the clean `\hat y - y`.

### Optimizers - each fixes a flaw in the last
- **SGD**, `w \leftarrow w - \alpha \nabla J`. Noisy on mini-batches; struggles in ravines (zig-zags across steep directions, crawls along shallow ones).
- **Momentum**, accumulate a velocity `v = \beta v + \nabla J`, step with `v`. Like a ball rolling downhill: averages out the zig-zag, accelerates along consistent directions. Fixes slow ravines.
- **RMSProp**, divide each coordinate's step by a running RMS of its recent gradients: `s = \rho s + (1-\rho)\nabla^2`, `w -= \alpha \nabla/\sqrt{s+\epsilon}`. Adapts the *per-parameter* learning rate, big-gradient directions get damped, small ones amplified. Fixes the "one global `α` doesn't fit all parameters" problem.
- **Adam**, momentum + RMSProp combined (first and second moment estimates, bias-corrected). The default. Robust, fast, little tuning. `betas=(0.9, 0.999)`, `lr≈1e-3` is the everyday starting point.

### Initialization
Start weights too big → activations/gradients explode; too small → they vanish. **Xavier/Glorot** init (variance `1/n`) for tanh/sigmoid, **He** init (variance `2/n`) for ReLU, chosen to keep activation variance stable across layers. (We used He init above.) Biases start at zero.

### Normalization
- **Batch norm**, normalize each layer's pre-activations to zero-mean/unit-variance *per mini-batch*, then learn a scale/shift. Stabilizes and accelerates training, acts as a mild regularizer. Behaves differently in train vs. eval (uses running stats at inference), a classic bug source.
- **Layer norm**, normalizes across features within one example (not across the batch). Batch-size independent; the norm of choice in Transformers and RNNs.

### Regularization
- **Dropout**, randomly zero a fraction `p` of activations each step (train only). Forces redundancy, prevents co-adaptation; like training an ensemble of subnetworks. Turn it off at eval.
- **Weight decay**, L2 on weights (the `(1-\alpha\lambda)w` shrink from 14.1), built into optimizers.
- **Early stopping**, halt when validation loss stops improving. Free regularization.

### The training loop + LR schedules
Per epoch: shuffle → for each mini-batch: forward → loss → `backward` → optimizer step → zero grads. Track train and val loss. **LR schedules** (step decay, cosine annealing, warmup) lower `α` over time so you take big steps early and fine steps near the minimum. A warmup ramp avoids early instability with adaptive optimizers.

## Rebuild the same net in PyTorch (and confirm autograd matches)

### First: autograd computes the gradients you derived by hand

```python
import torch

# One logistic-regression step, by hand vs. autograd
x = torch.tensor([[1.0, 2.0]])
y = torch.tensor([[1.0]])
w = torch.tensor([[0.1],[0.2]], requires_grad=True)
b = torch.tensor([[0.0]], requires_grad=True)

z = x @ w + b
yhat = torch.sigmoid(z)
loss = -(y*torch.log(yhat) + (1-y)*torch.log(1-yhat)).mean()
loss.backward()

print("autograd dL/dw:", w.grad.ravel().tolist())
# Hand-derived: dL/dw = (ŷ - y) * x
manual = ((yhat - y) * x).detach().ravel().tolist()
print("hand-derived :", manual)   # identical - autograd IS the chain rule
```

The numbers match. `loss.backward()` is doing exactly the `(\hat y - y)x` you derived, autograd is just automated backprop over the computation graph.

### The full net in PyTorch

```python
import torch
import torch.nn as nn

X = torch.tensor([[0,0],[0,1],[1,0],[1,1]], dtype=torch.float32)
y = torch.tensor([[0],[1],[1],[0]], dtype=torch.float32)

class XORNet(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(2, 8), nn.ReLU(),
            nn.Linear(8, 1))               # logits; loss applies sigmoid
    def forward(self, x):
        return self.net(x)

model = XORNet()
criterion = nn.BCEWithLogitsLoss()         # numerically stable sigmoid+BCE
optimizer = torch.optim.Adam(model.parameters(), lr=0.05)

for epoch in range(2000):
    optimizer.zero_grad()                  # clear old grads
    logits = model(X)                      # forward
    loss = criterion(logits, y)
    loss.backward()                        # autograd backprop
    optimizer.step()                       # update
    if epoch % 500 == 0:
        print(f"epoch {epoch}  loss {loss.item():.4f}")

print(torch.sigmoid(model(X)).detach().round().ravel())   # ~[0,1,1,0]
```

Same architecture, same result as the NumPy version, now with autograd doing the backward pass and Adam doing the update.

import tensorflow as tf

## Architectures overview (with intuition)

- **CNNs (images).** A **convolution** slides a small learnable filter across the image, computing dot products, detecting a local pattern (edge, texture) regardless of *where* it appears (translation equivariance) and sharing weights (far fewer parameters than dense layers). Stacked convs build a hierarchy: edges → motifs → parts → objects. **Pooling** (max/avg) downsamples for spatial invariance and a wider receptive field. This is *the* reason CNNs dominate vision: locality + weight sharing match image structure.

- **RNNs / LSTMs (sequences).** An RNN carries a hidden state across time steps, reusing the same weights, natural for sequences. Plain RNNs suffer vanishing gradients over long sequences (the deep-net problem, but in time). **LSTMs/GRUs** add gated memory cells (input/forget/output gates) so information and gradients flow across long spans. Relevant to **time-series forecasting**, an LSTM can learn seasonality and long-range dependence that a fixed-window model misses.

- **Transformers / attention (sequences, and now everything).** **Self-attention** lets each position directly look at every other position: compute query/key/value projections, score `Q K^\top / \sqrt{d}`, softmax to weights, take the weighted sum of values. Each token's new representation is a content-based weighted average of the whole sequence, no recurrence, fully parallel, and no distance-based gradient decay (any position can attend to any other in one step). **Multi-head** attention runs several in parallel to capture different relationships; positional encodings reinject order. This is why Transformers replaced RNNs for most sequence work, including modern **probabilistic forecasting** (Temporal Fusion Transformer, Informer), they model long-range temporal dependencies better than LSTMs and parallelize on GPUs.

## Practical training

- **GPUs.** Deep learning is matrix multiplies; GPUs do thousands in parallel. Move model and data to device (`.to("cuda")`); keep them on the same device. Use mixed precision (`torch.cuda.amp`) for big speedups.
- **Batching.** Mini-batches (32-512) balance gradient quality, memory, and hardware throughput. Bigger batches → smoother gradients but may generalize slightly worse and need LR scaling.
- **Overfitting diagnosis.** Watch train vs. val loss. *Both high* → underfitting (bigger model, train longer, less regularization). *Train low, val high and rising* → overfitting (more data, augmentation, dropout, weight decay, early stopping). The gap between the two curves is the bias-variance story (14.1) in real time.
- **Transfer learning.** Start from a model pretrained on a huge dataset, replace the head, fine-tune on your (smaller) data. Early layers already learned general features; you reuse them. Often the difference between failure and success when data is limited.

### Common mistakes

The deep-learning-specific footguns. Most "my net won't train" tickets are one of these.

- **Forgetting `optimizer.zero_grad()`.** PyTorch *accumulates* gradients by default. Skip the zeroing and gradients from every previous batch pile up, so your steps explode. Classic first-week bug.
- **Not putting the model in `eval()` mode for inference.** Dropout stays on and BatchNorm uses batch stats instead of running stats, so your validation/test numbers are wrong and noisy. Pair: `model.eval()` for inference, `model.train()` for training; wrap inference in `torch.no_grad()`.
- **Data leakage in scaling / windowing (time series).** Computing the scaler's mean/std on the whole series leaks the future into the past. Scale with train-only stats, split chronologically, never shuffle across the time boundary.
- **Wrong loss for the output activation.** Applying `sigmoid` *and* using `BCELoss` and also a manual log, or worse, double-squashing. Prefer `BCEWithLogitsLoss` / `CrossEntropyLoss`, which take **raw logits** (numerically stable) and apply the activation internally. Feeding already-softmaxed values to `CrossEntropyLoss` is a subtle, common error.
- **Learning rate wrong by 10×.** Too high → loss is NaN or oscillates; too low → loss barely moves. Always sanity-check the loss curve in the first few hundred steps before a long run.
- **Not scaling/normalizing inputs.** Nets train far better on standardized inputs; raw features with huge ranges cause unstable gradients.
- **Class imbalance ignored.** A net will happily predict the majority class. Use class weights in the loss, resampling, or focal loss, and never judge by accuracy (see 14.1).
- **Evaluating on training data / no held-out set.** Same sin as 14.1; a big net memorizes effortlessly. Watch the *gap* between train and val loss.
- **Exploding/vanishing gradients in RNNs.** Use gradient clipping (`clip_grad_norm_`), LSTM/GRU instead of vanilla RNN, and proper init.

### On the job / interview angle

Deep-learning interview questions skew conceptual, they want to know you understand the mechanism, not just the API.

> **Q: What does `loss.backward()` actually do?**
> A: It runs reverse-mode autodiff (backpropagation) over the computation graph built during the forward pass, computing `∂loss/∂parameter` for every parameter via the chain rule, and stores each in the parameter's `.grad`. It's the automated, memoized version of the `δ` recursion derived above.

> **Q: Why did ReLU replace sigmoid/tanh in hidden layers?**
> A: Sigmoid/tanh saturate, so their derivatives shrink toward zero; multiplying many small derivatives across layers makes early-layer gradients vanish and learning stalls. ReLU's derivative is exactly 1 on the active side, so gradients flow through deep nets. It's also cheaper to compute.

> **Q: SGD vs. Adam, when and why?**
> A: Adam (momentum + per-parameter adaptive step + bias correction) is the robust default; it converges fast with little tuning. Well-tuned SGD-with-momentum often generalizes slightly better and is common in vision (e.g., ResNet training) where you have time to tune the LR schedule. Start with Adam.

> **Q: How do you tell underfitting from overfitting in a training run?**
> A: Both losses high and plateaued → underfitting (bigger model, train longer, less regularization). Train loss low but val loss high/rising → overfitting (more data/augmentation, dropout, weight decay, early stopping). The gap between the two curves is the bias-variance story in real time.

> **Q: What's the difference between BatchNorm and LayerNorm, and when do you use each?**
> A: BatchNorm normalizes each feature across the mini-batch (great for CNNs, but batch-size-dependent and behaves differently in train vs. eval). LayerNorm normalizes across features within a single example (batch-size independent; the standard in Transformers and RNNs).

> **Q: Conceptually, how does self-attention work and why did it replace RNNs?**
> A: Each token projects to a query, key, and value; it scores its query against every other token's key (`QKᵀ/√d`), softmaxes to weights, and outputs a weighted sum of values. So every position reaches every other in one step, fully parallel, no distance-based gradient decay, which beats the sequential bottleneck and vanishing gradients of RNNs on long-range dependencies.

> **Q: Why use dropout, and what's the train/eval gotcha?**
> A: Dropout randomly zeros activations during training to prevent co-adaptation, acting like training an ensemble of subnetworks. At inference you turn it off (`model.eval()`) and the framework scales activations so expectations match, forgetting `eval()` is a common bug.

> **Q: When would you use transfer learning?**
> A: When you have limited labeled data but a relevant large-scale pretrained model exists. Freeze or lightly fine-tune the pretrained backbone (general features) and train a new task-specific head. Often the difference between a model that works and one that doesn't.

## Mini-project: time-series forecaster in PyTorch, end to end

A direct match to real forecasting work: train an LSTM to forecast a noisy seasonal series, with proper train/val split, a real training loop, evaluation, and a plot of predictions vs. truth.

```python
import numpy as np, torch
import torch.nn as nn
import matplotlib.pyplot as plt

device = "cuda" if torch.cuda.is_available() else "cpu"
torch.manual_seed(0); np.random.seed(0)

# ---- 1. Synthetic series: trend + seasonality + noise ----
t = np.arange(0, 1000)
series = 0.01*t + np.sin(2*np.pi*t/50) + 0.5*np.sin(2*np.pi*t/13) \
         + np.random.normal(0, 0.2, len(t))

# ---- 2. Scale using TRAIN stats only (no leakage), then window ----
split = 800
mu, sd = series[:split].mean(), series[:split].std()
s = (series - mu) / sd

W = 50                                   # lookback window
def make_windows(arr, w):
    Xs, ys = [], []
    for i in range(len(arr) - w):
        Xs.append(arr[i:i+w]); ys.append(arr[i+w])
    return np.array(Xs), np.array(ys)

Xall, yall = make_windows(s, W)
train_n = split - W
X_train = torch.tensor(Xall[:train_n], dtype=torch.float32).unsqueeze(-1).to(device)
y_train = torch.tensor(yall[:train_n], dtype=torch.float32).unsqueeze(-1).to(device)
X_val   = torch.tensor(Xall[train_n:], dtype=torch.float32).unsqueeze(-1).to(device)
y_val   = torch.tensor(yall[train_n:], dtype=torch.float32).unsqueeze(-1).to(device)

# ---- 3. Model: LSTM -> linear head ----
class Forecaster(nn.Module):
    def __init__(self, hidden=64):
        super().__init__()
        self.lstm = nn.LSTM(input_size=1, hidden_size=hidden, batch_first=True)
        self.head = nn.Linear(hidden, 1)
    def forward(self, x):
        out, _ = self.lstm(x)            # (batch, seq, hidden)
        return self.head(out[:, -1, :])  # use last time step

model = Forecaster().to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.MSELoss()

# ---- 4. Training loop with train/val tracking + early stopping ----
batch = 64
best_val, patience, wait = float("inf"), 15, 0
train_hist, val_hist = [], []
for epoch in range(200):
    model.train()
    perm = torch.randperm(len(X_train))
    for i in range(0, len(X_train), batch):
        idx = perm[i:i+batch]
        opt.zero_grad()
        pred = model(X_train[idx])
        loss = loss_fn(pred, y_train[idx])
        loss.backward()
        opt.step()
    model.eval()
    with torch.no_grad():
        tr = loss_fn(model(X_train), y_train).item()
        vl = loss_fn(model(X_val), y_val).item()
    train_hist.append(tr); val_hist.append(vl)
    if vl < best_val:
        best_val, wait = vl, 0
        best_state = {k: v.clone() for k, v in model.state_dict().items()}
    else:
        wait += 1
        if wait >= patience:
            print(f"early stop @ epoch {epoch}"); break

model.load_state_dict(best_state)

# ---- 5. Evaluate (de-scale back to original units) ----
model.eval()
with torch.no_grad():
    val_pred = model(X_val).cpu().numpy().ravel() * sd + mu
val_true = (y_val.cpu().numpy().ravel()) * sd + mu
rmse = np.sqrt(np.mean((val_pred - val_true)**2))
mae  = np.mean(np.abs(val_pred - val_true))
print(f"Val RMSE {rmse:.3f}  MAE {mae:.3f}")

# ---- 6. Visualize: loss curves + forecast vs. truth ----
fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(13, 4))
ax1.plot(train_hist, label="train"); ax1.plot(val_hist, label="val")
ax1.set_title("Loss (gap = overfitting signal)"); ax1.legend()
ax2.plot(val_true, label="actual"); ax2.plot(val_pred, "--", label="forecast")
ax2.set_title("Validation forecast vs. truth"); ax2.legend()
plt.tight_layout(); plt.show()
```

**Decisions and why:**
- Scaling with **train-only** statistics, using the full series' mean/std leaks the future into training. Same anti-leakage discipline as 14.1.
- A **chronological** split (no shuffling across the time boundary), shuffling time series leaks future into past.
- **Windowing** turns the sequence into supervised `(lookback → next-value)` pairs the LSTM can train on.
- The explicit **train/val loop** with **early stopping** keeps the best-validation weights and stops before overfitting, and the loss curves let you *see* the bias-variance tradeoff happen.
- Evaluate in **original units** (RMSE/MAE after de-scaling) so the error is interpretable, and plot forecast vs. truth to inspect whether it captured the seasonality, not just the trend.

This is the same scaffolding for an image classifier, swap the LSTM for a CNN, MSELoss for cross-entropy, RMSE for accuracy/F1. The skeleton (device, loader, train/val loop, early stopping, eval, visualize) is universal.

## Mini-project 2: gradient-check your from-scratch backprop, then a CNN on MNIST

Two builds. First, the single most valuable debugging skill in deep learning, **numerical gradient checking**, which *proves* your hand-derived backprop is correct. Then a real CNN, the universal skeleton applied to images.

### Part A - verify backprop with numerical gradients

The idea: the definition of a derivative is `(J(w+ε) - J(w-ε)) / 2ε`. If your analytic gradient matches this finite-difference estimate, your backprop is correct. This is how you catch a sign error or a missing transpose that otherwise silently wrecks training.

```python
import numpy as np
rng = np.random.default_rng(0)

def sigmoid(z): return 1/(1+np.exp(-z))
def relu(z):    return np.maximum(0, z)
def d_relu(z):  return (z > 0).astype(float)

# Same 2->4->1 net as before, packed so we can perturb single weights
X = np.array([[0,0],[0,1],[1,0],[1,1]], dtype=float)
y = np.array([[0],[1],[1],[0]], dtype=float)
W1 = rng.normal(0, 0.5, (2,4)); b1 = np.zeros((1,4))
W2 = rng.normal(0, 0.5, (4,1)); b2 = np.zeros((1,1))

def forward_loss(W1,b1,W2,b2):
    a1 = relu(X@W1+b1); yhat = sigmoid(a1@W2+b2)
    eps = 1e-9
    return -np.mean(y*np.log(yhat+eps)+(1-y)*np.log(1-yhat+eps)), a1, yhat

# Analytic gradient for W2 (the formula we derived)
loss, a1, yhat = forward_loss(W1,b1,W2,b2)
m = X.shape[0]
d2 = (yhat - y) / m
dW2_analytic = a1.T @ d2

# Numerical gradient for W2 via central differences
eps = 1e-5
dW2_numeric = np.zeros_like(W2)
for i in range(W2.shape[0]):
    Wp = W2.copy(); Wp[i,0] += eps
    Wm = W2.copy(); Wm[i,0] -= eps
    Jp = forward_loss(W1,b1,Wp,b2)[0]
    Jm = forward_loss(W1,b1,Wm,b2)[0]
    dW2_numeric[i,0] = (Jp - Jm) / (2*eps)

rel_err = np.abs(dW2_analytic - dW2_numeric) / (np.abs(dW2_analytic)+np.abs(dW2_numeric)+1e-12)
print("max relative error:", rel_err.max())   # ~1e-7  -> backprop is correct
```

A relative error around `1e-7` means the analytic and numerical gradients agree to ~7 digits, the derivation is right. If you ever see `1e-2` or worse, you have a bug (wrong transpose, missing activation derivative, off-by-one). **Gradient checking is the unit test of deep learning math.**

### Part B - a CNN on MNIST (the universal skeleton, on images)

Same train/val/eval scaffold as the forecaster, swapping in a convolutional net and classification loss.

```python
import torch, torch.nn as nn
from torchvision import datasets, transforms
from torch.utils.data import DataLoader

device = "cuda" if torch.cuda.is_available() else "cpu"
tf = transforms.Compose([transforms.ToTensor(),
                         transforms.Normalize((0.1307,), (0.3081,))])  # MNIST stats
train_ds = datasets.MNIST(".", train=True,  download=True, transform=tf)
test_ds  = datasets.MNIST(".", train=False, download=True, transform=tf)
train_dl = DataLoader(train_ds, batch_size=128, shuffle=True)
test_dl  = DataLoader(test_ds,  batch_size=256)

class CNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2),  # 28->14
            nn.Conv2d(16, 32, 3, padding=1), nn.ReLU(), nn.MaxPool2d(2), # 14->7
        )
        self.head = nn.Sequential(nn.Flatten(), nn.Dropout(0.25),
                                  nn.Linear(32*7*7, 10))
    def forward(self, x):
        return self.head(self.features(x))   # raw logits

model = CNN().to(device)
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
loss_fn = nn.CrossEntropyLoss()              # takes logits, applies softmax inside

for epoch in range(3):
    model.train()
    for xb, yb in train_dl:
        xb, yb = xb.to(device), yb.to(device)
        opt.zero_grad()                       # <-- the bug-prone line
        loss = loss_fn(model(xb), yb)
        loss.backward()
        opt.step()
    # eval
    model.eval(); correct = 0
    with torch.no_grad():
        for xb, yb in test_dl:
            xb, yb = xb.to(device), yb.to(device)
            correct += (model(xb).argmax(1) == yb).sum().item()
    print(f"epoch {epoch}  test acc {correct/len(test_ds):.4f}")  # ~0.99 by epoch 3
```

Three epochs reach ~99% on MNIST. Note every habit from the chapter: `zero_grad` each step, raw logits into `CrossEntropyLoss`, `model.eval()` + `no_grad()` for evaluation, normalized inputs, dropout for regularization. **It's the exact same skeleton as the forecaster**, only the data, architecture, and metric changed. That transferability is the payoff of learning the mechanism instead of memorizing recipes.

## Exercises

1. **(Easy)** Why can't a single neuron solve XOR? Give the one-sentence geometric reason.
2. **(Easy)** Compute `ReLU(-3)`, `ReLU(0)`, `ReLU(2.5)`, and their derivatives.
3. **(Easy)** A two-layer net has input dim 4, hidden dim 16, output dim 3. How many weight parameters (ignore biases)? How many biases?
4. **(Medium)** Forward pass by hand: `x=[1,0]`, `W¹=[[0.2,0.4]]` (one hidden neuron, weights on the two inputs), `b¹=0.1`, ReLU; output `W²=0.5`, `b²=-0.2`, sigmoid. Compute `z¹, a¹, z², ŷ`.
5. **(Medium)** For the net in Q4 with label `y=1`, compute `δ²`, `∂J/∂W²`, and `δ¹`.
6. **(Medium)** You train a net and the loss is `nan` after a few steps. List three likely causes and the fix for each.
7. **(Medium)** Explain in one paragraph why stacking linear layers with no activation is pointless, using a 2-layer example.
8. **(Hard)** Derive the gradient of softmax + cross-entropy and show it reduces to `ŷ - y` (the same clean form as sigmoid + BCE).
9. **(Hard)** Your CNN gets 99% train accuracy but 80% validation accuracy. Name the problem and give four concrete remedies, tying each to bias-variance.
10. **(Hard / conceptual)** Compare an LSTM and a Transformer for forecasting a series with both short daily cycles and a yearly cycle. Which captures the long-range dependency more directly, and why?

### Solutions

1. A single neuron defines one hyperplane (a straight decision boundary); XOR's two classes can't be separated by any single straight line, so no setting of one neuron's weights solves it.

2. `ReLU(-3)=0` (deriv 0), `ReLU(0)=0` (deriv undefined at 0; convention 0), `ReLU(2.5)=2.5` (deriv 1).

3. Weights: layer1 `4·16 = 64`, layer2 `16·3 = 48`, total **112**. Biases: `16 + 3 = 19`.

4. `z¹ = 0.2·1 + 0.4·0 + 0.1 = 0.3`; `a¹ = ReLU(0.3) = 0.3`. `z² = 0.5·0.3 + (-0.2) = 0.15 - 0.2 = -0.05`; `ŷ = σ(-0.05) = 1/(1+e^{0.05}) ≈ 0.4875`.

5. `δ² = ŷ - y = 0.4875 - 1 = -0.5125`. `∂J/∂W² = δ²·a¹ = -0.5125·0.3 ≈ -0.1538`. `δ¹ = (W²·δ²)·ReLU'(z¹) = (0.5·-0.5125)·1 = -0.2563` (ReLU'=1 since `z¹=0.3>0`).

6. Causes & fixes: **(a) learning rate too high** → loss diverges to inf/nan; lower the LR. **(b) `log(0)` in the loss** → add an epsilon or use the logits-based loss (`BCEWithLogitsLoss`/`CrossEntropyLoss`). **(c) exploding gradients** (deep/recurrent nets) → gradient clipping (`clip_grad_norm_`), better init, or normalization. (Also: division by a zero/near-zero, or unnormalized inputs.)

7. With identity activation, layer 2 computes `W²(W¹x + b¹) + b² = (W²W¹)x + (W²b¹ + b²)`. The product `W²W¹` is just some matrix `W'` and the bias term is just some vector `b'`, so the whole two-layer stack equals a single linear map `W'x + b'`. No amount of stacking adds expressive power without a nonlinearity between layers, the network can still only draw straight boundaries.

8. Softmax: `ŷ_k = e^{z_k}/Σ_j e^{z_j}`. Cross-entropy with one-hot `y`: `J = -Σ_k y_k log ŷ_k`. Then `∂J/∂z_i = Σ_k (∂J/∂ŷ_k)(∂ŷ_k/∂z_i)`. Using `∂ŷ_k/∂z_i = ŷ_k(δ_{ki} - ŷ_i)` and `∂J/∂ŷ_k = -y_k/ŷ_k`: `∂J/∂z_i = -Σ_k (y_k/ŷ_k)·ŷ_k(δ_{ki}-ŷ_i) = -Σ_k y_k(δ_{ki}-ŷ_i) = -y_i + ŷ_i Σ_k y_k = ŷ_i - y_i` (since `Σ_k y_k = 1`). So `∂J/∂z = ŷ - y`. ✓ Same clean form, the softmax-CE pairing is the multiclass analog of sigmoid-BCE.

9. **Overfitting (high variance)**, large train/val gap. Remedies: **(a)** more training data or data augmentation (directly lowers variance); **(b)** stronger regularization, dropout / weight decay (constrains the model, trading a little bias for less variance); **(c)** early stopping (halts before the model fits noise); **(d)** a smaller / shallower model (less capacity → less variance, more bias). Each slides the model back toward the bias-variance sweet spot from the high-variance side.

10. The **Transformer** captures the long-range (yearly) dependency more directly. Self-attention lets the forecast position attend to a point ~365 steps back in a *single* step (`QKᵀ` directly scores any pair), with no distance-based gradient decay. An LSTM must carry that information through 365 sequential recurrent steps in its hidden state, where it tends to fade (vanishing-gradient-in-time) and competes with the strong short daily cycle. The LSTM handles the short cycle fine; the long cycle is where attention's direct, parallel access wins, which is why Transformer forecasters (Informer, Temporal Fusion Transformer) became popular for long-horizon, multi-seasonal series.
