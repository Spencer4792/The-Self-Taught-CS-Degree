# Chapter 4.3 - Web Scraping & Talking to APIs

> Goal: Get comfortable pulling data off the internet the right way: understand HTTP from the client side (methods, headers, status codes, auth), call real REST APIs with `requests`, read API docs, handle pagination/rate limits/retries politely, parse HTML with BeautifulSoup when there's no API, and know the difference (technical and ethical) between "use the API" and "scrape." By the end you should be able to build a cached API-to-report tool and a polite static-site scraper without flailing.

Half the useful automation you'll want to write lives on the other side of an HTTP request: weather, GitHub stats, a price on a webpage, a public dataset. Maybe you've used `requests.get()` before, but superficially, without really understanding status codes, headers, or what "rate limit" and "backoff" mean in code. And scraping can feel vaguely sketchy until you know the actual rules (robots.txt, terms of service). This chapter covers both the mechanics and the responsibilities.

---

## Start here - the internet is just letters in the mail

Strip away the buzzwords and the web is simple: your program writes a letter (a **request**), drops it in the mailbox, and a server writes a letter back (a **response**). Every API call, every webpage load, every "fetch some data" is that one exchange repeated.

A request letter has four parts, and the postal analogy makes them stick:
- **Method**: what you're asking for. `GET` = "please send me a copy" (reading). `POST` = "here's something new, please file it" (submitting).
- **URL**: the address on the envelope, sometimes with notes in the margin (`?q=cats&page=2`, the **query string**).
- **Headers**: the fine print, who you are (`User-Agent`), your ID badge (`Authorization`), what format you'd like back (`Accept`).
- **Body**: the actual contents you're mailing (usually only for `POST`/`PUT`).

The reply letter comes back with a **status code**, a three-digit verdict that amounts to the mood of the response. `200` = "here you go!" `404` = "no such thing." `429` = "whoa, slow down." `500` = "I broke, not your fault." Learn the families (2xx good, 4xx your fault, 5xx their fault) and you can read any API's behavior.

Why this matters: an enormous amount of real-world value sits behind HTTP, including weather, stock prices, maps, payments, and every SaaS product. Once you're comfortable sending requests and reading responses, you can wire any of those into your own tools. There are two ways to get data off the web:

1. **An API**: the front door the site built for programs. Clean, documented, stable, allowed. Always prefer this.
2. **Scraping**: reading the HTML meant for human eyes and picking out the data yourself. The side door. Use it only when there's no API, and use it politely (this chapter spends real time on the ethics, because doing this carelessly gets you blocked or into legal trouble).

A mindset to carry through the whole chapter: **you are a guest on someone else's server.** Identify yourself honestly, don't knock on the door 10,000 times a second, and leave if asked. Polite code is also robust code: the same habits that are courteous (timeouts, retries, backoff) are what keep your script from crashing.

## Concept 1 - HTTP from the client side

Every web request is the same shape. The client (you) sends a **request**; the server sends back a **response**. Understanding the parts is 90% of using any API.

**A request has:**
- a **method** (verb): `GET` (read), `POST` (create/submit), `PUT`/`PATCH` (update), `DELETE` (remove).
- a **URL**, optionally with a **query string**: `https://api.example.com/search?q=cats&page=2`.
- **headers**: metadata like `Authorization`, `User-Agent`, `Accept`, `Content-Type`.
- optionally a **body** (for POST/PUT): often JSON.

**A response has:**
- a **status code** (the 3-digit verdict),
- **headers** (e.g. `Content-Type`, rate-limit info),
- a **body** (HTML, JSON, an image, …).

### Status codes - memorize the families

```
1xx  informational (rare in app code)
2xx  SUCCESS         200 OK, 201 Created, 204 No Content
3xx  redirect        301 Moved Permanently, 304 Not Modified
4xx  YOU messed up   400 Bad Request, 401 Unauthorized, 403 Forbidden,
                     404 Not Found, 429 Too Many Requests  <- rate limited!
5xx  SERVER messed up 500 Internal Error, 502 Bad Gateway, 503 Unavailable
```

The rule of thumb: 4xx means fix your request; 5xx means retry later (maybe). `429` specifically means "you're going too fast, slow down."

## Build it - `requests` end to end

`requests` is the de-facto HTTP client (`pip install requests`). It hides socket details but exposes everything above cleanly.

```python
import requests

# --- GET with query params (requests builds the ?key=val string for me, URL-encoding safely) ---
resp = requests.get(
    "https://httpbin.org/get",
    params={"q": "python", "page": 2},     # -> ...?q=python&page=2
    headers={"User-Agent": "spencer-learning-bot/1.0"},
    timeout=10,                            # ALWAYS set a timeout; never hang forever
)

print(resp.status_code)        # 200
print(resp.url)                # the fully-built URL with encoded params
print(resp.headers["Content-Type"])
data = resp.json()             # parse JSON body -> dict (raises if not JSON)
print(data["args"])            # {'q': 'python', 'page': '2'}

# --- Check for errors explicitly ---
resp.raise_for_status()        # raises requests.HTTPError on 4xx/5xx; no-op on 2xx

# --- POST a JSON body ---
resp = requests.post(
    "https://httpbin.org/post",
    json={"name": "Spencer", "active": True},   # json= sets Content-Type and serializes for me
    timeout=10,
)
print(resp.json()["json"])     # the server echoes back what I sent
```

### Auth headers

Most APIs authenticate via a header, usually a bearer token or an API key.

```python
import os
TOKEN = os.environ["GITHUB_TOKEN"]      # secrets from env, never hard-coded (Chapter 4.2!)

headers = {
    "Authorization": f"Bearer {TOKEN}",     # bearer-token style
    "Accept": "application/vnd.github+json", # tell the server which representation I want
}
resp = requests.get("https://api.github.com/user", headers=headers, timeout=10)

# Some APIs use a key as a query param or a custom header instead:
# requests.get(url, params={"api_key": KEY})
# requests.get(url, headers={"X-API-Key": KEY})
```

### Sessions - reuse connection + headers

For multiple calls to the same host, a `Session` reuses the TCP connection (faster) and lets you set headers once.

```python
with requests.Session() as s:
    s.headers.update({"Authorization": f"Bearer {TOKEN}", "User-Agent": "spencer-bot/1.0"})
    a = s.get("https://api.github.com/user", timeout=10)
    b = s.get("https://api.github.com/user/repos", timeout=10)
```

## Concept 2 - Reading API docs

When you hit a new API, look for these specific things, in order:

1. **Base URL**, e.g. `https://api.github.com`.
2. **Auth**, token? API key? where does it go (header vs. query)? how do you get one?
3. **Endpoints**, the paths and methods (`GET /users/{username}/repos`).
4. **Parameters**, required vs. optional, query vs. path vs. body.
5. **Response shape**, what JSON fields come back (so you know what to extract).
6. **Pagination**, how do you get page 2? (`?page=`, a `next` URL, a cursor token?)
7. **Rate limits**, how many requests per hour/minute? which headers report your remaining quota?
8. **Errors**, what do failures look like?

A 10-minute read of these saves an hour of guessing. The response shape and pagination style are the two to check first, because they shape your code the most.

## Concept 3 - Pagination & rate limits (be polite)

APIs cap how much they return per call. **Pagination** is how you walk through all of it. Common styles:

```python
# Style 1: page numbers
#   GET /items?page=1&per_page=100 ... until an empty page or a known total
def fetch_all_pages(session, url, params=None):
    params = dict(params or {})
    params.setdefault("per_page", 100)
    page = 1
    while True:
        params["page"] = page
        r = session.get(url, params=params, timeout=10)
        r.raise_for_status()
        batch = r.json()
        if not batch:                  # empty list -> we're done
            break
        yield from batch
        page += 1

# Style 2: "next" link (GitHub puts it in the Link header / response body)
def fetch_by_next_link(session, url):
    while url:
        r = session.get(url, timeout=10)
        r.raise_for_status()
        yield from r.json()
        url = r.links.get("next", {}).get("url")   # requests parses the Link header for me
```

### Rate limits & being polite

Servers cost money. Hammering them is rude (and gets you blocked). The politeness checklist:

- **Honor the limit.** Many APIs send headers like `X-RateLimit-Remaining` and `X-RateLimit-Reset`. Read them.
- **Throttle proactively.** A tiny `time.sleep()` between requests prevents `429`s.
- **Identify yourself.** A descriptive `User-Agent` (with contact info for serious scraping) is courteous and sometimes required.
- **Back off on `429`/`503`.** Respect the `Retry-After` header if present.

```python
import time, requests

def polite_get(session, url, **kwargs):
    """GET with retry + exponential backoff that respects 429/503 and Retry-After."""
    delay = 1.0
    for attempt in range(5):
        r = session.get(url, timeout=10, **kwargs)
        if r.status_code in (429, 503):
            wait = float(r.headers.get("Retry-After", delay))   # server's suggestion wins
            print(f"rate limited; sleeping {wait}s")
            time.sleep(wait)
            delay *= 2                                           # exponential backoff
            continue
        r.raise_for_status()
        # Proactively check remaining quota:
        remaining = r.headers.get("X-RateLimit-Remaining")
        if remaining is not None and int(remaining) < 5:
            time.sleep(2)                                        # slow down before we're blocked
        return r
    raise RuntimeError(f"giving up on {url} after retries")
```

**Exponential backoff** (1s, 2s, 4s, 8s…) is the standard pattern: each retry waits longer, so a struggling server gets breathing room instead of a stampede. Add a little random **jitter** in real systems to avoid all clients retrying in lockstep (the "thundering herd").

## Concept 4 - When to use an API vs. scrape, and the ethics/legality

**Always prefer an API.** An API is a contract: stable fields, documented, allowed. Scraping HTML is fragile (it breaks when the site's markup changes) and legally and ethically grayer. Only scrape when there's no API and the data is actually public.

### robots.txt

`https://site.com/robots.txt` tells bots which paths the site asks them not to crawl. It's not a law, but honoring it is the baseline of good citizenship, and ignoring it is evidence of bad faith if there's ever a dispute.

```python
import urllib.robotparser

rp = urllib.robotparser.RobotFileParser()
rp.set_url("https://example.com/robots.txt")
rp.read()
print(rp.can_fetch("spencer-bot/1.0", "https://example.com/some/page"))   # True/False
```

### An ethics/legality checklist before scraping

- Is there an **API or data download** you should use instead? (Usually yes.)
- Does **robots.txt** disallow this path? Honor it.
- Do the site's **Terms of Service** forbid automated access? Don't ignore them.
- Are you collecting **personal data**? Privacy laws (GDPR/CCPA) may apply. Be very careful.
- Are you **respecting rate limits** and not degrading the site for real users?
- Are you **identifying** your bot honestly via `User-Agent`?
- Are you scraping **copyrighted content** to republish? That's a legal problem, not just an etiquette one.

Treat scraping like being a guest in someone's house: take only what's offered, don't make a mess, and leave if asked. When in doubt, ask for permission or use the official channel.

## Build it - parsing HTML with BeautifulSoup

When there's no API, you parse HTML. **Do not** use regex for HTML: it's nested and irregular, and regex chokes on it. Use a real parser. `BeautifulSoup` (`pip install beautifulsoup4 lxml`) builds a navigable tree.

```python
from bs4 import BeautifulSoup
import requests

html = requests.get("https://example.com", timeout=10).text
soup = BeautifulSoup(html, "html.parser")    # or "lxml" for speed (needs the lxml package)

# --- Find one element ---
title = soup.find("h1")                       # first <h1>
print(title.get_text(strip=True))             # its text, trimmed

# --- Find many ---
for a in soup.find_all("a"):
    print(a.get("href"), "->", a.get_text(strip=True))

# --- CSS selectors (often the cleanest) ---
soup.select("div.article")                    # <div class="article">
soup.select("ul#menu > li")                   # direct children li of ul#menu
soup.select_one("a.button")                   # first match
prices = [el.get_text(strip=True) for el in soup.select("span.price")]

# --- Navigate the tree ---
first_link = soup.find("a")
print(first_link.parent.name)                 # enclosing tag
print(first_link.attrs)                       # dict of attributes
```

A good workflow: open the page in a browser, use "Inspect Element" to find the tag/class/id wrapping the data you want, then translate that into a `select()` call. CSS selectors map directly to what you see in DevTools, so they make a good default over `find_all`.

## Concept 5 - Browser automation with Playwright (for JS-heavy pages)

`requests` + BeautifulSoup only see the initial HTML. Modern sites render content with JavaScript after load, so the data you want may not be in `resp.text` at all. When that happens, you need a real browser. **Playwright** (`pip install playwright; playwright install`) drives a headless Chromium/Firefox/WebKit, runs the JS, and hands you the final DOM.

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)   # no visible window
    page = browser.new_page()
    page.goto("https://quotes.toscrape.com/js/", wait_until="networkidle")
    page.wait_for_selector(".quote")             # wait until JS has rendered the content

    quotes = page.query_selector_all(".quote")
    for q in quotes:
        text = q.query_selector(".text").inner_text()
        author = q.query_selector(".author").inner_text()
        print(f"{author}: {text}")

    browser.close()
```

Reach for it only when the data isn't in the raw HTML. Check by printing `resp.text` first; if the value is there, BeautifulSoup is lighter and faster. Playwright is heavier (it spins up a browser) but can also click, scroll, fill forms, and wait for elements: the things a human does. The same politeness and ethics rules apply, doubly so since a browser looks more like a real user.

## Mini-project A - GitHub API → cached report

> Goal: Pull a user's public repos from the GitHub REST API, cache the raw response to disk (so re-runs don't hammer the API), and produce a small text report: total repos, total stars, top languages, and the 5 most-starred projects.

### Design

1. Read a token from the environment (optional, raises the rate limit from 60 to 5000/hr).
2. Use a `Session` with auth + `User-Agent` headers.
3. Fetch all repos via pagination (`fetch_all_pages`).
4. **Cache**: save raw JSON to `cache/<user>.json` with a timestamp; reuse if it's fresh (< 1 hour old) to be polite and fast.
5. Aggregate with `Counter` and print a report.

### Full code

```python
#!/usr/bin/env python3
"""github_report.py - fetch a user's repos (cached) and print a summary.

Usage:
    export GITHUB_TOKEN=ghp_xxx        # optional but recommended
    python github_report.py octocat
"""
from __future__ import annotations

import json
import os
import sys
import time
from collections import Counter
from pathlib import Path

import requests

API = "https://api.github.com"
CACHE_DIR = Path("cache")
CACHE_TTL = 3600                       # seconds; reuse cache younger than this


def make_session() -> requests.Session:
    s = requests.Session()
    s.headers.update({
        "Accept": "application/vnd.github+json",
        "User-Agent": "spencer-github-report/1.0",
    })
    token = os.environ.get("GITHUB_TOKEN")
    if token:
        s.headers["Authorization"] = f"Bearer {token}"
    return s


def fetch_all_pages(session: requests.Session, url: str):
    """Follow GitHub's Link-header pagination, yielding each item."""
    params = {"per_page": 100, "page": 1}
    while True:
        r = session.get(url, params=params, timeout=15)
        if r.status_code == 403 and r.headers.get("X-RateLimit-Remaining") == "0":
            reset = int(r.headers.get("X-RateLimit-Reset", time.time() + 60))
            wait = max(0, reset - int(time.time())) + 1
            print(f"Rate limit hit; sleeping {wait}s (tip: set GITHUB_TOKEN)")
            time.sleep(wait)
            continue
        r.raise_for_status()
        batch = r.json()
        if not batch:
            break
        yield from batch
        if "next" not in r.links:      # requests parsed the Link header for me
            break
        params["page"] += 1


def get_repos(user: str) -> list[dict]:
    """Return repos, using a fresh disk cache when available."""
    CACHE_DIR.mkdir(exist_ok=True)
    cache_file = CACHE_DIR / f"{user}.json"

    if cache_file.exists() and (time.time() - cache_file.stat().st_mtime) < CACHE_TTL:
        print(f"(using cached data for {user})")
        return json.loads(cache_file.read_text(encoding="utf-8"))

    print(f"(fetching fresh data for {user})")
    session = make_session()
    repos = list(fetch_all_pages(session, f"{API}/users/{user}/repos"))
    cache_file.write_text(json.dumps(repos), encoding="utf-8")
    return repos


def report(user: str, repos: list[dict]) -> None:
    if not repos:
        print(f"No public repos for {user}.")
        return

    total_stars = sum(r["stargazers_count"] for r in repos)
    total_forks = sum(r["forks_count"] for r in repos)
    languages = Counter(r["language"] for r in repos if r["language"])
    top = sorted(repos, key=lambda r: r["stargazers_count"], reverse=True)[:5]

    print(f"\n=== Report for {user} ===")
    print(f"Public repos : {len(repos)}")
    print(f"Total stars  : {total_stars:,}")
    print(f"Total forks  : {total_forks:,}")

    print("\nTop languages:")
    for lang, count in languages.most_common(5):
        print(f"  {lang:<14} {count} repo(s)")

    print("\nMost-starred repositories:")
    for r in top:
        print(f"  ★ {r['stargazers_count']:>5}  {r['name']}")
        if r.get("description"):
            print(f"          {r['description'][:70]}")


def main() -> None:
    if len(sys.argv) != 2:
        sys.exit("Usage: python github_report.py <username>")
    user = sys.argv[1]
    report(user, get_repos(user))


if __name__ == "__main__":
    main()
```

### How to run

```bash
export GITHUB_TOKEN=ghp_your_token_here     # optional; raises rate limit 60 -> 5000/hr
python github_report.py octocat
python github_report.py octocat             # 2nd run uses the cache (no API call)
```

### What to notice
- **Caching** is the core of the design, both polite and practical: a re-run within an hour makes zero API calls. The cache is just JSON on disk keyed by username, with freshness from the file's mtime (Chapter 4.2).
- The code handles GitHub's specific rate-limit signal (`403` + `X-RateLimit-Remaining: 0`) by sleeping until `X-RateLimit-Reset`.
- Secrets come from `os.environ`, never the source.

### Extend it
- Add `--refresh` to bypass the cache.
- Render the report as Markdown or HTML.
- Swap GitHub for a weather API (`https://api.open-meteo.com` is free, no key) and report a 7-day forecast.

## Mini-project B - a polite static-site scraper

> Goal: Scrape quotes and authors from `quotes.toscrape.com` (a site built for practicing scraping, so it's explicitly allowed). Follow pagination, throttle requests, set a real User-Agent, check robots.txt, and save results to CSV.

### Full code

```python
#!/usr/bin/env python3
"""scrape_quotes.py - polite scraper for quotes.toscrape.com -> quotes.csv

Demonstrates: robots.txt check, throttling, pagination, BeautifulSoup parsing, CSV output.
"""
from __future__ import annotations

import csv
import time
import urllib.robotparser
from pathlib import Path

import requests
from bs4 import BeautifulSoup

BASE = "https://quotes.toscrape.com"
USER_AGENT = "spencer-learning-scraper/1.0 (educational; contact: me@example.com)"
DELAY = 1.0                       # seconds between requests - be gentle


def allowed(url: str) -> bool:
    rp = urllib.robotparser.RobotFileParser()
    rp.set_url(f"{BASE}/robots.txt")
    try:
        rp.read()
    except Exception:
        return True               # if robots.txt is unreachable, proceed cautiously
    return rp.can_fetch(USER_AGENT, url)


def scrape() -> list[dict]:
    session = requests.Session()
    session.headers["User-Agent"] = USER_AGENT

    results: list[dict] = []
    url = f"{BASE}/page/1/"

    while url:
        if not allowed(url):
            print(f"robots.txt disallows {url}; stopping.")
            break

        print(f"GET {url}")
        resp = session.get(url, timeout=10)
        resp.raise_for_status()
        soup = BeautifulSoup(resp.text, "html.parser")

        for quote in soup.select("div.quote"):
            results.append({
                "text": quote.select_one("span.text").get_text(strip=True),
                "author": quote.select_one("small.author").get_text(strip=True),
                "tags": ",".join(t.get_text(strip=True) for t in quote.select("a.tag")),
            })

        # Pagination: find the "Next" link, build the absolute URL
        next_link = soup.select_one("li.next > a")
        url = f"{BASE}{next_link['href']}" if next_link else None

        time.sleep(DELAY)         # THROTTLE - the single most important politeness move

    return results


def save_csv(rows: list[dict], path: Path) -> None:
    with path.open("w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=["text", "author", "tags"])
        writer.writeheader()
        writer.writerows(rows)


def main() -> None:
    rows = scrape()
    out = Path("quotes.csv")
    save_csv(rows, out)
    print(f"\nSaved {len(rows)} quotes to {out}")
    authors = {r['author'] for r in rows}
    print(f"Unique authors: {len(authors)}")


if __name__ == "__main__":
    main()
```

### How to run

```bash
pip install requests beautifulsoup4
python scrape_quotes.py
```

### What to notice
- The scraper checks robots.txt before each page, throttles with `time.sleep(DELAY)`, and sends an honest User-Agent with contact info: the three pillars of polite scraping.
- Pagination is "find the Next link, follow it until there isn't one," the HTML equivalent of the API's `next` URL.
- Output is CSV (Chapter 4.2), ready for a spreadsheet or the next pipeline stage.

### Extend it
- Add a JS-heavy variant using Playwright against `quotes.toscrape.com/js/`.
- De-duplicate quotes; track which run first saw each one.
- Wrap requests in the `@retry`-with-backoff decorator from Chapter 4.1.

## Mini-project C - a weather CLI on a free, no-key API

> Goal: A command-line weather tool using **Open-Meteo**, a free API that needs no key and no signup, so there's nothing to set up. It looks up a city by name (geocoding), fetches the current conditions plus a short forecast, and prints a readable summary. It makes a good first real API client, reinforcing query params, JSON parsing, error handling, and reading docs.

Open-Meteo has two endpoints we chain: one turns a city name into coordinates, the other turns coordinates into weather.

```python
#!/usr/bin/env python3
"""weather.py - current weather + forecast for any city. No API key needed.

Usage:
    python weather.py "Salt Lake City"
    python weather.py Tokyo
    python weather.py "Paris" --days 3
"""
from __future__ import annotations

import argparse
import sys

import requests

GEO_API = "https://geocoding-api.open-meteo.com/v1/search"
FORECAST_API = "https://api.open-meteo.com/v1/forecast"

# Open-Meteo's WMO weather codes -> human text (a tiny excerpt of the table from their docs).
WEATHER_CODES = {
    0: "Clear sky", 1: "Mainly clear", 2: "Partly cloudy", 3: "Overcast",
    45: "Fog", 51: "Light drizzle", 61: "Light rain", 63: "Rain", 65: "Heavy rain",
    71: "Light snow", 73: "Snow", 75: "Heavy snow", 80: "Rain showers",
    95: "Thunderstorm", 96: "Thunderstorm w/ hail",
}


def geocode(city: str) -> tuple[float, float, str]:
    """City name -> (latitude, longitude, pretty name). Raises if not found."""
    r = requests.get(GEO_API, params={"name": city, "count": 1}, timeout=10)
    r.raise_for_status()
    results = r.json().get("results")
    if not results:
        raise SystemExit(f"Couldn't find a place called {city!r}.")
    top = results[0]
    pretty = ", ".join(filter(None, [top.get("name"), top.get("admin1"), top.get("country")]))
    return top["latitude"], top["longitude"], pretty


def get_weather(lat: float, lon: float, days: int) -> dict:
    r = requests.get(FORECAST_API, params={
        "latitude": lat, "longitude": lon,
        "current_weather": True,
        "daily": "temperature_2m_max,temperature_2m_min,weathercode",
        "forecast_days": days,
        "timezone": "auto",
    }, timeout=10)
    r.raise_for_status()
    return r.json()


def describe(code: int) -> str:
    return WEATHER_CODES.get(code, f"code {code}")


def main() -> None:
    ap = argparse.ArgumentParser(description="Weather for a city (no API key).")
    ap.add_argument("city", help="city name, e.g. 'New York'")
    ap.add_argument("--days", type=int, default=4, help="forecast days (1-7)")
    args = ap.parse_args()

    try:
        lat, lon, name = geocode(args.city)
        data = get_weather(lat, lon, max(1, min(args.days, 7)))
    except requests.RequestException as e:
        sys.exit(f"Network error: {e}")

    now = data["current_weather"]
    print(f"\n  {name}")
    print(f"  Now: {now['temperature']:.0f}°C, {describe(now['weathercode'])}, "
          f"wind {now['windspeed']:.0f} km/h\n")

    daily = data["daily"]
    print("  Forecast:")
    for date, hi, lo, code in zip(daily["time"], daily["temperature_2m_max"],
                                  daily["temperature_2m_min"], daily["weathercode"]):
        print(f"    {date}   {lo:>4.0f}°-{hi:<4.0f}°C   {describe(code)}")
    print()


if __name__ == "__main__":
    main()
```

What to notice:
- **No auth, no signup.** Open-Meteo is an ideal API to practice on: you get to focus on the mechanics (params, JSON, errors) without key management.
- **Chaining two endpoints** (geocode → forecast) is common in real APIs; one call's output feeds the next call's input.
- The code parses the documented response shape (`results`, `current_weather`, `daily`), exactly the "read the docs for the JSON fields" skill from Concept 2.
- `zip()` walks the parallel arrays Open-Meteo returns (dates, highs, lows, and codes line up by index), a clean idiom for column-oriented JSON.
- Real error handling: a city that doesn't exist exits cleanly; a network failure is caught as `requests.RequestException`.

## Common mistakes

- **No `timeout=`.** Without it, a stalled server hangs your script forever. Always pass `timeout=` to every request. This is the most common rookie omission.
- **Assuming `200` means success without checking.** Some APIs return `200` with an error in the body, and any request can return `4xx`/`5xx`. Call `resp.raise_for_status()` (or check `resp.ok`) before trusting the data.
- **Calling `.json()` on a non-JSON response.** An HTML error page or empty body makes `.json()` raise. Guard it, or check `resp.headers["Content-Type"]` first.
- **Hard-coding API keys in source.** They leak into git history forever. Load from `os.environ` / a git-ignored `.env` (Chapter 4.2). Reviewers treat this as a security incident.
- **Hammering an API with no throttle.** A tight loop of requests earns you a `429` and possibly a ban. Add `time.sleep()` between calls and back off on `429`/`503`.
- **Ignoring pagination.** You get page 1, see 100 items, and assume that's everything. Check for `next` links / page params or you'll silently process a fraction of the data.
- **Parsing HTML with regex.** It's nested and irregular; regex breaks on it. Use BeautifulSoup.
- **Brittle scraper selectors.** Pinning to auto-generated class names (`css-1x7y9z`) breaks the moment the site rebuilds. Prefer stable attributes (`id`, `data-*`, semantic tags) and fail loudly when a selector finds nothing.
- **Reaching for Playwright too early.** It's heavy. First print `resp.text`; if your data is already in the raw HTML, plain requests + BeautifulSoup is faster and simpler.
- **Scraping without checking robots.txt / ToS.** Skipping the ethics check is how you end up blocked or in a legal dispute.

## On the job / interview angle

- **"Integrate with a third-party API" is a near-universal task.** Payments (Stripe), email (SendGrid), maps, auth (OAuth), internal microservices: backend and full-stack work is full of HTTP clients. The exact skills here (auth headers, pagination, retries/backoff, reading docs) are what you'll do in week one.
- **Resilience patterns are senior signals.** Timeouts, exponential backoff with jitter, idempotent retries, and respecting `Retry-After` are the difference between a script and a production integration. Interviewers ask: "Your API call fails intermittently. What do you do?" The answer is retry with backoff, but only on retryable status codes (429/5xx), not on 4xx.
- **Status-code fluency gets tested.** "What's the difference between 401 and 403?" (unauthenticated vs. authenticated-but-not-allowed). "What does 429 mean and how do you handle it?" Know these cold.
- **Caching shows maturity.** The "cache to disk, reuse if fresh" pattern (Project A) demonstrates you think about cost, politeness, and speed, not just correctness.
- **Data roles do a lot of "API → dataframe."** Pulling paginated JSON from an API into pandas for analysis is a core data-analyst/scientist workflow.
- **The ethics knowledge is a differentiator.** Being able to say "I check robots.txt, throttle, identify my bot, and prefer the official API" signals professionalism and keeps the company out of trouble. Scraping carelessly is a real legal/PR risk that companies care about.
- **Reading API docs fast is an underrated skill.** In an interview take-home, the people who finish are the ones who quickly find the base URL, auth, endpoints, and pagination style instead of guessing.

Portfolio tip: a small tool that calls a real API, caches responses, handles rate limits, and outputs a report (Project A or the weather CLI) is a great talking point: it shows end-to-end competence on exactly what you'll do at work.

```python
def all_repos(user):
    url = f"https://api.github.com/users/{user}/repos"
```

**7.**
```python
import time, requests
def get_with_retry(url, max_tries=4):
    delay = 1.0
    for attempt in range(1, max_tries + 1):
        r = requests.get(url, timeout=10)
        if r.status_code in (429, 500, 502, 503, 504):
            if attempt == max_tries:
                break
            wait = float(r.headers.get("Retry-After", delay))
            print(f"got {r.status_code}; sleeping {wait}s")
            time.sleep(wait)
            delay *= 2
            continue
        r.raise_for_status()
        return r
    raise RuntimeError(f"gave up on {url} after {max_tries} tries")
```

```python
import time, requests
def check(urls):
    results = []
    for url in urls:
        start = time.perf_counter()
        try:
            r = requests.get(url, timeout=10)
            ms = (time.perf_counter() - start) * 1000
            results.append((url, r.status_code, ms))
        except requests.RequestException as e:
            results.append((url, f"ERR {e.__class__.__name__}", float("inf")))
    results.sort(key=lambda t: t[2], reverse=True)   # slowest first
    print(f"{'URL':<35}{'STATUS':<12}{'MS':>8}")
    for url, status, ms in results:
        shown = "n/a" if ms == float("inf") else f"{ms:.0f}"
        print(f"{url:<35}{str(status):<12}{shown:>8}")

check(["https://httpbin.org/get", "https://api.github.com",
       "https://example.com", "https://httpbin.org/delay/2"])
```
