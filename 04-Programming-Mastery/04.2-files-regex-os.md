## Concept 1 - Files: text vs. binary, and the buffer underneath

A file on disk is just a sequence of **bytes**. The OS gives you a stream; Python wraps it in a file object. The first decision is **text mode vs. binary mode**, because that decides whether Python decodes bytes into `str` for you.

- **Text mode** (`"r"`, `"w"`, `"a"`): Python reads bytes and decodes them into a `str` using an encoding (default UTF-8 on modern systems). It also translates line endings (`\r\n` ↔ `\n`). You get strings.
- **Binary mode** (`"rb"`, `"wb"`, `"ab"`): no decoding, no newline translation. You get raw `bytes`. Use this for images, PDFs, anything non-text, or when you need exact bytes.

```python
# TEXT: read a whole file into one string
with open("notes.txt", "r", encoding="utf-8") as f:
    text = f.read()

# TEXT: iterate line by line (lazy - doesn't load the whole file)
with open("notes.txt", encoding="utf-8") as f:
    for line in f:                 # `line` includes the trailing "\n"
        print(line.rstrip("\n"))

# BINARY: read raw bytes
with open("photo.jpg", "rb") as f:
    header = f.read(4)            # first 4 bytes
    print(header)                # e.g. b'\xff\xd8\xff\xe0' for a JPEG
```

### Why `with` (context managers) for files

`open()` grabs an OS resource (a file descriptor). If you forget to `close()`, you leak descriptors, and on Windows the file stays locked. `with` guarantees `close()` runs even if the body raises — it's the `__enter__`/`__exit__` protocol from Chapter 4.1 in its most common use.

```python
# DON'T:
f = open("x.txt")
data = f.read()      # if this raises, f is never closed
f.close()

# DO:
with open("x.txt", encoding="utf-8") as f:
    data = f.read()  # f.close() is guaranteed on exit, exception or not
```

### Writing, appending, and `"x"`

```python
with open("out.txt", "w", encoding="utf-8") as f:   # "w" TRUNCATES (wipes) the file first!
    f.write("line one\n")
    f.writelines(["line two\n", "line three\n"])    # note: writelines adds NO newlines itself

with open("out.txt", "a", encoding="utf-8") as f:   # "a" appends to the end
    f.write("appended\n")

# "x" -> exclusive create: raises FileExistsError if it already exists (no accidental clobber)
try:
    with open("once.txt", "x") as f:
        f.write("only written if new")
except FileExistsError:
    print("already there")
```

**Always pass `encoding="utf-8"` in text mode.** The default depends on the platform's locale, which can burn you with mojibake (garbled characters) when a file written on one machine is read on another.

## Concept 2 - `pathlib`: modern path handling

For years, people built paths with string concatenation (`dir + "/" + name`) and `os.path.join`. `pathlib` (Python 3.4+) is the modern, object-oriented way and it's strictly better: paths are objects with methods, and the `/` operator joins them in an OS-correct way.

```python
from pathlib import Path

p = Path("data") / "logs" / "app.log"   # builds data/logs/app.log on Unix, data\logs\app.log on Windows
print(p.name)        # 'app.log'        (filename)
print(p.stem)        # 'app'            (name without suffix)
print(p.suffix)      # '.log'           (extension, with the dot)
print(p.parent)      # PosixPath('data/logs')
print(p.parts)       # ('data', 'logs', 'app.log')

home = Path.home()             # user's home directory
here = Path.cwd()              # current working directory
print(p.absolute())            # resolve relative to cwd
print((home / "x").expanduser())  # expand ~ if present
```

### Reading/writing/inspecting with `pathlib`

```python
p = Path("notes.txt")
p.write_text("hello\nworld\n", encoding="utf-8")   # one-shot write (opens+writes+closes)
print(p.read_text(encoding="utf-8"))                # one-shot read
p.write_bytes(b"\x00\x01\x02")                      # binary one-shot

print(p.exists())     # True/False
print(p.is_file())    # is it a regular file?
print(p.is_dir())     # is it a directory?
print(p.stat().st_size)        # size in bytes
import datetime
print(datetime.datetime.fromtimestamp(p.stat().st_mtime))  # last-modified time

Path("new/nested/dir").mkdir(parents=True, exist_ok=True)  # mkdir -p, no error if it exists
# p.rename("renamed.txt")      # move/rename
# p.unlink(missing_ok=True)    # delete a file (missing_ok avoids error if gone)
```

### Globbing - finding files by pattern

```python
root = Path(".")
for py in root.glob("*.py"):            # non-recursive: just this directory
    print(py)

for py in root.rglob("*.py"):           # recursive: this dir and ALL subdirectories
    print(py)

# glob patterns: * (any chars), ? (one char), ** (recurse), [abc] (char set)
images = list(root.rglob("*.[jp][pn]g"))   # crude match for .jpg/.png
```

Adopt `pathlib` as your default. The only time you still need `os.path` is when interoperating with old code that expects strings (and even then, `str(path)` converts cleanly).

## Concept 3 - Structured data: CSV and JSON

### CSV

CSV looks trivial ("just split on commas") but isn't: fields can contain commas, quotes, and newlines inside quotes. The `csv` module handles all the quoting rules; never hand-roll a CSV parser.

```python
import csv

# Reading rows as lists
with open("people.csv", newline="", encoding="utf-8") as f:   # newline="" is REQUIRED on the csv module
    reader = csv.reader(f)
    header = next(reader)            # first row
    for row in reader:
        print(row)                   # ['Alice', '30', 'NYC']

# Reading rows as dicts (keyed by header) - usually what I want
with open("people.csv", newline="", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        print(row["name"], row["age"])

# Writing
rows = [{"name": "Bob", "age": 25}, {"name": "Cara", "age": 40}]
with open("out.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "age"])
    writer.writeheader()
    writer.writerows(rows)
```

That `newline=""` is non-obvious: the `csv` module does its *own* newline handling, so you must stop the file object from also translating newlines, or you get blank rows on Windows.

### JSON

JSON is the lingua franca of APIs and config. The `json` module maps cleanly to Python types: object↔dict, array↔list, string↔str, number↔int/float, true/false/null↔True/False/None.

```python
import json

data = {"name": "Spencer", "skills": ["python", "sql"], "active": True, "level": None}

# Python object -> JSON string
s = json.dumps(data, indent=2, sort_keys=True)   # indent=2 for pretty-printing
print(s)

# JSON string -> Python object
back = json.loads(s)
print(back["skills"][0])     # 'python'

# Straight to/from files
with open("config.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)          # dump (no s) writes to a file

with open("config.json", encoding="utf-8") as f:
    cfg = json.load(f)                    # load (no s) reads from a file
```

These four are easy to mix up. The "s" suffix means "string": `dumps`/`loads` work with strings, `dump`/`load` work with files.

## Concept 4 - The OS: `os`, environment variables, and `subprocess`

### `os` and environment variables

```python
import os

print(os.getcwd())                  # current working directory
os.makedirs("a/b/c", exist_ok=True) # (pathlib's mkdir(parents=True) is nicer, but this exists)

# Environment variables - how config and SECRETS reach a program
print(os.environ.get("HOME"))                    # read; returns None if missing
api_key = os.environ.get("API_KEY", "default")   # with a fallback
os.environ["MY_VAR"] = "value"                    # set for this process and its children
```

### Secrets handling - the right way

**Never hard-code secrets (API keys, passwords, tokens) in source.** They end up in git history forever. The standard pattern is environment variables, often loaded from a `.env` file that is git-ignored.

```python
# .env   (add this filename to .gitignore!)
# API_KEY=sk-12345
# DB_PASSWORD=hunter2

# Load it with python-dotenv (pip install python-dotenv)
from dotenv import load_dotenv
import os

load_dotenv()                                  # reads .env into os.environ
api_key = os.environ["API_KEY"]                # KeyError if missing -> fail loudly, good
db_pw = os.getenv("DB_PASSWORD")               # None if missing -> handle gracefully

if not api_key:
    raise RuntimeError("API_KEY not set - copy .env.example to .env and fill it in")
```

The rules: (1) secrets live in env vars / `.env`, never in code; (2) `.env` is git-ignored, but you commit a `.env.example` with blank values as documentation; (3) for production, the platform (CI, cloud) injects real env vars.

### `subprocess` - running shell commands safely

Sometimes you need to shell out (run `git`, `ffmpeg`, `ls`). The modern tool is `subprocess.run`. The single most important safety rule: **pass arguments as a list, and avoid `shell=True`**, otherwise a filename like `"; rm -rf ~"` becomes a shell-injection vulnerability.

```python
import subprocess

# SAFE: arguments as a list -> no shell parsing, no injection
result = subprocess.run(
    ["git", "status", "--short"],
    capture_output=True,    # grab stdout/stderr
    text=True,              # decode bytes -> str (instead of raw bytes)
    check=True,             # raise CalledProcessError if exit code != 0
)
print("stdout:", result.stdout)
print("exit code:", result.returncode)

# Passing a variable safely - it's just a list element, never interpreted by a shell
filename = "; rm -rf ~"         # malicious-looking, but harmless here
subprocess.run(["echo", filename], text=True)   # prints the literal string

# DANGEROUS - do NOT do this with untrusted input:
# subprocess.run(f"echo {filename}", shell=True)   # the ; would execute rm -rf ~ !!
```

Handling failure:

```python
try:
    subprocess.run(["false"], check=True)        # `false` always exits 1
except subprocess.CalledProcessError as e:
    print(f"command failed with code {e.returncode}")
```

So: list-of-args + `text=True` + `check=True` is your default incantation, and `shell=True` is a code smell to avoid unless you genuinely need shell features on fully-trusted input.

## Concept 5 - Regular expressions, from the engine up

A regex is a pattern that describes a set of strings. The **regex engine** is a little state machine that scans the input left to right, trying to match the pattern and **backtracking** when a path fails. "Left to right, with backtracking" explains almost every weird regex behavior, especially greedy vs. lazy.

We'll use Python's `re` module. Always use raw strings (`r"..."`) for patterns, so backslashes go to the regex engine instead of being eaten by Python's own string escaping.

### The building blocks

**Literals** match themselves: `r"cat"` matches the text `cat`.

**Character classes** match one character from a set:

```
.           any character except newline
\d  \D      a digit (0-9)        /  a NON-digit
\w  \W      word char [A-Za-z0-9_]  /  a non-word char
\s  \S      whitespace           /  non-whitespace
[abc]       one of a, b, or c
[a-z]       one char in range a-z
[^abc]      one char that is NOT a, b, or c (^ inside [] means negate)
```

**Quantifiers** say how many of the preceding thing:

```
*       0 or more
+       1 or more
?       0 or 1 (optional)
{3}     exactly 3
{2,5}   between 2 and 5
{2,}    2 or more
```

**Anchors** match positions, not characters:

```
^       start of string (or line, with re.MULTILINE)
$       end of string (or line)
\b      word boundary (between \w and non-\w)
```

**Groups** `( ... )` capture a sub-match and let quantifiers apply to a chunk:

```
(abc)+         one or more "abc"
(\d{4})-(\d{2})  two captured groups
(?:abc)        non-capturing group (group for quantifying, don't capture)
(?P<year>\d{4}) named group -> access by name "year"
```

**Alternation** `|` means "or": `r"cat|dog"` matches `cat` or `dog`.

### The `re` module API

```python
import re

text = "Order 12345 shipped on 2026-06-26 to zip 90210."

re.search(r"\d+", text)            # first match anywhere -> Match object (or None)
re.match(r"\d+", text)             # match only at the START of the string
re.findall(r"\d+", text)           # ALL matches as a list -> ['12345','2026','06','26','90210']
re.finditer(r"\d+", text)          # ALL matches as Match objects (lazy iterator)
re.sub(r"\d+", "#", text)          # replace all matches -> "Order # shipped on #-#-# to zip #."
re.split(r"\s+", text)             # split on the pattern

m = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)   # the date
if m:
    print(m.group(0))    # '2026-06-26'  (whole match)
    print(m.group(1))    # '2026'        (first group)
    print(m.groups())    # ('2026', '06', '26')
```

### Named groups + compiling

For anything you'll reuse, compile the pattern once and name the groups so the code reads like prose:

```python
DATE = re.compile(r"(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})")
m = DATE.search(text)
print(m.group("year"))         # '2026'
print(m.groupdict())           # {'year': '2026', 'month': '06', 'day': '26'}
```

### Greedy vs. lazy - the #1 regex confusion

By default quantifiers are **greedy**: they match as much as possible, then backtrack only if forced. Adding `?` makes them **lazy** (also called non-greedy): match as little as possible.

```python
html = "<b>bold</b> and <i>italic</i>"

re.findall(r"<.*>", html)     # GREEDY: ['<b>bold</b> and <i>italic</i>']  -- ONE giant match!
re.findall(r"<.*?>", html)    # LAZY:   ['<b>', '</b>', '<i>', '</i>']     -- each tag
```

Why? Greedy `.*` grabs the whole rest of the string, then backtracks character by character until it finds the final `>`, so it spans from the first `<` to the last `>`. Lazy `.*?` matches the minimum, expanding only until the next `>` is found. Knowing this, you reach for `*?`/`+?` whenever you want "up to the next delimiter."

### Lookahead and lookbehind - match based on context without consuming it

```python
# Positive lookahead (?=...) : "followed by" but don't include it in the match
re.findall(r"\d+(?= dollars)", "5 dollars and 10 cents")    # ['5'] - only the number before " dollars"

# Negative lookahead (?!...) : "NOT followed by"
re.findall(r"\d+(?! cents)", "5 dollars and 10 cents")      # ['5', '1'] (tricky - try it!)

# Positive lookbehind (?<=...) : "preceded by"
re.findall(r"(?<=\$)\d+", "price $42 vs €30")               # ['42'] - number after a $

# Password check: at least one digit AND at least one uppercase, 8+ chars
strong = re.compile(r"^(?=.*\d)(?=.*[A-Z]).{8,}$")
print(bool(strong.match("Passw0rd")))   # True
print(bool(strong.match("password")))   # False (no digit, no uppercase)
```

Lookarounds are **zero-width**: they assert a condition about the surrounding text but don't consume characters, so you can stack several at one position (like the password rule above checking two conditions at the start).

### Worked patterns you'll actually reuse

```python
EMAIL  = re.compile(r"[\w.+-]+@[\w-]+\.[\w.-]+")
IPV4   = re.compile(r"\b(?:\d{1,3}\.){3}\d{1,3}\b")
URL    = re.compile(r"https?://[^\s)>\"]+")
PRICE  = re.compile(r"\$\d+(?:\.\d{2})?")            # $5 or $5.00
PHONE  = re.compile(r"\(?\d{3}\)?[-.\s]?\d{3}[-.\s]?\d{4}")   # (555) 123-4567, 555.123.4567, etc.
HEXCOL = re.compile(r"#[0-9a-fA-F]{6}\b")           # #aabbcc
```

One caveat: regex is for recognizing patterns in flat text, not for parsing recursive or nested structures. Parsing HTML or JSON with regex is a trap; use `BeautifulSoup` or the `json` module. Regex shines on log lines, IDs, dates, and simple field extraction.

## Build it - walking a directory tree

To organize files you first need to find them. Two ways: `pathlib.Path.rglob` (clean, modern) and `os.walk` (older, gives directories and files separately at each level).

```python
from pathlib import Path
import os

root = Path(".")

# Modern: every file under root, recursively
for path in root.rglob("*"):
    if path.is_file():
        print(path, path.stat().st_size)

# Classic os.walk: yields (current_dir, subdir_names, file_names) for each level
for dirpath, dirnames, filenames in os.walk("."):
    # I can prune: skip hidden dirs by mutating dirnames in place
    dirnames[:] = [d for d in dirnames if not d.startswith(".")]
    for name in filenames:
        full = Path(dirpath) / name
        print(full)
```

The `dirnames[:] = [...]` trick is worth remembering: `os.walk` lets you edit the list it's about to descend into, so you can skip `.git`, `node_modules`, etc. `rglob` can't prune like that, so for big trees with junk dirs, `os.walk` wins.

## Mini-project A - the Downloads folder organizer

> Goal: Sort a messy folder into subfolders by file type, and optionally by year-month, moving each file into the right bucket. Dry-run by default so you never destroy data by accident.

### Design

1. Define category → extensions mapping (Images, Documents, Audio, Video, Archives, Code, Other).
2. Walk the target folder (top level only, don't recurse into already-organized subfolders).
3. For each file, pick its category by extension, and a date bucket from its modified time.
4. Compute the destination, handle name collisions, and move it, but only if `--apply` is passed (otherwise just print what *would* happen).

### Full code

```python
#!/usr/bin/env python3
"""organize.py - sort a messy folder by file type (and optionally by date).

Usage:
    python organize.py ~/Downloads            # DRY RUN: prints planned moves
    python organize.py ~/Downloads --apply    # actually move files
    python organize.py ~/Downloads --by-date --apply
"""
from __future__ import annotations

import argparse
import shutil
from datetime import datetime
from pathlib import Path

# extension (lowercase, with dot) -> category folder name
CATEGORIES: dict[str, str] = {}
def _register(folder: str, *exts: str) -> None:
    for e in exts:
        CATEGORIES[e] = folder

_register("Images", ".jpg", ".jpeg", ".png", ".gif", ".webp", ".heic", ".svg", ".bmp")
_register("Documents", ".pdf", ".doc", ".docx", ".txt", ".md", ".rtf", ".odt")
_register("Spreadsheets", ".csv", ".xls", ".xlsx", ".ods")
_register("Audio", ".mp3", ".wav", ".flac", ".m4a", ".aac")
_register("Video", ".mp4", ".mov", ".mkv", ".avi", ".webm")
_register("Archives", ".zip", ".tar", ".gz", ".tgz", ".rar", ".7z")
_register("Code", ".py", ".js", ".ts", ".java", ".c", ".cpp", ".rs", ".go", ".sh")
_register("Installers", ".dmg", ".pkg", ".exe", ".msi", ".deb")


def category_for(path: Path) -> str:
    return CATEGORIES.get(path.suffix.lower(), "Other")


def date_bucket(path: Path) -> str:
    """Return 'YYYY-MM' from the file's last-modified time."""
    ts = path.stat().st_mtime
    return datetime.fromtimestamp(ts).strftime("%Y-%m")


def unique_destination(dest: Path) -> Path:
    """If dest exists, append ' (1)', ' (2)', ... before the suffix."""
    if not dest.exists():
        return dest
    stem, suffix, parent = dest.stem, dest.suffix, dest.parent
    n = 1
    while True:
        candidate = parent / f"{stem} ({n}){suffix}"
        if not candidate.exists():
            return candidate
        n += 1


def organize(target: Path, apply: bool, by_date: bool) -> None:
    if not target.is_dir():
        raise SystemExit(f"Not a directory: {target}")

    moves: list[tuple[Path, Path]] = []
    for item in target.iterdir():           # top level only - don't recurse
        if item.is_dir() or item.name.startswith("."):
            continue                         # skip folders and hidden files
        category = category_for(item)
        dest_dir = target / category
        if by_date:
            dest_dir = dest_dir / date_bucket(item)
        dest = unique_destination(dest_dir / item.name)
        moves.append((item, dest))

    if not moves:
        print("Nothing to organize.")
        return

    for src, dest in moves:
        rel = dest.relative_to(target)
        if apply:
            dest.parent.mkdir(parents=True, exist_ok=True)
            shutil.move(str(src), str(dest))
            print(f"MOVED  {src.name}  ->  {rel}")
        else:
            print(f"PLAN   {src.name}  ->  {rel}")

    verb = "Moved" if apply else "Would move"
    print(f"\n{verb} {len(moves)} file(s). " + ("" if apply else "Re-run with --apply to do it."))


def main() -> None:
    parser = argparse.ArgumentParser(description="Organize a folder by file type.")
    parser.add_argument("folder", type=Path, help="folder to organize")
    parser.add_argument("--apply", action="store_true", help="actually move files (default: dry run)")
    parser.add_argument("--by-date", action="store_true", help="also bucket into YYYY-MM subfolders")
    args = parser.parse_args()
    organize(args.folder.expanduser(), apply=args.apply, by_date=args.by_date)


if __name__ == "__main__":
    main()
```

### How to run

```bash
python organize.py ~/Downloads                 # safe preview
python organize.py ~/Downloads --by-date --apply
```

The dry-run-by-default design is deliberate: you want destructive tools to show you their plan first. `argparse` gives you a real CLI with `--help` for free.

### Extend it
- Add a `--undo` that reads a log of moves and reverses them.
- Hash files and detect/quarantine duplicates instead of renaming.
- Add a config file (JSON) for custom category mappings.

## Mini-project B - a log-file parser with regex

> Goal: Take a web-server-style access log and extract structured records (IP, timestamp, method, path, status, bytes), then report top IPs, error counts, and the noisiest paths. This ties together file iteration, regex with named groups, and `collections.Counter`.

### Sample log format (Common Log Format-ish)

```
192.168.1.10 - - [26/Jun/2026:10:15:32 +0000] "GET /index.html HTTP/1.1" 200 1043
10.0.0.5 - - [26/Jun/2026:10:15:33 +0000] "POST /api/login HTTP/1.1" 401 12
```

### Full code

```python
#!/usr/bin/env python3
"""logparse.py - extract structured data from access logs and summarize.

Usage:
    python logparse.py access.log
"""
from __future__ import annotations

import re
import sys
from collections import Counter
from dataclasses import dataclass
from pathlib import Path

# One compiled pattern with named groups -> each field is self-documenting.
LINE = re.compile(
    r'(?P<ip>\d{1,3}(?:\.\d{1,3}){3})'        # 192.168.1.10
    r'\s+\S+\s+\S+\s+'                          # the "- -" identity fields (ignored)
    r'\[(?P<time>[^\]]+)\]\s+'                  # [26/Jun/2026:10:15:32 +0000]
    r'"(?P<method>[A-Z]+)\s+(?P<path>\S+)\s+[^"]+"\s+'  # "GET /index.html HTTP/1.1"
    r'(?P<status>\d{3})\s+'                     # 200
    r'(?P<bytes>\d+|-)'                         # 1043  (or '-' when unknown)
)


@dataclass
class Entry:
    ip: str
    time: str
    method: str
    path: str
    status: int
    size: int


def parse_line(line: str) -> Entry | None:
    m = LINE.search(line)
    if not m:
        return None                            # malformed line -> skip
    g = m.groupdict()
    size = 0 if g["bytes"] == "-" else int(g["bytes"])
    return Entry(g["ip"], g["time"], g["method"], g["path"], int(g["status"]), size)


def parse_file(path: Path):
    """Generator pipeline: yields Entry objects, lazily, line by line."""
    with path.open(encoding="utf-8", errors="replace") as f:
        for line in f:
            entry = parse_line(line)
            if entry is not None:
                yield entry


def report(path: Path) -> None:
    ips = Counter()
    statuses = Counter()
    paths = Counter()
    total_bytes = 0
    n = 0
    errors = []                                # collect 4xx/5xx lines

    for e in parse_file(path):
        n += 1
        ips[e.ip] += 1
        statuses[e.status] += 1
        paths[e.path] += 1
        total_bytes += e.size
        if e.status >= 400:
            errors.append(e)

    print(f"Parsed {n} log entries from {path}\n")

    print("Top 5 IPs:")
    for ip, count in ips.most_common(5):
        print(f"  {ip:<16} {count}")

    print("\nStatus code breakdown:")
    for status, count in sorted(statuses.items()):
        print(f"  {status}: {count}")

    print("\nTop 5 paths:")
    for p, count in paths.most_common(5):
        print(f"  {p:<24} {count}")

    print(f"\nTotal bytes served: {total_bytes:,}")
    print(f"Error responses (>=400): {len(errors)}")
    for e in errors[:10]:
        print(f"  {e.status} {e.method} {e.path} from {e.ip}")


def main() -> None:
    if len(sys.argv) != 2:
        sys.exit("Usage: python logparse.py <access.log>")
    report(Path(sys.argv[1]))


if __name__ == "__main__":
    main()
```

## Mini-project C - a duplicate-file finder (automate something annoying)

> Goal: Scan a folder tree and find files that are byte-for-byte identical, even if they have different names (`invoice.pdf` vs `invoice (1).pdf`). Group the duplicates, report wasted space, and optionally delete all but one copy. Dry-run by default. This is the kind of script that quietly reclaims gigabytes from a Downloads folder.

The trick: two files with the same contents have the same **hash** (a short fingerprint computed from the bytes). Comparing fingerprints is fast and reliable; comparing full contents directly would be slow. We bucket by size first (a cheap pre-filter — files of different sizes can't be identical), then hash contents only for files that share a size.

```python
#!/usr/bin/env python3
"""dedupe.py - find (and optionally remove) duplicate files by content.

Usage:
    python dedupe.py ~/Downloads             # dry run: report duplicates
    python dedupe.py ~/Downloads --delete    # keep one of each, delete the rest
"""
from __future__ import annotations

import argparse
import hashlib
from collections import defaultdict
from pathlib import Path


def file_hash(path: Path, chunk: int = 65536) -> str:
    """SHA-256 of a file, read in chunks so huge files don't blow up memory."""
    h = hashlib.sha256()
    with path.open("rb") as f:                 # binary mode: we want raw bytes
        while block := f.read(chunk):          # walrus := assigns and tests in one go
            h.update(block)
    return h.hexdigest()


def find_duplicates(root: Path) -> dict[str, list[Path]]:
    # Step 1: bucket files by SIZE (cheap). Only same-size files can be identical.
    by_size: dict[int, list[Path]] = defaultdict(list)
    for p in root.rglob("*"):
        if p.is_file():
            by_size[p.stat().st_size].append(p)

    # Step 2: within each size bucket of 2+, hash contents to confirm.
    by_hash: dict[str, list[Path]] = defaultdict(list)
    for size, paths in by_size.items():
        if len(paths) < 2:
            continue                            # unique size -> can't be a dup
        for p in paths:
            by_hash[file_hash(p)].append(p)

    # Keep only hashes with real duplicates.
    return {h: ps for h, ps in by_hash.items() if len(ps) > 1}


def main() -> None:
    ap = argparse.ArgumentParser(description="Find duplicate files by content.")
    ap.add_argument("folder", type=Path)
    ap.add_argument("--delete", action="store_true",
                    help="delete all but the first copy of each duplicate set")
    args = ap.parse_args()

    dups = find_duplicates(args.folder.expanduser())
    if not dups:
        print("No duplicates found.")
        return

    wasted = 0
    for h, paths in dups.items():
        paths.sort()                            # deterministic "keeper" = first
        keeper, extras = paths[0], paths[1:]
        size = keeper.stat().st_size
        wasted += size * len(extras)
        print(f"\nDuplicate set ({len(paths)} copies, {size:,} bytes each):")
        print(f"  KEEP   {keeper}")
        for extra in extras:
            if args.delete:
                extra.unlink()
                print(f"  DELETED {extra}")
            else:
                print(f"  dup    {extra}")

    verb = "Reclaimed" if args.delete else "Could reclaim"
    print(f"\n{verb} {wasted:,} bytes "
          + ("" if args.delete else "(re-run with --delete to do it)."))


if __name__ == "__main__":
    main()
```

Run it:

```bash
python dedupe.py ~/Downloads            # safe preview
python dedupe.py ~/Downloads --delete   # actually free the space
```

What to notice:
- Binary mode plus chunked reading (`open("rb")`, `f.read(chunk)`) hashes a 4 GB video without loading it into RAM — the streaming lesson from Chapter 4.1 applied to bytes.
- The size pre-filter is a real performance pattern: avoid expensive work (hashing) by ruling things out with a cheap check first.
- `while block := f.read(chunk):` uses the **walrus operator** (`:=`) to read-and-test in one line; the loop ends when `read` returns empty `bytes`.
- Dry-run by default, because a delete tool that doesn't show its plan first is a foot-gun.

### Extend it
- Print a progress bar for large trees (`tqdm`), since hashing is the slow part.
- Add `--hardlink` to replace duplicates with hard links instead of deleting (saves space, keeps every path working).
- Skip files under a size threshold (`--min-size`) so you don't churn on tiny files.

## Common mistakes

- **Forgetting `encoding="utf-8"` in text mode.** The default depends on the OS locale, so a file written on a Mac can come back as garbled "mojibake" on Windows. Always be explicit.
- **Forgetting `newline=""` with the `csv` module.** Without it, you get blank rows between every line on Windows, because the csv module and the file object both translate newlines. The rule: `open(path, newline="", encoding="utf-8")` for all CSV I/O.
- **Mixing up `dump`/`load` vs `dumps`/`loads`.** The `s` means string: `dumps`/`loads` work with strings; `dump`/`load` work with file objects. Passing a filename where a file object is expected raises a confusing error.
- **Opening with `"w"` when you meant `"a"`.** `"w"` truncates: it wipes the file the instant you open it, before you write a byte. Use `"a"` to append, `"x"` to create-only-if-new.
- **Building paths with string `+` and hardcoded `/`.** Breaks on Windows and mangles edge cases. Use `pathlib` and the `/` operator.
- **`shell=True` with untrusted input.** A filename like `"; rm -rf ~"` becomes a shell command. Pass arguments as a list and leave `shell=False` (the default).
- **Not using a raw string for regex.** `"\d"` may get eaten by Python's own escaping before the regex engine sees it. Always `r"\d"`.
- **Greedy `.*` when you wanted "up to the next delimiter."** `<.*>` swallows everything between the first `<` and the *last* `>`. Use the lazy `<.*?>`.
- **Using regex to parse HTML or JSON.** They're nested/recursive; regex can't reliably handle that. Use `BeautifulSoup` / the `json` module.
- **Catching `FileNotFoundError` too late, or not at all.** Decide up front whether a missing file is fatal or recoverable, and handle it explicitly (`try/except` or `path.exists()`).
