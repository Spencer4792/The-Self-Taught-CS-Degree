## Start here (the gentle on-ramp)

Imagine a coin-operated turnstile at a subway. It has exactly two states: **Locked** and **Unlocked**. Two things can happen to it: you **push** the arm, or you **insert a coin**. When it's Locked and you push, nothing happens (still Locked). When it's Locked and you insert a coin, it unlocks. When it's Unlocked and you push, you walk through and it relocks. That's the *entire* machine. It has no memory of how many coins you've inserted over your lifetime, no counter, no notion of "earlier today." It only knows *which of two states it's in right now*, and a fixed rule for how each input flips that state.

That turnstile is a **finite automaton**. It's the simplest interesting model of computation: a finite set of states, and a transition rule that, given the current state and the next input symbol, tells you the next state. The whole field called the **theory of computation** is built on a stack of machines like this, ordered by power. The turnstile sits at the bottom. As we add capabilities, a stack, then an unbounded tape, the machines climb a ladder until, at the top, we reach the **Turing machine**, which captures *everything* that can be computed at all (that's next chapter, [23.2](23.2-computability-and-complexity.md)).

Why bother climbing a ladder of toy machines? Because each rung answers a precise, *permanent* question: **"What problems can a machine with exactly this much memory solve?"** These are answers about the *kind* of problem, not about a fast laptop versus a slow one. A finite automaton, no matter how many states you give it, *physically cannot* count to an arbitrary depth and check balance: it can't tell whether `(((...)))` is balanced. This isn't a matter of speed: it *can't*, ever, and we'll **prove** it. That's the shock and the joy of this subject: we get theorems that say "no machine of this class will ever do this," the way physics says "no engine beats the Carnot limit."

The map for this chapter, the bottom of the **Chomsky hierarchy**:

| Rung | Language class | Machine that recognizes it | What it can do |
|---|---|---|---|
| 3 | **Regular** | Finite automaton (DFA/NFA) = regex | Fixed finite memory. Pattern matching. |
| 2 | **Context-free** | Pushdown automaton (one stack) | Nesting / balance. Parsing. |
| 1 | Context-sensitive | Linear-bounded automaton | (mentioned, not our focus) |
| 0 | Recursively enumerable | **Turing machine** (next chapter) | Everything computable. |

We live on rungs 3 and 2 here. Rung 3 (regular) is the world of `grep`, lexical tokenizing, and regex. Rung 2 (context-free) is the world of programming-language *grammars* and parsers, the front end of every compiler ([Part 24](../24-Compilers/24.1-lexing-parsing-asts.md)). By the end you'll see that "regex" and "finite automaton" are *literally the same thing wearing different clothes," and that the reason a regex can't match balanced parentheses is the same reason a turnstile can't count.

This chapter is where you stop treating regex and parsers as black boxes someone else built. We're going to derive them from first principles and *implement the machines*, a DFA simulator, the NFA→DFA construction, regex→NFA, and a from-scratch regex engine, so the theory is never abstract for more than a page.

## Languages, alphabets, and strings - the vocabulary

Before machines, the objects they chew on. This is just careful naming.

- An **alphabet** `Σ` is a finite, non-empty set of **symbols**. E.g. `Σ = {0, 1}` or `Σ = {a, b}` or the set of ASCII characters.
- A **string** (or word) over `Σ` is a finite sequence of symbols from `Σ`. E.g. `0110`, `aab`. The **empty string** is written `ε` (length 0).
- `Σ*` ("Σ star") is the set of *all* strings over `Σ`, including `ε`. It's infinite. E.g. over `{0,1}`: `ε, 0, 1, 00, 01, 10, 11, 000, …`.
- A **language** `L` over `Σ` is *any* subset of `Σ*`, a (possibly infinite) set of strings. "The language of binary strings with an even number of 1s" is a language. "The set of all valid Python programs" is a language.

That last definition is the core idea: **a computational problem is a language.** "Decide whether a string is in L" = "recognize the language L." A machine *recognizes* (or *accepts*) a language L if it says "yes" exactly on the strings in L and "no" on the rest. So asking "what can this machine compute?" becomes the sharp question "**which languages can it recognize?**" Different machine classes recognize different families of languages, that's the Chomsky hierarchy.

A bit of notation we'll reuse:
- **Concatenation** of strings: `x·y` (or `xy`) glues them. `01 · 10 = 0110`. The identity is `ε` (`εx = xε = x`).
- **Concatenation of languages**: `L₁L₂ = { xy : x ∈ L₁, y ∈ L₂ }`.
- **Kleene star of a language**: `L* = {ε} ∪ L ∪ LL ∪ LLL ∪ …`, zero or more strings from L glued together. (`Σ*` is exactly this with L = Σ.)

These three operations, union, concatenation, star, will turn out to be *exactly* what regular expressions are built from. Hold that thought.

## Deterministic Finite Automata (DFA) - the formal 5-tuple

A DFA is the turnstile, made precise. Formally a DFA is a **5-tuple** `M = (Q, Σ, δ, q₀, F)` where:

- `Q`, a finite set of **states**.
- `Σ`, the input **alphabet**.
- `δ : Q × Σ → Q`, the **transition function**. Given a state and a symbol, it returns *exactly one* next state. ("Deterministic" = exactly one; no choice, no ambiguity.)
- `q₀ ∈ Q`, the **start state**.
- `F ⊆ Q`, the set of **accept (final) states**.

**How it runs.** Start in `q₀`. Read the input string one symbol at a time, each time replacing the current state with `δ(current, symbol)`. After consuming the whole string, look at where you landed: if it's in `F`, **accept**; otherwise **reject**. The set of all strings the DFA accepts is `L(M)`, the **language of M**. Any language equal to `L(M)` for some DFA is called a **regular language**.

We extend `δ` to whole strings with the **extended transition function** `δ̂ : Q × Σ* → Q`:

```
δ̂(q, ε)   = q                       (empty string: stay put)
δ̂(q, x·a) = δ( δ̂(q, x), a )         (process x, then take one more step on a)
```

Then crisply: `M` **accepts** `w` iff `δ̂(q₀, w) ∈ F`.

### A worked DFA: "binary strings with an even number of 1s"

Let `L = { w ∈ {0,1}* : w has an even number of 1s }`. Two states are enough, we only need to remember the *parity* of 1s seen so far, not the count (that's the key insight: finite memory tracks a finite fact).

- `Q = {even, odd}`
- `Σ = {0, 1}`
- `q₀ = even` (zero 1s so far is even)
- `F = {even}`
- δ: reading a `0` never changes parity; reading a `1` flips it.

```
        0          1
even  → even      → odd
odd   → odd       → even
```

State diagram (states are circles, the accept state is a double circle, arrows are transitions):

```
        0                 1
      ┌───┐             ┌────┐
      ▼   │             ▼    │
   ((even)) ──1──▶  ( odd )
      ▲                  │
      └──────1───────────┘
   (0 self-loops on both states)
```

On `0110`: even →0→ even →1→ odd →1→ even →0→ even. Land in `even ∈ F` ⇒ **accept** (two 1s, even ✓). On `010`: even →0→ even →1→ odd →0→ odd. Land in `odd ∉ F` ⇒ **reject** (one 1, odd ✓).

Notice what made two states enough: the *only* thing about the past that affects the future is the parity. Everything else about the history is irrelevant and can be forgotten. **A DFA can recognize L iff "what matters about the prefix read so far" takes only finitely many distinct values.** (That intuition is formalized by the Myhill-Nerode theorem, equivalence classes of prefixes, which we'll mention but not prove in full.)

## Build it - a DFA simulator

Let's make the 5-tuple executable: a DFA is literally a data structure plus a `for` loop.

```python
from dataclasses import dataclass, field

@dataclass
class DFA:
    states: set                 # Q
    alphabet: set               # Σ
    transition: dict            # δ as {(state, symbol): state}
    start: object               # q0
    accept: set                 # F

    def accepts(self, w: str) -> bool:
        """Run the DFA on string w; return True iff it ends in an accept state."""
        state = self.start
        for symbol in w:
            if symbol not in self.alphabet:
                raise ValueError(f"symbol {symbol!r} not in alphabet")
            key = (state, symbol)
            if key not in self.transition:
                # No transition defined => implicit dead state => reject.
                return False
            state = self.transition[key]          # δ(state, symbol)
        return state in self.accept               # δ̂(q0, w) ∈ F ?

# The "even number of 1s" DFA:
even_ones = DFA(
    states={"even", "odd"},
    alphabet={"0", "1"},
    transition={
        ("even", "0"): "even", ("even", "1"): "odd",
        ("odd",  "0"): "odd",  ("odd",  "1"): "even",
    },
    start="even",
    accept={"even"},
)

for w in ["", "0", "1", "11", "0110", "010", "1010101"]:
    print(f"{w!r:12} -> {even_ones.accepts(w)}")
```

Output:

```
''           -> True      # zero 1s, even
'0'          -> True      # zero 1s, even
'1'          -> False     # one 1, odd
'11'         -> True      # two 1s, even
'0110'       -> True      # two 1s, even
'010'        -> False     # one 1, odd
'1010101'    -> True      # four 1s, even
```

(Run it and read the trace, counting the 1s by hand confirms each verdict: `1010101` has four 1s → even → True.) The simulator *is* the definition: a loop applying `δ`, then a membership test against `F`. That's a DFA, fully demystified.

A handy debugging trick, print the state trace:

```python
def trace(dfa, w):
    state, path = dfa.start, [dfa.start]
    for sym in w:
        state = dfa.transition.get((state, sym))
        path.append(state)
        if state is None:
            break
    verdict = state in dfa.accept
    print(" -> ".join(str(s) for s in path), f"  [{'ACCEPT' if verdict else 'reject'}]")

trace(even_ones, "0110")   # even -> even -> odd -> even -> even   [ACCEPT]
```

## Nondeterministic Finite Automata (NFA) - choice and ε-moves

Now we add a strange new capability: **nondeterminism**. In a DFA, `δ(q, a)` is one state. In an **NFA**, the transition can go to a *set* of states, zero, one, or several, and we also allow **ε-transitions**: moves the machine may take *without consuming any input symbol*.

Formally an NFA is `(Q, Σ, δ, q₀, F)` where the only change is

```
δ : Q × (Σ ∪ {ε}) → P(Q)      (P(Q) = the power set: δ returns a *set* of states)
```

**How an NFA accepts.** Think of it as exploring *all possible paths at once*. The machine accepts a string `w` if there *exists* **at least one** path of transitions (consuming `w`, with ε-moves allowed anywhere) that ends in an accept state. It's an existential ("is there a lucky guess?"), versus the DFA's single forced path. Equivalently, and this is how we'll implement it, at every moment the NFA is in a *set* of states simultaneously; it accepts if that set ever includes an accept state when the input runs out.

Why would we want this? **NFAs are dramatically easier to *design* and to *build from a regex*.** Nondeterminism lets you write "guess which branch is right" without machinery to actually choose. For example, "strings ending in `01`":

```
        Σ (loop on 0 and 1)
      ┌──────┐
      ▼      │
   ▶( q0 )──0──▶( q1 )──1──▶(( q2 ))
```

From `q0` we *loop forever on any symbol*, and *also* (nondeterministically) "guess" that the `01` suffix starts now by stepping to `q1` on a `0`. If the guess was right and the string really ends `01`, some path lands in `q2`. A DFA for the same language needs you to track more state explicitly; the NFA just says "guess the start of the suffix."

The astonishing fact we'll prove next: **nondeterminism adds no power.** Every NFA can be converted to a DFA recognizing the *same* language. NFAs are a convenience, not a stronger machine. The conversion is the **subset construction**.

### ε-closure

To handle ε-moves we need one helper. The **ε-closure** of a set of states `S` is "every state reachable from `S` using only ε-transitions (including the states of S themselves)."

```
ε-closure(S) = smallest set T with  S ⊆ T  and  (q ∈ T  ⇒  δ(q, ε) ⊆ T)
```

It's a graph reachability over ε-edges, a BFS/DFS. We'll need it constantly.

---

## Build it - an NFA simulator (sets of states + ε-closure)

```python
from dataclasses import dataclass

@dataclass
class NFA:
    states: set
    alphabet: set
    transition: dict      # {(state, symbol_or_'eps'): set_of_states}
    start: object
    accept: set

    def _eps_closure(self, states: set) -> frozenset:
        """All states reachable from `states` via ε-moves (transitive)."""
        stack = list(states)
        closure = set(states)
        while stack:
            q = stack.pop()
            for nxt in self.transition.get((q, "eps"), set()):
                if nxt not in closure:
                    closure.add(nxt)
                    stack.append(nxt)
        return frozenset(closure)

    def _move(self, states: set, symbol: str) -> set:
        """States reachable from `states` by consuming exactly one `symbol`."""
        result = set()
        for q in states:
            result |= self.transition.get((q, symbol), set())
        return result

    def accepts(self, w: str) -> bool:
        # Current "superposition" = set of states the NFA could be in now.
        current = self._eps_closure({self.start})
        for symbol in w:
            current = self._eps_closure(self._move(current, symbol))
            if not current:
                return False                       # all paths died
        return bool(current & self.accept)         # any path in an accept state?

# NFA for "ends in 01":
ends01 = NFA(
    states={"q0", "q1", "q2"},
    alphabet={"0", "1"},
    transition={
        ("q0", "0"): {"q0", "q1"},   # loop on 0 AND guess suffix starts
        ("q0", "1"): {"q0"},         # loop on 1
        ("q1", "1"): {"q2"},         # saw the 0, now want a 1
    },
    start="q0",
    accept={"q2"},
)

for w in ["01", "001", "1101", "010", "10", ""]:
    print(f"{w!r:6} -> {ends01.accepts(w)}")
# '01' True, '001' True, '1101' True, '010' False, '10' False, '' False
```

The body of `accepts` is the literal meaning of "explore all paths simultaneously": `current` is the set of every state some path could be in. ε-closure pulls in free moves; `_move` advances on the symbol; we accept if any live path is in `F`. **That set-of-states idea is also the seed of the subset construction**, because if we precompute, for every reachable *set* of states, where each symbol takes it, we've built a DFA.

## The subset construction (NFA → DFA), and the equivalence theorem

**Theorem.** For every NFA `N` there is a DFA `D` with `L(D) = L(N)`. So DFAs and NFAs recognize exactly the same class of languages, the regular languages.

**The idea (powerset / subset construction).** The NFA's "current set of states" can only ever be one of the *subsets* of `Q`. There are finitely many subsets (`2^|Q|` of them). So make a DFA whose **states are sets of NFA states**:

- DFA start state = `ε-closure({q₀})`.
- DFA transition: from a set `S` on symbol `a`, go to `ε-closure( move(S, a) )`.
- DFA accept states = every set `S` that contains at least one NFA accept state.

Each DFA "state" packages a whole NFA superposition. The NFA's existential ("does some path accept?") becomes the DFA's deterministic ("does this set contain an accept state?"). Reachability keeps the construction finite and usually small: we only build subsets actually reachable from the start, not all `2^|Q|`.

### Proof sketch (why it's correct)

We show by induction on `|w|` that `δ̂_D(S₀, w) = ε-closure(set of NFA states reachable from q₀ on w)`. Base case `w = ε`: `δ̂_D(S₀, ε) = S₀ = ε-closure({q₀})` ✓. Inductive step: assume it holds for `x`; for `xa`, the DFA does `δ_D(δ̂_D(S₀,x), a) = ε-closure(move(δ̂_D(S₀,x), a))`, which by the IH equals the ε-closure of all NFA states reachable on `xa`. So the DFA's state after reading `w` is *exactly* the NFA's set of reachable states after `w`. Hence the DFA accepts `w` (its state ⊇ an accept) iff the NFA accepts `w` (some path reaches an accept). ∎

The cost: the DFA can have up to `2^|Q|` states (**exponential blowup**), and there are families of NFAs that genuinely require it. That blowup is the price of determinism: it's *why* regex libraries that simulate the NFA directly (Thompson/Pike style) can beat backtracking engines on adversarial patterns. (More on that in the mini-project and the on-the-job note.)

## Build it - the subset construction

```python
def nfa_to_dfa(nfa: NFA) -> DFA:
    """Subset construction: build a DFA whose states are frozensets of NFA states."""
    start = nfa._eps_closure({nfa.start})
    dfa_states = {start}
    dfa_trans = {}
    worklist = [start]                      # BFS over reachable subsets

    while worklist:
        S = worklist.pop()
        for symbol in nfa.alphabet:
            target = nfa._eps_closure(nfa._move(S, symbol))
            if not target:
                continue                    # dead set: omit (implicit reject)
            dfa_trans[(S, symbol)] = target
            if target not in dfa_states:
                dfa_states.add(target)
                worklist.append(target)

    dfa_accept = {S for S in dfa_states if S & nfa.accept}  # any accept inside?
    return DFA(states=dfa_states, alphabet=set(nfa.alphabet),
               transition=dfa_trans, start=start, accept=dfa_accept)

# Convert the "ends in 01" NFA and check it agrees on every short string.
dfa = nfa_to_dfa(ends01)

import itertools
def all_strings(alphabet, max_len):
    for n in range(max_len + 1):
        for tup in itertools.product(sorted(alphabet), repeat=n):
            yield "".join(tup)

mismatch = [w for w in all_strings({"0", "1"}, 6)
            if dfa.accepts(w) != ends01.accepts(w)]
print("mismatches:", mismatch)             # [] - the two machines agree exactly
print("DFA has", len(dfa.states), "states")
```

The empty `mismatches` list is the equivalence theorem *checked empirically* on all 127 strings of length ≤ 6. We didn't trust the proof blindly; we made the machine vouch for it. The DFA ended up with a small handful of states, the subsets actually reachable, far below the `2³` worst case.

## Regular expressions = finite automata (Kleene's theorem)

Now the punchline that ties this to everyday tools. A **regular expression** over `Σ` is built from a tiny grammar:

```
R  ::=  ∅              (matches nothing)
     |  ε              (matches the empty string)
     |  a              (a ∈ Σ; matches the single symbol a)
     |  R₁ | R₂        (union / alternation: either)
     |  R₁ R₂          (concatenation: one then the other)
     |  R*             (Kleene star: zero or more)
     |  (R)            (grouping)
```

The language `L(R)` is defined to match: `L(∅)=∅`, `L(ε)={ε}`, `L(a)={a}`, `L(R₁|R₂)=L(R₁)∪L(R₂)`, `L(R₁R₂)=L(R₁)L(R₂)`, `L(R*)=L(R)*`. **Notice these are exactly union, concatenation, and star**, the three language operations from the vocabulary section. That's not a coincidence; it's the design.

**Kleene's Theorem.** A language is regular (recognized by some DFA/NFA) **if and only if** it is described by some regular expression. So all three, DFA, NFA, regex, describe *the same* class of languages. They are three notations for one idea.

The "regex ⇒ NFA" direction is the one that matters for building tools, and it's directly constructive: **Thompson's construction**. It builds an NFA *recursively from the structure of the regex*, with ε-transitions as the glue. Each sub-NFA has exactly one start and one accept state, which makes the gluing rules clean:

- **Symbol `a`:** `start ──a──▶ accept`.
- **`R₁ R₂` (concat):** build N₁ and N₂; add an ε-edge from N₁'s accept to N₂'s start. New start = N₁'s start, new accept = N₂'s accept.
- **`R₁ | R₂` (union):** new start with ε-edges into both N₁'s and N₂'s starts; both accepts ε-edge into a new common accept.
- **`R*` (star):** new start and accept; ε from new start to N₁'s start *and* to new accept (zero copies); ε from N₁'s accept back to N₁'s start (loop) *and* to new accept.

The `|`, concat, and `*` direction (regex ⇒ NFA) is Thompson. The reverse (NFA ⇒ regex) is **state elimination**, rip out states one at a time, relabeling edges with regexes, which we'll describe but not implement; it confirms the "only if" half. The practical workhorse is Thompson, because it's how `grep` and other NFA-simulation engines actually compile a pattern.

## Build it - regex → NFA (Thompson's construction)

We'll parse a small regex into an NFA. To keep states unique, every state is just an incrementing integer.

```python
class ThompsonNFA:
    """An NFA being built, with one start and one accept state."""
    def __init__(self):
        self.transitions = {}     # {(state, symbol_or_'eps'): set_of_states}
        self.counter = 0

    def new_state(self):
        s = self.counter
        self.counter += 1
        return s

    def add(self, src, symbol, dst):
        self.transitions.setdefault((src, symbol), set()).add(dst)

# Each builder returns (start_state, accept_state) of a fragment.

def build_symbol(nfa, a):
    s, f = nfa.new_state(), nfa.new_state()
    nfa.add(s, a, f)
    return s, f

def build_epsilon(nfa):
    s, f = nfa.new_state(), nfa.new_state()
    nfa.add(s, "eps", f)
    return s, f

def build_concat(nfa, frag1, frag2):
    s1, f1 = frag1
    s2, f2 = frag2
    nfa.add(f1, "eps", s2)        # glue: end of 1 -> start of 2
    return s1, f2

def build_union(nfa, frag1, frag2):
    s1, f1 = frag1
    s2, f2 = frag2
    s, f = nfa.new_state(), nfa.new_state()
    nfa.add(s, "eps", s1); nfa.add(s, "eps", s2)   # branch
    nfa.add(f1, "eps", f); nfa.add(f2, "eps", f)   # merge
    return s, f

def build_star(nfa, frag):
    s1, f1 = frag
    s, f = nfa.new_state(), nfa.new_state()
    nfa.add(s, "eps", s1)        # enter the loop body
    nfa.add(s, "eps", f)         # or skip it (zero copies)
    nfa.add(f1, "eps", s1)       # loop back for another copy
    nfa.add(f1, "eps", f)        # or exit
    return s, f
```

Those five builders *are* Thompson's construction. Next we need a parser to turn a regex string into a tree of these operations. We'll support `|`, concatenation (implicit), `*`, `(...)`, and literal symbols, a real, if small, regex. We'll write a recursive-descent parser (the same technique used for real languages in [Chapter 24.1](../24-Compilers/24.1-lexing-parsing-asts.md)).

```python
# Grammar (precedence: star > concat > union):
#   union  := concat ('|' concat)*
#   concat := star+              (juxtaposition = concatenation)
#   star   := atom '*'?
#   atom   := '(' union ')' | symbol

class RegexParser:
    def __init__(self, pattern):
        self.s = pattern
        self.i = 0

    def peek(self):
        return self.s[self.i] if self.i < len(self.s) else None

    def next(self):
        c = self.s[self.i]; self.i += 1; return c

    def parse(self, nfa):
        frag = self.union(nfa)
        if self.i != len(self.s):
            raise ValueError(f"unexpected {self.peek()!r} at {self.i}")
        return frag

    def union(self, nfa):
        frag = self.concat(nfa)
        while self.peek() == "|":
            self.next()
            rhs = self.concat(nfa)
            frag = build_union(nfa, frag, rhs)
        return frag

    def concat(self, nfa):
        frag = None
        while self.peek() is not None and self.peek() not in ")|":
            piece = self.star(nfa)
            frag = piece if frag is None else build_concat(nfa, frag, piece)
        if frag is None:                       # empty -> epsilon
            frag = build_epsilon(nfa)
        return frag

    def star(self, nfa):
        frag = self.atom(nfa)
        while self.peek() == "*":
            self.next()
            frag = build_star(nfa, frag)
        return frag

    def atom(self, nfa):
        c = self.peek()
        if c == "(":
            self.next()
            frag = self.union(nfa)
            if self.next() != ")":
                raise ValueError("missing )")
            return frag
        return build_symbol(nfa, self.next())  # a literal symbol

def regex_to_nfa(pattern, alphabet):
    nfa = ThompsonNFA()
    start, accept = RegexParser(pattern).parse(nfa)
    return NFA(states=set(range(nfa.counter)),
               alphabet=set(alphabet),
               transition=nfa.transitions,
               start=start, accept={accept})

# Try it:
N = regex_to_nfa("(a|b)*abb", alphabet={"a", "b"})
for w in ["abb", "aabb", "babb", "abab", "ab", ""]:
    print(f"{w!r:6} -> {N.accepts(w)}")
# 'abb' True, 'aabb' True, 'babb' True, 'abab' False, 'ab' False, '' False
```

We just compiled the regex `(a|b)*abb` into an NFA and *ran it* with the NFA simulator from earlier. The pipeline is **regex → (parse) → AST → (Thompson) → NFA → (simulate, or subset-construct to a DFA) → match**. That is, modulo features, **exactly the architecture of a real regex engine**, and of the lexer at the front of a compiler. We'll finish the engine in the mini-project.

## Closure properties of regular languages

Regular languages are remarkably well-behaved: combine them with the obvious operations and you stay regular. Knowing these lets you *prove a language regular by construction*, and they power optimizations.

The regular languages are **closed under**:

- **Union** `L₁ ∪ L₂`, NFA with a new start ε-branching to both (or, by regex, `R₁|R₂`).
- **Concatenation** `L₁L₂`, Thompson concat (`R₁R₂`).
- **Kleene star** `L*`, Thompson star (`R*`).
- **Complement** `Σ* \ L`, take the DFA, **swap accept and non-accept states**. (Only clean for DFAs, because each input has exactly one path; swapping for an NFA is wrong.)
- **Intersection** `L₁ ∩ L₂`, the **product construction**: run both DFAs in lockstep, state = `(state₁, state₂)`, accept when *both* accept. (Or use De Morgan: `L₁ ∩ L₂ = ¬(¬L₁ ∪ ¬L₂)`.)
- **Difference, reversal, homomorphism**, also closed (reversal: flip every arrow, swap start/accept after determinizing).

```python
def complement(dfa: DFA) -> DFA:
    """Swap accept / non-accept. Requires a *complete* DFA (transition on every
    (state, symbol)); add a dead state first if yours has missing edges."""
    return DFA(dfa.states, dfa.alphabet, dfa.transition, dfa.start,
               accept=dfa.states - dfa.accept)
```

These closures are not just theory: a tool that intersects two patterns, or that wants "match this but NOT that," is leaning on closure under intersection and complement under the hood.

## The limits of finite automata - the Pumping Lemma

Here's the deep payoff. A finite automaton has a *fixed, finite* number of states, say `p` of them. If you feed it a string longer than `p`, then by the **pigeonhole principle** ([Chapter 1.3](../01-Foundations/01.3-discrete-math.md)), it must revisit some state while reading those first `p` symbols. The piece of input read *between* two visits to that same state forms a loop in the machine, and a loop can be traversed 0, 1, 2, … times, all ending in the same place. So if a long string is accepted, a whole *family* of strings (with that loop section repeated any number of times) must also be accepted. That's the Pumping Lemma, the formal statement that **finite memory can't count unboundedly.**

**Pumping Lemma for regular languages.** If `L` is regular, then there exists a number `p ≥ 1` (the "pumping length") such that *every* string `s ∈ L` with `|s| ≥ p` can be split into three pieces `s = xyz` satisfying:

1. `|y| ≥ 1` (the middle piece is non-empty, it's the loop),
2. `|xy| ≤ p` (the loop occurs within the first `p` symbols),
3. for **all** `i ≥ 0`, `x yⁱ z ∈ L` (pumping y up or down keeps you in L).

We use it as a tool to **prove a language is NOT regular**, by contradiction. The structure is always the same and it's an adversarial game:

> Assume L is regular ⇒ it has a pumping length `p` (we don't get to choose p). We pick a *specific* string `s ∈ L` with `|s| ≥ p` (we choose s cleverly). The lemma promises *some* split `s = xyz` with the three properties (we don't get to choose the split, but conditions 1-2 constrain it). We show that for that split, some pump `x yⁱ z` is *not* in L, contradiction. Therefore L is not regular.

### Worked proof: `L = { aⁿbⁿ : n ≥ 0 }` is not regular

This is *the* canonical example, "equal numbers of a's then b's." Intuitively a DFA can't do it because it would have to remember `n`, an unbounded count, with finite states. Let's prove it.

> **Proof.** Suppose, for contradiction, that `L = {aⁿbⁿ}` is regular. Then the pumping lemma gives a pumping length `p`. Choose the string
> ```
> s = aᵖ bᵖ            (p a's followed by p b's)
> ```
> Then `s ∈ L` and `|s| = 2p ≥ p`, so the lemma applies: `s = xyz` with `|y| ≥ 1` and `|xy| ≤ p`.
>
> Because `|xy| ≤ p` and the first `p` symbols of `s` are all `a`'s, both `x` and `y` lie entirely within the `a`-block. So `y = aᵏ` for some `k ≥ 1` (condition 1 gives k ≥ 1).
>
> Now pump with `i = 2`: the string `x y² z = a^{p+k} bᵖ` has `p+k` a's but still `p` b's. Since `k ≥ 1`, the counts differ, so `x y² z ∉ L`. But the lemma demanded `x yⁱ z ∈ L` for **all** `i`. Contradiction.
>
> Therefore `L = {aⁿbⁿ}` is **not regular**. ∎

The moral: any language requiring you to *match an unbounded count on one side against the other* (balanced parentheses, `aⁿbⁿ`, palindromes, `aⁿbⁿcⁿ`) escapes the regular world. **Memory matters, and a finite automaton has none beyond its states.** To match nesting you need a *stack*, which is exactly the next rung up.

```python
# We can *see* the failure: any DFA you build for {a^n b^n} must cap n somewhere.
def dfa_anbn_up_to(N):
    """A DFA that accepts a^n b^n only for n <= N - it CANNOT handle all n."""
    trans = {}
    # states: ('a', k) seen k a's; ('b', k) need k more b's; 'dead'
    for k in range(N):
        trans[(('a', k), 'a')] = ('a', k + 1)
    for k in range(1, N + 1):
        trans[(('b', k), 'b')] = ('b', k - 1)
    for k in range(1, N + 1):
        trans[(('a', k), 'b')] = ('b', k - 1)   # switch from a's to b's
    states = {('a', k) for k in range(N + 1)} | {('b', k) for k in range(N + 1)}
    return DFA(states, {'a', 'b'}, trans, start=('a', 0), accept={('a', 0), ('b', 0)})

d = dfa_anbn_up_to(3)
print(d.accepts("aaabbb"))   # True  (n=3, within cap)
print(d.accepts("aaaabbbb")) # False (n=4 exceeds the cap - proving the point)
```

No finite `N` is enough; the language needs *all* n, and that's beyond any finite machine.

## Context-free grammars & languages - the next rung up

To recognize `{aⁿbⁿ}` we need a machine with **one stack** of unbounded depth: a **pushdown automaton (PDA)**. Intuitively, push a marker for each `a`, pop one for each `b`; accept iff the stack empties exactly as input ends. The stack *is* the memory the DFA lacked. The languages PDAs recognize are the **context-free languages (CFLs)**, rung 2 of the hierarchy, and we usually *describe* them not by drawing a PDA but by writing a **context-free grammar (CFG)**.

A **CFG** is a 4-tuple `G = (V, Σ, R, S)`:

- `V`, **variables** (nonterminals), like `S`, `Expr`, `Term`.
- `Σ`, **terminals** (the alphabet, the actual symbols of the language).
- `R`, **production rules** of the form `A → α`, where `A ∈ V` and `α` is a string of variables and terminals.
- `S ∈ V`, the **start variable**.

You generate strings by **derivation**: start with `S`, and repeatedly replace a variable using a rule, until only terminals remain. The set of all terminal strings derivable from `S` is `L(G)`.

### `{aⁿbⁿ}` as a CFG

```
S → a S b
S → ε
```

Derivation of `aabb`:

```
S ⇒ aSb ⇒ a aSb b ⇒ a a ε b b ⇒ aabb
```

Each `a` is *matched* with a `b` by the recursion `S → aSb`, and the recursion's depth IS the count. The grammar's nesting handles exactly what the finite automaton couldn't. (And yes, the same nesting handles balanced parentheses: `S → (S) | SS | ε`.)

### Derivations, parse trees, and ambiguity

A **parse tree** records *how* a string was derived: the root is `S`, each internal node is a variable, its children are the symbols its rule produced, and the leaves read left-to-right spell the string. Parse trees are the bridge to compilers: parsing a program *is* building its parse tree (then condensing it to an AST, [24.1](../24-Compilers/24.1-lexing-parsing-asts.md)).

Consider an arithmetic grammar:

```
E → E + E
E → E * E
E → ( E )
E → num
```

The string `num + num * num` has **two different parse trees**: one grouping as `(num + num) * num`, one as `num + (num * num)`. A grammar where some string has more than one parse tree is **ambiguous**. Ambiguity is poison for compilers: it means the meaning isn't determined by the grammar. We fix it by *layering precedence* into the grammar:

```
E → E + T | T          (sum of terms)
T → T * F | F          (product of factors)
F → ( E ) | num
```

Now `num + num * num` has a *unique* parse tree where `*` binds tighter than `+`, precedence is baked into the grammar's shape. This precedence-layering trick is one you'll reuse directly when you write a parser in Part 24.

### Where CFGs sit, and a glimpse of their pumping lemma

CFLs strictly contain the regular languages (every regex is a CFG, but `{aⁿbⁿ}` is a CFL that's not regular). They are closed under union, concatenation, and star, **but not** under intersection or complement (a famous gotcha). And just as finite automata have a ceiling, so do PDAs. There's a **pumping lemma for context-free languages**: every long enough string in a CFL can be written `s = uvxyz` with `|vy| ≥ 1`, `|vxy| ≤ p`, and `u vⁱ x yⁱ z ∈ L` for all `i`, note it pumps **two** pieces in tandem (because a parse tree tall enough must repeat a variable, creating a "doubled" loop). Using it, one proves `{aⁿbⁿcⁿ}` is **not context-free**: a single stack can match a's against b's *or* b's against c's, but not both at once. Matching *three* counts needs more than one stack, which pushes you toward the linear-bounded automata of rung 1 and, ultimately, the Turing machine of [Chapter 23.2](23.2-computability-and-complexity.md).

## Mini-project - build a tiny regex engine ("you just built grep")

Let's assemble the pieces into a working regex matcher and *feel* that it's the core of `grep`. We already have: a parser, Thompson's construction, an NFA simulator, and the subset construction. The engine just wires them together and adds a couple of conveniences.

```python
class Regex:
    """A compiled regular expression. Pipeline: pattern -> NFA -> DFA -> match."""
    def __init__(self, pattern, alphabet):
        self.pattern = pattern
        self.alphabet = set(alphabet)
        self.nfa = regex_to_nfa(pattern, self.alphabet)   # Thompson
        self.dfa = nfa_to_dfa(self.nfa)                    # determinize once

    def fullmatch(self, text) -> bool:
        """True iff the ENTIRE text matches (anchored both ends)."""
        return self.dfa.accepts(text)

    def search(self, text) -> bool:
        """True iff SOME substring matches - what grep reports per line.
        Trick: 'R appears somewhere' == the regex .*R.* matches the whole line.
        We implement it directly by trying every substring (clear over clever)."""
        n = len(text)
        for i in range(n + 1):
            for j in range(i, n + 1):
                if self.dfa.accepts(text[i:j]):
                    return True
        return False

    def grep(self, lines):
        """Like `grep PATTERN file`: yield (lineno, line) for matching lines."""
        for k, line in enumerate(lines, 1):
            if self.search(line):
                yield k, line


# --- Use it like grep ---
log = [
    "ERROR  disk full",
    "INFO   request ok",
    "ERROR  timeout on db",
    "WARN   retry scheduled",
]

# Pattern over the alphabet present in the text (here: letters + space + 'b','d'...).
alpha = set("".join(log))
pat = Regex("ERROR", alphabet=alpha)

print("=== grep 'ERROR' log ===")
for lineno, line in pat.grep(log):
    print(f"{lineno}: {line}")

# fullmatch vs search
even = Regex("(a|b)*abb", alphabet={"a", "b"})
print(even.fullmatch("aababb"))    # True  (whole string matches)
print(even.search("xxabbxx".replace("x", "a")))  # demo with a/b only
```

What you've built, honestly:
- **A regex parser** (recursive descent) → an **AST**.
- **Thompson's construction** turning that AST into an NFA with ε-moves.
- The **subset construction** compiling the NFA into a DFA so matching is linear-time per character.
- A **search** loop, which is exactly what `grep` does line by line.

Real engines add character classes (`[a-z]`, `\d`), anchors (`^`, `$`), `+`/`?` (sugar: `R+ = RR*`, `R? = R|ε`), and capture groups, but the *spine* is precisely what you wrote: **regex → NFA → (DFA) → match.** The first time the `grep` loop prints both ERROR lines, you can see that `grep` is just Kleene's theorem with I/O wrapped around it.

**A note on engine flavors.** Your DFA engine is *Thompson/Pike-style* (used by Go's `regexp`, RE2, and classic `grep`): it never backtracks, so it runs in linear time and can't be blown up by adversarial patterns. The other major family, PCRE, Python's `re`, Perl, JS, uses **backtracking**, which supports backreferences (`\1`) and lookarounds (features that go *beyond* regular languages!) but can suffer **catastrophic backtracking** (the `(a+)+$` denial-of-service bug). You just built the safe kind, and now you understand the tradeoff that decides which kind a tool uses.

## Common mistakes

- **Thinking "regex" (the programming feature) = regular languages.** Modern regex libraries add backreferences and lookahead, which can match *non-regular* languages. The theory term "regular expression" is the stricter `∅, ε, a, |, ·, *` grammar. Don't conflate them.
- **Forgetting ε-closure.** An NFA simulator that doesn't take ε-closure on the start state and after every move will silently mis-accept/reject. ε-moves are free and must be chased to a fixpoint.
- **Complementing an NFA by swapping accept states.** Only valid for a *complete DFA*. For an NFA, "some path accepts" doesn't negate to "some path rejects." Determinize first, complete it (add a dead state for missing transitions), *then* swap.
- **Pumping-lemma direction errors.** The lemma is a *necessary* condition for regularity, used to prove **non**-regularity by contradiction. You do **not** get to pick `p` or the split `xyz`; the adversary (the lemma) does. You only pick the string `s` and the pump count `i`. A "proof" that chooses the split is wrong.
- **Assuming a small NFA gives a small DFA.** Subset construction can blow up to `2^n` states. Usually it doesn't (only reachable subsets matter), but it can.
- **Using a regex to match nested/balanced structure** (HTML tags, parentheses, JSON). Nesting is context-free, not regular, so no true regex matches arbitrary nesting. Use a parser.

## On the job / interview angle

- **Lexers/tokenizers are DFAs.** Every compiler and many config/data parsers tokenize input with finite automata generated from regexes (`lex`/`flex` literally do the regex→NFA→DFA pipeline you built). Recognizing "this is a regular-language problem" tells you to reach for a state machine, not a fragile hand-rolled `if/else` soup.
- **"Why is this regex slow?"** is a real production question. The answer is usually *catastrophic backtracking* in a PCRE-style engine on a pathological pattern (a ReDoS vulnerability). Knowing that DFA-based engines (RE2) run in linear time, because you understand the NFA→DFA construction, is a senior-level insight.
- **Model state machines explicitly.** Connection lifecycles, UI flows, protocol handshakes, retry logic, these are DFAs. Drawing the `(Q, Σ, δ, q₀, F)` makes edge cases (illegal transitions) obvious. Interviewers love "I'd model this as a state machine."
- **The classic interview chestnut:** "Write a function to validate [phone numbers / IP addresses / a number format]." A clean answer builds or describes a DFA. And "is `aⁿbⁿ` regular?" tests whether you understand the pumping lemma, the expected answer is "no, finite automata can't count, here's the pumping argument."
- **Grammars show up in parsing tasks.** Configuration DSLs, query languages, calculator/expression evaluators, knowing CFGs, precedence layering, and ambiguity lets you write a correct parser instead of a buggy regex hack. This is the on-ramp to [Part 24](../24-Compilers/24.1-lexing-parsing-asts.md).

### Solutions

**1.** Reading binary left-to-right, each new bit updates value `v ← 2v + bit`. We only need `v mod 3`. States `{r0, r1, r2}` for the remainder; start `r0`; accept `{r0}`.

```python
trans = {}
for r in range(3):
    for bit in (0, 1):
        trans[(f"r{r}", str(bit))] = f"r{(2*r + bit) % 3}"
div3 = DFA({"r0","r1","r2"}, {"0","1"}, trans, "r0", {"r0"})
for n in range(10):
    b = bin(n)[2:]
    assert div3.accepts(b) == (n % 3 == 0), n
print("divisible-by-3 DFA passes")   # also note '' accepts (value 0)
```

The transition `r ← (2r+bit) mod 3` *is* Horner's rule on the remainder, finite memory suffices because we only track the residue, never the full number.

**2.** Determinizing (start = `{A}`):
- `{A}` on a → `{A,B}`, on b → `{A}`.
- `{A,B}` on a → `{A,B}` (from A), on b → `{A,C}` (A→A, B→C).
- `{A,C}` on a → `{A,B}`, on b → `{A}`. Accept (contains C).
- DFA accept states: any subset containing C, i.e. `{A,C}`.

```python
nfa = NFA({"A","B","C"}, {"a","b"},
          {("A","a"):{"A","B"}, ("A","b"):{"A"}, ("B","b"):{"C"}},
          "A", {"C"})
dfa = nfa_to_dfa(nfa)
mismatch = [w for w in all_strings({"a","b"}, 5)
            if dfa.accepts(w) != nfa.accepts(w)]
print("mismatches:", mismatch)        # []
```
The language is "ends in `ab`", sanity-checks the hand work.

**3.** `a*b*` accepts `""` (zero of each), `aabb` (a's then b's), **not** `abab` (interleaved) and **not** `ba`. `(ab)*` accepts `""` and `abab` (two copies of `ab`), **not** `aabb`, **not** `ba`. Compile both with `regex_to_nfa` and verify.

**4.** Suppose `L` (equal 0s and 1s) is regular with pumping length `p`. Choose `s = 0ᵖ1ᵖ ∈ L`, `|s| = 2p ≥ p`. By the lemma `s = xyz` with `|xy| ≤ p` and `|y| ≥ 1`; since the first `p` symbols are all `0`, `y = 0ᵏ` (`k ≥ 1`). Pump `i=0`: `xz = 0^{p−k}1ᵖ` has `p−k` zeros and `p` ones, unequal (`k ≥ 1`), so `xz ∉ L`. Contradiction; `L` is not regular. ∎ (Alternatively: `L ∩ 0*1* = {0ⁿ1ⁿ}`; if L were regular, so would that intersection be, but it isn't, using closure under intersection with the regular language `0*1*`.)

**5.** Product construction: states `Q = Q₁ × Q₂`. Start `(q₀¹, q₀²)`. Transition `δ((p,q), a) = (δ₁(p,a), δ₂(q,a))`, run both in lockstep. For **intersection**, accept iff *both* components accept: `F = F₁ × F₂`. (For union: `F = (F₁×Q₂) ∪ (Q₁×F₂)`.)

```python
def product(d1, d2, accept_rule):
    states = {(p, q) for p in d1.states for q in d2.states}
    alphabet = d1.alphabet & d2.alphabet
    trans = {}
    for (p, q) in states:
        for a in alphabet:
            np_ = d1.transition.get((p, a)); nq = d2.transition.get((q, a))
            if np_ is not None and nq is not None:
                trans[((p, q), a)] = (np_, nq)
    accept = {(p, q) for (p, q) in states if accept_rule(p in d1.accept, q in d2.accept)}
    return DFA(states, alphabet, trans, (d1.start, d2.start), accept)

# intersection:  product(d1, d2, lambda a, b: a and b)
```

**6.** Balanced parentheses: `S → ( S ) S | ε` (unambiguous). The grammar `S → SS | (S) | ε` is ambiguous: for `()()` you can derive `S ⇒ SS ⇒ (S)S ⇒ ()S ⇒ ()(S) ⇒ ()()` *or* group the other way `S ⇒ SS ⇒ S(S) ⇒ (S)(S) ⇒ ()()`, also `SS` itself can split `()() ` as (first `()`)(second `()`) or via a chain of three `S`s (`SSS` with an empty one), giving distinct parse trees. Two distinct trees ⇒ ambiguous.

## Teach it back

If you can explain these out loud without notes, the chapter stuck:

1. **Why a theory of computation exists:** to answer, *permanently*, "what kinds of problems can a machine with this much memory solve?", and the Chomsky hierarchy ranks machines by power, from finite automata (no memory) to Turing machines (everything).
2. **DFA (5-tuple `(Q, Σ, δ, q₀, F)`):** finite states, a deterministic transition `δ`, run by applying δ symbol-by-symbol and checking if you end in `F`. Recognizes exactly the **regular languages**.
3. **NFA = DFA in power, not just convenience:** nondeterminism + ε-moves mean "explore all paths at once / accept if some path works." The **subset construction** determinizes any NFA (DFA states = sets of NFA states), at up to exponential blowup.
4. **Kleene's theorem:** DFA ≡ NFA ≡ regex, three notations for the regular languages. **Thompson's construction** builds an NFA from a regex with ε-glue; that's how real regex engines and lexers work.
5. **Closure properties:** regular languages survive union, concat, star, complement (swap accept states of a complete DFA), and intersection (product construction).
6. **Pumping lemma:** finite memory ⇒ long strings force a state-repeat ⇒ a pumpable loop. Used to *prove non-regularity* (e.g. `aⁿbⁿ`) by the adversarial xyz argument. The limit: finite automata can't count unboundedly.
7. **CFGs/CFLs (rung 2):** add a stack (PDA). Grammars with productions/derivations/parse trees describe nesting (`aⁿbⁿ`, balanced parens, arithmetic). Watch for **ambiguity**; fix it with precedence layering. CFGs power parsers, straight into [compilers](../24-Compilers/24.1-lexing-parsing-asts.md).
8. **The mini-project:** you compiled a regex to an NFA to a DFA and matched lines with it, *you built the core of grep*, and you understand why DFA engines are immune to the catastrophic backtracking that bites PCRE.

Next: lift the ceiling entirely. Give the machine an unbounded tape, and you get the **Turing machine**, and the questions become "what can be computed *at all*?" and "what's *efficiently* computable?" That's [Chapter 23.2](23.2-computability-and-complexity.md).
