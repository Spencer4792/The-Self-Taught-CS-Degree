# Chapter 0.2 - Programming Fundamentals (starting from zero)

> *Goal: by the end of this chapter you can read and write real Python - variables, types, conditionals, loops, the everyday containers, and functions - run your own `.py` files, read an error without panic, and build four small but complete programs. This is the floor everything else in the book stands on.*

This chapter assumes you've never (or barely) written code. That's exactly the right starting point. You're not going to memorize syntax like a phrasebook; you're going to build a small mental model of how a program thinks, and hang the syntax off of it. Everything here is runnable. The deal of this whole book - no black boxes - starts now. Whenever we show code, you should actually type it and run it. Reading code is like reading sheet music: necessary, but you only learn to play by playing.

> **The one analogy for the whole chapter.** A program is a kitchen. **Variables** are labeled containers on the counter. **Data types** are what's in them (a number, some text, a yes/no flag). **Operators** are the basic actions (add, compare). **Conditionals** are "if the oven's hot, put it in." **Loops** are "stir until smooth." **Functions** are recipes you write once and reuse. **Lists/dicts/sets** are different ways to organize ingredients (a row of jars, a labeled spice rack, a bag of unique items). Keep this kitchen in mind and the rest is just learning where things are kept.

## How to use this chapter (the REPL is your friend)

You'll learn fastest by trying things immediately. Two ways to run Python:

1. **The interactive REPL.** Type `python` (or `python3`) in the terminal. You get a `>>>` prompt. Type `2 + 2`, press Enter, see `4`. It's a calculator that grows into a whole language. Type `exit()` to leave. This is perfect for "what does *this* do?" experiments.
2. **A `.py` file.** For anything more than a line or two, you put code in a file like `play.py` and run it with `python play.py`. (We do this for real at the end, in [0.2.13](#0213-writing-and-running-a-py-file).)

Throughout, you'll see lots of "predict the output" exercises. The single highest-value habit a beginner can build is to predict before running. Guess what the code prints, then run it. When your guess is wrong, that gap is the lesson - chase it down. Don't skip this; it's the difference between recognizing code and understanding it.

# Chapter 0.2.1 - Variables: labeled boxes

> Goal: understand what a variable is and assign and reassign values confidently.

## Concept

A **variable** is a name that points at a value. The `=` sign is **assignment**: "make this name refer to this value." It is not the math equals - it's an arrow pointing right-to-left.

```python
age = 27          # the name "age" now refers to the number 27
name = "Spencer"  # "name" refers to the text "Spencer"
```

> Think of a variable as a sticky label you slap onto a value. `age = 27` means "stick the label `age` on the value 27." You can peel the label off and stick it on something else anytime - that's *reassignment*.

```python
score = 10
score = score + 5   # read right side first: 10 + 5 = 15, then re-label "score" to 15
print(score)        # 15
```

That line `score = score + 5` looks paradoxical until you remember `=` runs the right side first, then re-points the name. Python evaluates `score + 5` (which is `15`), then sticks the `score` label on `15`.

## Build it

```python
favorite_number = 7
print(favorite_number)        # 7

favorite_number = 42          # reassign - the old 7 is forgotten
print(favorite_number)        # 42

x = 5
y = x                         # y now points at 5 too
x = 99                        # reassigning x does NOT change y
print(x, y)                   # 99 5
```

**Naming rules (and good taste):** names can have letters, digits, and underscores, but can't start with a digit. By convention you use `snake_case` (lowercase words joined by underscores). Good names *describe* the value: `user_age`, not `a`. Future-you reading this code will thank present-you.

## Exercises

1. Predict the output:
   ```python
   a = 3
   b = a
   a = 10
   print(a, b)
   ```
2. Predict the output:
   ```python
   total = 100
   total = total - 30
   total = total - 30
   print(total)
   ```
3. Which of these are valid variable names? `2cool`, `cool2`, `my-name`, `my_name`, `MyName`, `class_size`.

### Solutions

1. `10 3`. `b` was set to the *value* `3` (what `a` pointed to at that moment), not to `a` itself. Reassigning `a` later doesn't follow back to `b`.
2. `40`. Each line re-evaluates the right side then re-labels: `100 - 30 = 70`, then `70 - 30 = 40`.
3. Valid: `cool2`, `my_name`, `MyName`, `class_size`. Invalid: `2cool` (starts with a digit), `my-name` (hyphens aren't allowed, Python reads it as `my` minus `name`).

# Chapter 0.2.2 - Data types: what's actually in the box

> Goal: know the core built-in types and how to check and convert them.

## Concept

Every value has a **type**, what kind of thing it is. The five you need first:

| Type | Means | Examples |
|------|-------|----------|
| `int` | whole number | `0`, `42`, `-7` |
| `float` | decimal number | `3.14`, `-0.5`, `2.0` |
| `str` | text ("string" of characters) | `"hi"`, `'a'`, `""` |
| `bool` | truth value | `True`, `False` |
| `NoneType` | "nothing here" | `None` |

The type decides what operations make sense. `5 + 3` is `8`; `"5" + "3"` is `"53"` (text glued together). Same symbol, different meaning depending on type, so types matter a lot.

> `None` is Python's way of saying "deliberately empty." Not zero, not empty text - the absence of a value. A function that doesn't return anything gives back `None`. It's the placeholder for "we'll fill this in later" or "nothing applies here."

## Build it

```python
print(type(42))        # <class 'int'>
print(type(3.14))      # <class 'float'>
print(type("hello"))   # <class 'str'>
print(type(True))      # <class 'bool'>
print(type(None))      # <class 'NoneType'>
```

**Converting between types** (called *casting*):

```python
int("25")        # 25   (string -> int)
float("3.5")     # 3.5  (string -> float)
str(99)          # "99" (int -> string)
int(3.9)         # 3    (float -> int: TRUNCATES toward zero, does NOT round)
bool(0)          # False
bool("hi")       # True
```

This matters constantly because **`input()` always gives you a string**. If a user types `25`, you get the text `"25"`, and `"25" + 1` is an error. You must `int("25")` first.

> **Common mistakes**
> - `int(3.9)` is `3`, not `4`. It chops the decimal; it does **not** round. Use `round(3.9)` for that.
> - `int("3.5")` crashes (`ValueError`). You can only `int()` a string that's a whole number. To go from the string `"3.5"` to an int, do `int(float("3.5"))`.
> - `"5" + 5` raises `TypeError`, can't glue text and a number. Convert one to match the other.

## Exercises

1. Predict: `print(int(7.99))`
2. Predict: `print("3" + "4")` and `print(3 + 4)`
3. What does `int("12") + int("8")` give? What about `"12" + "8"`?
4. Predict: `print(type(2.0))`

### Solutions

1. `7`, truncates, no rounding.
2. `"34"` (string concatenation) and `7` (integer addition). Same `+`, behavior set by the operands' types.
3. `20` and `"128"`. First converts to ints and adds; second glues strings.
4. `<class 'float'>`, the `.0` makes it a float even though its value is whole.

# Chapter 0.2.3 - Operators: doing things to values

> Goal: fluently use arithmetic, comparison, and logical operators, including the tricky ones (`//`, `%`, `**`).

## Concept

**Arithmetic:**

```python
7 + 2     # 9   addition
7 - 2     # 5   subtraction
7 * 2     # 14  multiplication
7 / 2     # 3.5 division (always gives a float)
7 // 2    # 3   FLOOR division (drops the remainder, rounds down)
7 % 2     # 1   MODULO (the remainder)
7 ** 2    # 49  exponent (7 to the power 2)
```

The two that trip everyone up, and that you'll use constantly in this book, are `//` and `%`.

> **`//` and `%` are "sharing cookies."** You have 7 cookies and 2 friends. `7 // 2 = 3` is how many each friend gets (whole cookies only). `7 % 2 = 1` is how many are left over. Together they describe whole-number division completely. `%` is secretly everywhere: "is `n` even?" is `n % 2 == 0`. "Every 3rd item?" is `i % 3 == 0`. Learn to love the remainder.

**Comparison** (these produce a `bool`):

```python
5 == 5    # True   equal? (TWO equals signs - one is assignment!)
5 != 3    # True   not equal
5 > 3     # True
5 <= 5    # True
```

**Logical** (combine bools):

```python
True and False   # False  (both must be true)
True or False    # True   (at least one true)
not True         # False  (flip it)
```

> **The classic beginner trap:** `=` assigns, `==` compares. `if x = 5:` is a syntax error; you meant `if x == 5:`. Python actually protects you here by refusing `=` inside a condition, a kindness many languages don't offer.

## Build it

```python
total_cents = 287
dollars = total_cents // 100     # 2
cents   = total_cents % 100      # 87
print(dollars, "dollars and", cents, "cents")   # 2 dollars and 87 cents

print(10 % 2 == 0)   # True  -> 10 is even
print(7 % 2 == 0)    # False -> 7 is odd
```

**Operator precedence** follows math (PEMDAS-ish): `**` first, then `* / // %`, then `+ -`, then comparisons, then `not`, then `and`, then `or`. When in doubt, add parentheses - they cost nothing and remove all ambiguity.

```python
print(2 + 3 * 4)      # 14, not 20 - multiplication first
print((2 + 3) * 4)    # 20 - parens force the addition first
```

## Exercises

1. Predict: `print(17 // 5, 17 % 5)`
2. Predict: `print(2 ** 3 ** 2)` (hint: `**` groups right-to-left)
3. Write an expression that's `True` only when `x` is between 1 and 10 inclusive.
4. Predict: `print(3 + 4 > 5 and 2 < 1)`
5. A clock: it's hour `h` now (0-23). What hour is it `n` hours later, on a 24-hour clock? Write the expression.

### Solutions

1. `3 2`. `17 // 5` is 3 (5 goes in 3 times), remainder `17 % 5` is 2.
2. `512`. `**` is right-associative: `3 ** 2 = 9`, then `2 ** 9 = 512` (not `8 ** 2 = 64`).
3. `1 <= x <= 10` (Python allows chained comparisons), or `x >= 1 and x <= 10`.
4. `False`. `3 + 4 > 5` is `True`, `2 < 1` is `False`, `True and False` is `False`.
5. `(h + n) % 24`. The modulo wraps around past 23 back to 0, exactly clock behavior.

# Chapter 0.2.4 - Input and output: talking to the user

> Goal: print results clearly and read input from the keyboard, remembering input is always a string.

## Concept

`print(...)` shows things on screen. `input(...)` shows a prompt and waits for the user to type a line, then hands you that line **as a string.**

```python
print("Hello!")
print("a", "b", "c")          # a b c   (print adds spaces between arguments)
print("no newline", end="")   # 'end' replaces the default newline

answer = input("Type something: ")   # waits for you; stores what you typed (a str)
print("You typed:", answer)
```

> **Input is always a string.** Even if you type `42`, you get `"42"`. To do math you must convert: `age = int(input("Age? "))`. Forgetting this is the single most common beginner bug, so it bears repeating.

## Build it

```python
name = input("Your name? ")
age = int(input("Your age? "))          # convert right away
print("Hi", name + "! Next year you'll be", age + 1)
```

If the user types non-numbers for age, `int()` crashes with a `ValueError`. For now that's fine - you'll learn to handle it gracefully in the error-handling chapter. Building the habit of converting input is what matters today.

## Exercises

1. What's wrong with `age = input("Age? "); print(age + 1)`?
2. Write code that asks for two numbers and prints their sum (correctly, as a number).
3. Predict: `print("x", "y", "z", sep="-")` (look up: `sep` sets the separator between items).

### Solutions

1. `input` returns a string, so `age + 1` tries `str + int`, raising `TypeError`. Fix: `age = int(input("Age? "))`.
2. ```python
   a = float(input("First: "))
   b = float(input("Second: "))
   print("Sum:", a + b)
   ```
   (`float` so decimals work too.)
3. `x-y-z`. `sep` controls what goes *between* printed items (default is a space).

# Chapter 0.2.5 - Strings: working with text

> Goal: index, slice, and transform strings; use the most common methods; format output with f-strings.

## Concept

A **string** is a sequence of characters. Each character has a position (**index**) starting at **0**.

```
 s = "Python"
       P  y  t  h  o  n
       0  1  2  3  4  5      (positive indices)
      -6 -5 -4 -3 -2 -1      (negative indices, from the end)
```

**Indexing** grabs one character; **slicing** grabs a range `[start:stop]` (stop is *exclusive* - up to but not including).

```python
s = "Python"
s[0]      # 'P'
s[-1]     # 'n'   (last char)
s[0:3]    # 'Pyt'  (indices 0,1,2, NOT 3)
s[2:]     # 'thon' (from 2 to the end)
s[:2]     # 'Py'   (start to 2, exclusive)
s[::-1]   # 'nohtyP' (a step of -1 reverses it, a handy trick)
len(s)    # 6
```

> **Why does indexing start at 0?** Think of the index as "how many steps from the start." The first character is 0 steps in. It feels odd for a day, then becomes second nature - and it's consistent across lists, tuples, everything sequential in Python.

> Strings are **immutable** - you can't change a character in place. `s[0] = "J"` errors. Instead you build a *new* string: `"J" + s[1:]`.

## Build it - common methods

Methods are functions attached to a value, called with a dot:

```python
text = "  Hello, World!  "
text.lower()         # '  hello, world!  '
text.upper()         # '  HELLO, WORLD!  '
text.strip()         # 'Hello, World!'   (removes surrounding whitespace)
text.replace("l", "L")   # '  HeLLo, WorLd!  '
"a,b,c".split(",")   # ['a', 'b', 'c']   -> a list
"-".join(["a","b"])  # 'a-b'             -> a string
"World" in text      # True              (substring check)
"Hello".startswith("He")  # True
"42".isdigit()       # True
```

Note methods *return new strings* (because strings are immutable); they don't modify the original. `text.lower()` gives you a lowercased copy - `text` itself is unchanged unless you reassign it.

**f-strings** are the modern, readable way to build strings with values inside. Put an `f` before the quotes and `{}` around expressions:

```python
name = "Spencer"
age = 27
print(f"{name} is {age} years old.")          # Spencer is 27 years old.
print(f"Next year: {age + 1}")                # expressions work inside {}
price = 19.5
print(f"Total: ${price:.2f}")                 # Total: $19.50  (.2f = 2 decimals)
```

f-strings are so much cleaner than `+` concatenation that you'll use them by default.

## Exercises

1. Given `w = "computer"`, predict: `w[0]`, `w[-1]`, `w[1:4]`, `w[::-1]`.
2. Predict: `print("Hi".upper() + "!" * 3)`
3. Turn `"  data SCIENCE  "` into `"data science"` (trimmed, lowercased) in one line.
4. Use an f-string to print `"3 + 4 = 7"` using variables `a = 3`, `b = 4`.
5. Predict: `print(len("hello world"))` (don't forget the space).

### Solutions

1. `'c'`, `'r'`, `'omp'` (indices 1,2,3), `'retupmoc'` (reversed).
2. `HI!!!`. `.upper()` gives `"HI"`, `"!" * 3` repeats the string to `"!!!"`, then concatenated.
3. `"  data SCIENCE  ".strip().lower()` → `'data science'`. (Methods *chain*: each returns a string the next acts on.)
4. `print(f"{a} + {b} = {a + b}")`.
5. `11` (5 + 1 space + 5).

# Chapter 0.2.6 - Booleans, comparison & truthiness

> Goal: reason about True/False, and understand which values count as "truthy" or "falsy."

## Concept

A `bool` is `True` or `False`. Comparisons produce bools; `and`/`or`/`not` combine them (from [0.2.3](#chapter-023--operators-doing-things-to-values)). The new idea here is **truthiness**: in a condition, Python treats many non-bool values as if they were true or false.

**Falsy** values (treated as `False`): `False`, `0`, `0.0`, `""` (empty string), `[]` (empty list), `{}` (empty dict), `()` (empty tuple), `None`.
**Everything else is truthy**, including any non-empty string or container and any non-zero number.

```python
bool(0)        # False
bool("")       # False
bool("no")     # True   (non-empty string is truthy, even the word "no"!)
bool([])       # False
bool([0])      # True   (a list with something in it)
bool(None)     # False
```

This lets you write clean conditions. Instead of `if len(name) > 0:` you can write `if name:` ("if name has something in it"). Instead of `if items != []:` just `if items:`.

> **`bool("False")` is `True`!** The *string* `"False"` is non-empty, so it's truthy. Truthiness is about emptiness/zero-ness, not the meaning of the text. This bites people reading user input - don't test `if user_input == "True"` expecting bool behavior; compare strings explicitly.

> **On the job / interview angle.** "What's truthy in Python?" is a real interview warm-up. Being able to rattle off the falsy values - `0`, `0.0`, `""`, `[]`, `{}`, `()`, `None`, `False` - and explain that everything else is truthy signals you actually know the language, not just its surface.

## Exercises

1. Predict each: `bool(0)`, `bool(-1)`, `bool("0")`, `bool([])`, `bool([[]])`.
2. Rewrite `if len(s) == 0:` using truthiness.
3. Predict: `print(not "")` and `print(not "x")`.

### Solutions

1. `False`, `True` (non-zero), `True` (non-empty string), `False`, `True` (a list containing one item - an empty list - is itself non-empty).
2. `if not s:` ("if s is empty/falsy").
3. `True` (empty string is falsy, `not` flips it) and `False`.

# Chapter 0.2.7 - Conditionals: making decisions

> Goal: branch with `if`/`elif`/`else` and understand indentation as Python's block syntax.

## Concept

```python
if condition:
    # runs if condition is truthy
elif other_condition:
    # runs if the first was false AND this is truthy
else:
    # runs if all the above were false
```

Python uses **indentation** (whitespace) to define blocks - there are no `{ }` braces. Everything indented under an `if:` belongs to it. The standard is **4 spaces** per level. Be consistent; PyCharm handles this automatically.

> **Indentation is the structure, not decoration.** In Python, *where* a line sits horizontally determines *whether and when* it runs. Lines indented under the `if` only run when the `if` is true. Dedent back to the left, and you've left the `if` - that line always runs. This feels strict at first, then you realize it forces readable code.

## Build it

```python
temp = 72

if temp > 85:
    print("Hot")
elif temp > 60:
    print("Nice")
else:
    print("Cold")
# prints "Nice" - the first true branch wins, the rest are skipped
```

Only **one** branch of an if/elif/else chain runs - the first whose condition is truthy. Order matters: put the most specific conditions first.

Conditions can use everything from earlier chapters:

```python
age = int(input("Age? "))
if age >= 18 and age < 65:
    print("Adult")
elif age >= 65:
    print("Senior")
else:
    print("Minor")
```

> **Common mistakes**
> - Forgetting the colon `:` at the end of the `if`/`elif`/`else` line. Python tells you with a `SyntaxError`.
> - Mixing tabs and spaces - Python rejects it. Pick spaces (the IDE default).
> - Using `=` (assign) where you meant `==` (compare). Python catches this one for you.
> - Writing separate `if`s when you meant `elif`: with three independent `if`s, *more than one* can run. Use `elif`/`else` when the cases are mutually exclusive.

## Exercises

1. Predict the output:
   ```python
   x = 5
   if x > 0:
       print("positive")
   if x > 3:
       print("big")
   ```
2. Now predict with `elif`:
   ```python
   x = 5
   if x > 0:
       print("positive")
   elif x > 3:
       print("big")
   ```
3. Write a grader: score 90+ → "A", 80-89 → "B", 70-79 → "C", else "F".

### Solutions

1. Both `positive` and `big`. Two *independent* `if`s - both conditions are true, both run.
2. Only `positive`. With `elif`, once the first `if` matches, the `elif` is skipped entirely.
3. ```python
   score = int(input("Score? "))
   if score >= 90:
       print("A")
   elif score >= 80:
       print("B")
   elif score >= 70:
       print("C")
   else:
       print("F")
   ```
   Order matters: checking `>= 90` before `>= 80` means an A never falls through to B.

# Chapter 0.2.8 - Loops: doing things repeatedly

> Goal: use `for` and `while`, `range`, and `break`/`continue`; avoid infinite loops.

## Concept

Two loops:

- **`for`**, "do this once for each item in a collection." Best when you know what you're iterating over.
- **`while`**, "keep doing this as long as a condition holds." Best when you don't know how many times in advance.

```python
for item in [10, 20, 30]:
    print(item)          # 10, then 20, then 30

count = 0
while count < 3:
    print(count)         # 0, 1, 2
    count = count + 1    # MUST change the condition, or loop forever
```

> A `for` loop is "deal out each card in the deck and do something with it." A `while` loop is "keep stirring *while* the sauce is lumpy." The danger with `while` is forgetting to make the sauce smooth: if the condition never becomes false, you stir forever (an **infinite loop**; stop it with `Ctrl+C`).

**`range(...)`** generates a sequence of numbers, the workhorse of counting loops:

```python
range(5)        # 0,1,2,3,4         (stop only: 0 up to 5, exclusive)
range(2, 6)     # 2,3,4,5           (start, stop)
range(0, 10, 2) # 0,2,4,6,8         (start, stop, step)

for i in range(5):
    print(i)    # 0 1 2 3 4
```

**`break`** exits the loop immediately. **`continue`** skips to the next iteration.

```python
for i in range(10):
    if i == 5:
        break        # stop entirely at 5
    print(i)         # 0 1 2 3 4

for i in range(5):
    if i % 2 == 0:
        continue     # skip evens
    print(i)         # 1 3
```

## Build it

```python
# sum the numbers 1..100
total = 0
for n in range(1, 101):     # 1 to 100 inclusive (stop is exclusive, so 101)
    total += n              # += is shorthand for total = total + n
print(total)               # 5050

# loop over a string's characters
for ch in "cat":
    print(ch)              # c, a, t

# loop with index using enumerate
for i, ch in enumerate("cat"):
    print(i, ch)          # 0 c / 1 a / 2 t
```

> **Common mistakes**
> - **Infinite `while`:** forgetting to change the variable the condition checks. Always ask "what makes this stop?"
> - **Off-by-one with `range`:** `range(1, 100)` stops at 99. For 1..100 inclusive use `range(1, 101)`.
> - **Modifying a list while looping over it**, causes skipped or repeated items. Loop over a copy, or build a new list.

> **Interview angle.** A huge fraction of coding interview problems are "loop over this and accumulate / check / transform." Comfort with `for`, `range`, `enumerate`, and `break`/`continue` is non-negotiable. We'll drill this in [Chapter 0.3](00.3-problem-solving.md).

## Exercises

1. Predict: `for i in range(3, 0, -1): print(i)`
2. Predict the final `total`:
   ```python
   total = 0
   for n in range(1, 6):
       if n == 3:
           continue
       total += n
   print(total)
   ```
3. Print only the even numbers from 0 to 20 using a `for` loop.
4. Using a `while` loop, keep halving 100 (integer division) and printing until it reaches 0.

### Solutions

1. `3 2 1`, counts down with step `-1`, stopping before 0.
2. `12`. Sums 1+2+4+5; the `continue` skips adding 3 (`1+2+4+5 = 12`).
3. ```python
   for n in range(0, 21, 2):
       print(n)
   # or: for n in range(21):  if n % 2 == 0: print(n)
   ```
4. ```python
   x = 100
   while x > 0:
       print(x)
       x = x // 2     # 100, 50, 25, 12, 6, 3, 1, then 0 -> loop stops
   ```

# Chapter 0.2.9 - Lists, tuples, dicts, sets: the everyday containers

> Goal: know what each container is, the operations on each, and *when to reach for which.*

## Concept - the four containers at a glance

| Container | Looks like | Ordered? | Changeable? | Duplicates? | Reach for it when... |
|-----------|-----------|----------|-------------|-------------|----------------------|
| **list** | `[1, 2, 3]` | yes | yes | yes | you have an ordered, growable collection |
| **tuple** | `(1, 2, 3)` | yes | **no** | yes | a fixed group that shouldn't change (e.g. a coordinate) |
| **dict** | `{"a": 1}` | yes* | yes | keys unique | you need to look things up by a key/name |
| **set** | `{1, 2, 3}` | no | yes | **no** | you need unique items / fast membership tests |

\*dicts preserve insertion order in modern Python, but you shouldn't *rely* on order being meaningful, they're for lookups.

### Lists - the workhorse

```python
nums = [10, 20, 30]
nums[0]            # 10        (index, like strings)
nums[-1]           # 30
nums[1:]           # [20, 30]  (slicing, like strings)
len(nums)          # 3

nums.append(40)    # [10,20,30,40]   add to the end
nums.insert(0, 5)  # [5,10,20,30,40] insert at index
nums.pop()         # removes & returns last (40)
nums.remove(20)    # removes the first 20
nums[0] = 99       # lists are MUTABLE - change in place
30 in nums         # True (membership)
sorted([3,1,2])    # [1,2,3] (returns a NEW sorted list)
[1,2] + [3,4]      # [1,2,3,4]  (concatenation)
[0] * 3            # [0,0,0]    (repetition)
```

### Tuples - like lists, but frozen

```python
point = (3, 4)
point[0]           # 3
# point[0] = 9     # ERROR - tuples are immutable
x, y = point       # "unpacking": x=3, y=4
```

Use a tuple when the group is fixed and meaningful as a unit, coordinates, RGB colors, a row from a database. Immutability is a feature: it signals "this won't change" and lets tuples be used as dict keys.

### Dicts - key → value lookups

A **dictionary** maps **keys** to **values**. Think of a real dictionary: look up a word (key), get its definition (value). Lookups are *fast* regardless of size.

```python
ages = {"Alice": 30, "Bob": 25}
ages["Alice"]            # 30           (look up by key)
ages["Carol"] = 28       # add/update a key
"Bob" in ages            # True         (checks KEYS)
ages.get("Dan", 0)       # 0            (safe lookup with a default)
ages.keys()              # dict_keys(['Alice','Bob','Carol'])
ages.values()            # the values
for name, age in ages.items():   # loop over key-value pairs
    print(name, age)
```

> `ages["Dan"]` when "Dan" isn't a key raises `KeyError`. Use `ages.get("Dan", default)` when a key might be missing, it returns the default instead of crashing. This pattern is everywhere (e.g., counting things, [0.2.10 mini-project]).

### Sets - unique items, fast membership

```python
s = {1, 2, 2, 3}     # -> {1, 2, 3}  duplicates dropped automatically
s.add(4)
3 in s               # True - membership tests are very fast
{1,2,3} & {2,3,4}    # {2,3}   intersection (in both)
{1,2,3} | {3,4}      # {1,2,3,4} union (in either)
{1,2,3} - {2}        # {1,3}   difference
list(set([1,1,2,2])) # [1,2]   classic trick: dedupe a list
```

> **When do you pick which?** Need order and to keep duplicates and to grow it → **list.** A fixed bundle that shouldn't change → **tuple.** Looking things up by name/id → **dict.** "Have I seen this before?" or "give me the unique ones" → **set.** Ninety percent of everyday code is lists and dicts.

# Chapter 0.2.10 - Functions: naming and reusing logic

> Goal: define functions with parameters, return values, default arguments; understand scope.

## Concept

A **function** packages a piece of logic under a name so you can reuse it. `def` defines one; `return` hands a value back to the caller.

```python
def greet(name):              # 'name' is a PARAMETER
    return f"Hello, {name}!"  # send a value back

message = greet("Spencer")    # "Spencer" is the ARGUMENT
print(message)                # Hello, Spencer!
```

> **A function is a recipe.** You write it once ("how to make a greeting"). **Parameters** are the ingredients it expects. The **argument** is the actual ingredient you hand it when you *call* it. **`return`** is the finished dish handed back. A function with no `return` hands back `None` (it did something but produced no value, like `print`, which shows text but returns nothing).

```python
def add(a, b):
    return a + b

def shout(text):
    print(text.upper())       # no return -> returns None

x = add(2, 3)        # x = 5
y = shout("hi")      # prints HI, but y is None
```

**Default arguments** let parameters have a fallback value:

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

greet("Sam")                    # 'Hello, Sam!'   (uses default)
greet("Sam", "Hi")             # 'Hi, Sam!'       (overrides)
greet("Sam", greeting="Hey")   # 'Hey, Sam!'      (by name = keyword argument)
```

## Scope - where names live

A variable created *inside* a function is **local**, it exists only while the function runs and is invisible outside. This is a feature: functions don't accidentally clobber each other's variables.

```python
def f():
    secret = 42      # local to f
    return secret

f()                  # 42
# print(secret)      # ERROR - 'secret' doesn't exist out here
```

The function *can* read variables from the enclosing (global) scope, but to stay clean you should prefer to pass what you need in as parameters and return results out, rather than reaching for globals. "Inputs in via parameters, results out via return" keeps functions self-contained and testable.

> **Common mistakes**
> - Forgetting `return`, then wondering why the result is `None`. If you want a *value* back, you must `return` it. `print`-ing inside is not the same as returning.
> - Defining a function but never *calling* it. `def f(): ...` only creates it; `f()` runs it.
> - Mutable default arguments (`def f(items=[])`), a famous Python gotcha where the default list is shared across calls. For now: don't use mutable defaults; use `None` and create inside (`def f(items=None): items = items or []`).

> **Interview angle.** Functions are the unit of nearly every interview answer. Interviewers love watching you *factor* a messy solution into well-named functions, it shows you think in reusable pieces, not one giant blob.

## Mini-project - a tiny function library

```python
def is_even(n):
    return n % 2 == 0

def celsius_to_fahrenheit(c):
    return c * 9 / 5 + 32

def initials(full_name):
    parts = full_name.split()
    return "".join(part[0].upper() for part in parts)

print(is_even(10))                       # True
print(celsius_to_fahrenheit(100))        # 212.0
print(initials("ada lovelace"))          # AL
```

# Chapter 0.2.11 - Reading errors & basic debugging

> Goal: stop fearing red text. Read a traceback, identify the error type, and fix it methodically.

## Concept

Errors are not punishment - they're the most specific, honest help you'll ever get. When Python can't continue, it prints a **traceback**: a report of where it broke and why. The trick is to read it bottom-up.

```
Traceback (most recent call last):
  File "play.py", line 3, in <module>
    print(total / count)
ZeroDivisionError: division by zero
```

- The **last line** is the headline: the error **type** (`ZeroDivisionError`) and a **message** ("division by zero"). Read this first.
- The lines above show **where** it happened: file `play.py`, **line 3**, and the actual offending line of code.

So your reading order is: (1) what *kind* of error, (2) what does the message say, (3) which line, (4) go look at that line with the message in mind.

## The errors you'll meet most, and what they mean

| Error | Usually means | Typical fix |
|-------|---------------|-------------|
| `SyntaxError` | Python can't even parse it | missing `:`, unbalanced `()`/`[]`, smart quotes |
| `NameError` | used a name that doesn't exist | typo, or used before defining |
| `TypeError` | wrong type for an operation | `"5" + 5` - convert with `int()`/`str()` |
| `ValueError` | right type, bad value | `int("hello")` |
| `IndexError` | list/string index out of range | index past the end |
| `KeyError` | dict key doesn't exist | use `.get(key, default)` |
| `ZeroDivisionError` | divided by 0 | check the denominator first |
| `IndentationError` | inconsistent indentation | use 4 spaces, no tabs |
| `AttributeError` | method/attr doesn't exist on that type | typo or wrong type (`"x".apend`) |

## Build it - debugging by printing

The simplest debugger is `print`. When confused, print the values right before the failing line to *see reality* instead of guessing.

```python
def average(nums):
    total = sum(nums)
    count = len(nums)
    print("DEBUG total, count:", total, count)   # peek at the values
    return total / count

average([])   # reveals count is 0 -> that's why we'd get ZeroDivisionError
```

You'll learn the real IDE debugger (breakpoints, stepping) properly - it was introduced in [0.1.4](00.1-setup-and-tooling.md) and gets deeper use later. But `print`-debugging is always available and surprisingly powerful. The mindset: **don't guess, verify.** Most bugs are "I assumed a value was X; it was actually Y." Printing closes that gap instantly.

> **Rubber-duck debugging.** Explain the broken code, line by line, out loud, to a rubber duck (or any object). The act of narrating forces you to confront the step where your mental model and the code disagree. It sounds silly; it works embarrassingly often. (More technique in [0.3](00.3-problem-solving.md).)

## Exercises

For each snippet, name the error type and fix it:

1. `print("hi"`
2. `print(naem)` where you defined `name = "x"`
3. `result = "3" + 4`
4. `nums = [1, 2, 3]; print(nums[3])`
5. `d = {"a": 1}; print(d["b"])`

### Solutions

1. `SyntaxError` - missing closing `)`. Fix: `print("hi")`.
2. `NameError` - `naem` is a typo for `name`. Fix the spelling.
3. `TypeError` - string + int. Fix: `"3" + str(4)` (→ `"34"`) or `int("3") + 4` (→ `7`), depending on intent.
4. `IndexError` - valid indices are 0,1,2; `nums[3]` is past the end. Fix: use `nums[2]` or `nums[-1]`.
5. `KeyError` - no key `"b"`. Fix: `d.get("b", None)` for a safe lookup, or add the key first.

# Chapter 0.2.12 - Comments & clean style (PEP 8, lightly)

> Goal: write code future-you can read; comment the *why*, not the obvious *what*.

## Concept

A **comment** starts with `#`; Python ignores it. Comments are for humans.

```python
# Good: explains WHY (not obvious from the code)
rate = 0.07   # state sales tax for our region

# Bad: restates the obvious
x = x + 1     # add one to x   <- adds no information
```

The best comment is often a better variable name. `tax_rate = 0.07` needs no comment.

**PEP 8** is Python's style guide. The handful that matter early:

- **4 spaces** per indent level (never tabs; never 2).
- **`snake_case`** for variables and functions; `CONSTANTS_IN_CAPS`.
- Spaces around operators: `x = a + b`, not `x=a+b`.
- A space after commas: `f(a, b)`, not `f(a,b)`.
- Blank lines between functions to separate ideas.
- Descriptive names over comments where possible.

You don't memorize PEP 8 - you let the IDE auto-format (PyCharm: `Cmd/Ctrl+Alt+L`) and gradually internalize it. Clean code isn't vanity; it's how you (and teammates) avoid bugs born of confusion.

> **On the job.** In a real codebase, *readability is a feature.* Code is read far more often than written. Consistent style, good names, and comments that explain *why* are what separate a hireable junior from a frustrating one. Many teams run an auto-formatter (`black`) so style is never debated.

> **Docstrings** (a peek ahead): a string right under a `def` documents what a function does:
> ```python
> def add(a, b):
>     """Return the sum of a and b."""
>     return a + b
> ```
> Tools and editors surface it as help text. You'll use these more as functions get real.

## Exercises

2. Which of these comments is worth keeping? `count += 1  # increment count` vs `count += 1  # skip the header row`

### Solutions

1. ```python

       return slope * x_offset + 1
   ```
   (Spaces around `*` and `+`, descriptive names, body on its own indented line.)
2. The second. It explains *why* we add one (skipping a header), information not visible from the code. The first just restates the obvious.
3. ```python

       """Return True if n is even, False otherwise."""
       return n % 2 == 0
   ```

# Chapter 0.2.13 - Writing and running a `.py` file

> Goal: leave the REPL behind for real programs - write a file, run it, and structure it with the `__main__` guard.

## Build it

1. In your editor, create `hello.py`:
   ```python
   name = input("What's your name? ")
   print(f"Hello, {name}! You're officially writing programs.")
   ```
2. Save it.
3. In the terminal, from the folder containing the file:
   ```bash
   python hello.py        # (or python3 hello.py)
   ```
4. It runs top to bottom, asks your name, prints the greeting.

**Structuring a script** with functions and a `main`:

```python
def greet(name):
    return f"Hello, {name}!"

def main():
    name = input("Name? ")
    print(greet(name))

if __name__ == "__main__":   # only runs when THIS file is run directly
    main()
```

> **What's `if __name__ == "__main__":`?** When you *run* a file directly, Python sets a hidden variable `__name__` to `"__main__"`. When you *import* the file from another file, `__name__` is the module's name instead. So this guard means "only run `main()` when I run this file directly, not when something imports it." It lets you reuse a file's functions elsewhere without its script part firing. You'll see this in nearly every Python file you read - now it's not magic.

> If `python hello.py` says "can't open file," you're probably in the wrong folder. `pwd` to check, `cd` to the file's folder, or pass the full path. (See the [0.1 Troubleshooting FAQ](00.1-setup-and-tooling.md#troubleshooting-faq).)

# Chapter 0.2.14 - Mini-projects (fully worked)

Now let's assemble everything into four small, complete programs. Each is real - type it, run it, then tweak it. The "tweak it" instinct is where learning compounds.

## Project 1 - Number-guessing game

Concepts used: `import`, `while`, `if/elif/else`, `int(input(...))`, `break`.

```python
import random   # standard library module for randomness

def play():
    secret = random.randint(1, 100)    # random int from 1 to 100 inclusive
    attempts = 0
    print("I'm thinking of a number between 1 and 100.")

    while True:                        # loop forever until we 'break'
        guess = int(input("Your guess: "))
        attempts += 1

        if guess < secret:
            print("Too low.")
        elif guess > secret:
            print("Too high.")
        else:
            print(f"Got it in {attempts} attempts!")
            break                      # correct -> leave the loop

if __name__ == "__main__":
    play()
```

How it works: we pick a `secret`, then loop forever reading guesses. Each guess nudges the user higher/lower until they match, at which point `break` ends the game. `attempts` counts tries. *Tweak:* limit guesses to 7 and lose if exceeded (`if attempts >= 7: print("Out of guesses!"); break`).

## Project 2 - A terminal to-do list

Concepts used: lists, dict-style menu, `while`, functions, string methods.

```python
def show(todos):
    if not todos:                      # truthiness: empty list is falsy
        print("(no tasks yet)")
    for i, task in enumerate(todos, start=1):   # number from 1
        print(f"{i}. {task}")

def main():
    todos = []
    while True:
        print("\n--- TO-DO ---")
        show(todos)
        cmd = input("[a]dd, [d]one, [q]uit: ").strip().lower()

        if cmd == "a":
            todos.append(input("New task: ").strip())
        elif cmd == "d":
            n = int(input("Finish which number? "))
            if 1 <= n <= len(todos):
                done = todos.pop(n - 1)     # -1: humans count from 1, lists from 0
                print(f"Done: {done}")
            else:
                print("No such task.")
        elif cmd == "q":
            print("Bye!")
            break
        else:
            print("Unknown command.")

if __name__ == "__main__":
    main()
```

How it works: `todos` is a list of strings. The menu loops, dispatching on the typed command. `enumerate(todos, start=1)` numbers tasks for humans; `pop(n - 1)` converts that human number back to a 0-based index. Note the defensive `if 1 <= n <= len(todos)` so a bad number doesn't crash with `IndexError`. *Tweak:* add an `[e]dit` command, or save tasks to a file (a great bridge into file I/O later).

## Project 3 - Temperature converter

Concepts used: functions, conditionals, f-strings, float formatting.

```python
def c_to_f(c):
    return c * 9 / 5 + 32

def f_to_c(f):
    return (f - 32) * 5 / 9

def main():
    direction = input("Convert C to F or F to C? (c/f): ").strip().lower()
    value = float(input("Temperature: "))

    if direction == "c":
        result = c_to_f(value)
        print(f"{value}°C = {result:.1f}°F")
    elif direction == "f":
        result = f_to_c(value)
        print(f"{value}°F = {result:.1f}°C")
    else:
        print("Please type 'c' or 'f'.")

if __name__ == "__main__":
    main()
```

How it works: two small, testable conversion functions hold the math; `main` handles talking to the user. `{result:.1f}` formats to one decimal place. Splitting "logic" (the conversions) from "I/O" (the prompts) is a habit worth forming now - it makes the math trivially testable with `pytest`. *Tweak:* add Kelvin.

## Project 4 - Tip calculator

Concepts used: floats, `%` formatting, integer split math, f-strings.

```python
def main():
    bill = float(input("Bill amount: $"))
    tip_pct = float(input("Tip %: "))
    people = int(input("Split between how many? "))

    tip = bill * tip_pct / 100
    total = bill + tip
    per_person = total / people

    print(f"Tip:        ${tip:.2f}")
    print(f"Total:      ${total:.2f}")
    print(f"Per person: ${per_person:.2f}")

if __name__ == "__main__":
    main()
```

How it works: pure arithmetic plus `:.2f` to show money with two decimals. *Tweak:* guard against `people == 0` (which would `ZeroDivisionError` - connect it to [0.2.11](#chapter-0211--reading-errors--basic-debugging)), or round the per-person amount *up* to the nearest cent so the tip is never short.
