# Chapter 3.6 - Greedy and Backtracking

> *Goal: master two opposite philosophies for building solutions. Greedy commits to the locally best choice and never looks back: fast, but only correct when you can prove it. Backtracking explores every choice and rewinds at dead ends: slow but complete, made practical by pruning. By the end you'll have built interval scheduling, Huffman coding, N-Queens, a Sudoku solver, and subset/permutation generators, all from scratch with passing tests.*

---

## Start here

Before any proofs or code, here are the two ideas in plain pictures.

**Greedy:** grab the best-looking option right now, and never look back. Picture the grocery store: you walk up to the registers and join the shortest line you can see at this moment, without simulating every line's future or peeking at how full each cart is. You take the locally best option and commit. That's greedy: one quick decision rule, applied over and over, no undo. It's fast. The catch: the shortest line right now might have someone with a price check and forty coupons, and a worse-looking line would've been faster. Greedy can be fooled by the future, which is why it's only trustworthy when we can prove the local choice never costs us later.

**Backtracking:** try a path in a maze; if it dead-ends, walk back and try another. Picture standing in a hedge maze. You pick a corridor and walk down it. When you hit a dead end, you retrace your steps to the last fork and take a different corridor. You keep doing this, systematically, until you reach the exit, or until you've actually tried everything and know there's no way out. Backtracking is exhaustive but smart: it explores choices, and the key move is undoing a choice to free yourself to try the next one. It's slower than greedy, but it's complete: it will find a solution if one exists.

These are opposite philosophies. Greedy commits and never reconsiders; backtracking tentatively tries and rewinds. Greedy bets that being locally smart is globally smart: sometimes a great bet, sometimes a disaster. Backtracking refuses to bet: it checks the alternatives, paying in time for that certainty. A large part of algorithm design is sizing up a new problem and asking, "can I get away with a fast greedy rule here, or do I need to actually search?" This chapter trains that instinct. We'll see greedy win (interval scheduling, Huffman), greedy lose (coin change with `{1,3,4}`), and backtracking reach where greedy can't (N-Queens, Sudoku, generating all combinations).

## The greedy paradigm

Here's the whole idea of a greedy algorithm in one sentence: **at each step, make the choice that looks best right now, and never reconsider it.** No undoing, no exploring alternatives. You walk forward, grabbing the locally optimal option, and hope that a sequence of locally optimal choices adds up to a globally optimal answer.

That "and hope" is the dangerous part. Greedy is seductive because it's fast, usually one pass, often `O(n log n)` because of a sort. But it's frequently wrong. The skill of greedy algorithms is knowing when the hope is justified.

Two properties make greedy provably correct:

1. **Greedy-choice property.** There exists a globally optimal solution that *agrees with* the greedy first choice. In other words, taking the locally best option doesn't lock us out of an optimal answer; we can always build the rest of an optimal solution on top of it.
2. **Optimal substructure.** After we commit to the greedy choice, what remains is a smaller instance of the *same* problem, and an optimal solution to the whole contains an optimal solution to that subproblem.

If both hold, greedy works. The tool we use to prove the greedy-choice property is the **exchange argument**, demonstrated carefully below. The idea: take any optimal solution, and show you can swap one of its choices for the greedy choice without making it worse. Repeat, and you've transformed an arbitrary optimum into the greedy solution, so the greedy solution is also optimal.

## When greedy fails - building intuition

Before you trust greedy anywhere, you should see how it breaks. The cleanest counterexample is **coin change with arbitrary denominations**.

The greedy coin-change algorithm: to make an amount, repeatedly take the largest coin that fits. With US coins `{1, 5, 10, 25}` this happens to be optimal. With a weird set like `{1, 3, 4}`, it isn't.

```python
def greedy_coin_change(amount, coins):
    """Return number of coins greedy uses, taking largest-fitting coin each step."""
    coins = sorted(coins, reverse=True)
    count = 0
    for c in coins:
        while amount >= c:
            amount -= c
            count += 1
    return count if amount == 0 else None


def optimal_coin_change(amount, coins):
    """True optimum via DP - the honest answer to compare against."""
    INF = float("inf")
    best = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and best[a - c] + 1 < best[a]:
                best[a] = best[a - c] + 1
    return best[amount] if best[amount] != INF else None


# Greedy on {1,3,4} making 6: takes 4, then 1, then 1 -> 3 coins.
# Optimal: 3 + 3 -> 2 coins. Greedy is WRONG.
assert greedy_coin_change(6, [1, 3, 4]) == 3
assert optimal_coin_change(6, [1, 3, 4]) == 2
print("Greedy coin change on {1,3,4} for 6:", greedy_coin_change(6, [1, 3, 4]))
print("Optimal:", optimal_coin_change(6, [1, 3, 4]))
```

Greedy grabs the 4 because it's locally biggest, which strands us at 2 and forces two pennies. The optimum ignores the locally tempting 4 entirely. **Lesson: greedy can't see that a worse-looking choice now enables a better outcome later.** Whenever a problem has that flavor, where a choice's value depends on the future, be suspicious of greedy and reach for DP.

The **0/1 knapsack** fails the same way: greedily taking the highest value-per-weight item can leave capacity that no remaining item fits well. (Fractional knapsack, where you *can* take pieces, is greedy-optimal; the difference is whether the substructure stays clean.)

## Interval scheduling - and a real proof

Now a problem where greedy *is* provably optimal, so we can show the exchange argument in full.

**Interval scheduling (activity selection):** given `n` activities each with a start and finish time, select the largest set of mutually non-overlapping activities. One room, one resource, maximize how many things you fit.

The greedy rule that works: **always pick the activity that finishes earliest among those still compatible.** Intuition: finishing early frees the resource as soon as possible, leaving the most room for everything else.

```python
def interval_scheduling(intervals):
    """
    intervals: list of (start, finish). Return a max-size set of
    non-overlapping intervals, chosen greedily by earliest finish time.
    """
    # Sort by finish time. This is the heart of the algorithm.
    chosen = []
    last_finish = float("-inf")
    for start, finish in sorted(intervals, key=lambda iv: iv[1]):
        if start >= last_finish:      # compatible with the last one we took
            chosen.append((start, finish))
            last_finish = finish
    return chosen


events = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9),
          (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
result = interval_scheduling(events)
print("Selected:", result)
assert len(result) == 4   # e.g. (1,4),(5,7),(8,11),(12,16)

# Verify the result really is non-overlapping.
for i in range(1, len(result)):
    assert result[i][0] >= result[i - 1][1]
print("All selected intervals are mutually compatible.")
```

### Proof of optimality (exchange argument)

Let's prove the greedy-by-earliest-finish solution is optimal.

Let greedy's choices, in order, be `g₁, g₂, …, g_k` (sorted so each finishes before the next starts). Let `o₁, o₂, …, o_m` be the activities of *any* optimal solution, also sorted by finish time. The claim is `k = m`.

**Lemma (greedy stays ahead).** For every `i` from `1` to `k`, the finish time of `gᵢ` is `≤` the finish time of `oᵢ`. That is, after picking `i` activities, greedy has finished no later than the optimum has.

*Proof by induction on `i`.*
- **Base case** `i = 1`: greedy explicitly chooses the activity with the smallest finish time of all, so `finish(g₁) ≤ finish(o₁)`. ✓
- **Inductive step:** Assume `finish(gᵢ₋₁) ≤ finish(oᵢ₋₁)`. Since the optimal solution is internally compatible, `start(oᵢ) ≥ finish(oᵢ₋₁) ≥ finish(gᵢ₋₁)`. So `oᵢ` is compatible with greedy's first `i−1` picks: a legal candidate at greedy's `i`-th step. Greedy picks the compatible activity with the earliest finish, so `finish(gᵢ) ≤ finish(oᵢ)`. ✓

**Conclusion.** Suppose for contradiction the optimum is strictly larger, `m > k`. By the lemma, `finish(g_k) ≤ finish(o_k)`. Then `o_{k+1}` exists, and `start(o_{k+1}) ≥ finish(o_k) ≥ finish(g_k)`, so `o_{k+1}` is compatible with all of greedy's `k` picks. But then greedy would not have stopped; it would have taken `o_{k+1}` (or something finishing even earlier). Contradiction. Therefore `k = m`: greedy selects as many activities as the optimum. ∎

That's the exchange/stay-ahead flavor in action: we showed greedy never falls behind, so it can't end up with fewer activities. **Runtime:** sort is `O(n log n)`, the single pass is `O(n)`, so `O(n log n)` total.

### Stepped trace - watch greedy pick intervals

Let's run the algorithm by hand on a small set so the pick/skip decision is visible. Candidates, already sorted by finish time (the sort does the heavy lifting):

```

```

You sweep left to right, keeping one number in your pocket, `last_finish`, the finish time of the most recent interval you took. You take the next interval only if its `start >= last_finish`.

def interval_scheduling_trace(intervals):

    chosen = []
    last_finish = float("-inf")

        if start >= last_finish:
            chosen.append((start, finish))

## Worked example - Jump Game (greedy reachability)

A different flavor of greedy that doesn't need a sort. **Jump Game:** given an array `nums` where `nums[i]` is the *maximum* jump length from index `i`, can you reach the last index starting from index 0?

The naive approach backtracks over every possible jump length, which is exponential. But there's a clean greedy: **sweep left to right, tracking the farthest index reachable so far.** If you ever stand on an index beyond your farthest reach, you're stranded and the answer is no. Otherwise you keep extending the frontier.

```python
def can_jump(nums):
    """Can we reach the last index? Greedy frontier of farthest-reachable index."""
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:            # we can't even stand here -> stuck
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(nums) - 1:
            return True             # last index already reachable
    return True


assert can_jump([2, 3, 1, 1, 4]) is True     # 0->1->4, or 0->2...->4
assert can_jump([3, 2, 1, 0, 4]) is False    # the 0 at index 3 traps us
assert can_jump([0]) is True                 # already at the end
print("Jump Game passed.")
```

**Why the greedy is correct.** `farthest` is the union of everything reachable from any index you've validly stood on. Reachability is "monotone": if you can reach index `i`, you can reach any index between your current position and `i + nums[i]`. So a single forward sweep maintaining the maximum frontier captures all reachability with no need to try individual jump sequences; there's no future-dependence for a worse-looking jump to unlock later. **Runtime:** one pass, `O(n)` time, `O(1)` space. (Contrast: the backtracking-over-all-jumps version is `O(2ⁿ)`. This is exactly the "can you get away with greedy?" instinct paying off.)

## Worked example - Fractional Knapsack (greedy-optimal, unlike 0/1)

Back in the "when greedy fails" section we noted that **0/1 knapsack** breaks greedy but **fractional knapsack** doesn't. Let's build the fractional version to see exactly why.

**Fractional knapsack:** items each have a weight and a value, the knapsack holds `capacity` units of weight, and you're allowed to take fractions of an item (think gold dust, not gold bars). Maximize total value.

The greedy rule: **sort by value-per-weight (density), descending, and greedily fill.** Take whole items while they fit, then a fraction of the next item to top off the capacity exactly.

```python
def fractional_knapsack(items, capacity):
    """
    items: list of (weight, value). Fractions allowed.
    Greedily take highest value-per-weight first. Returns max total value.
    """
    items = sorted(items, key=lambda it: it[1] / it[0], reverse=True)
    total_value = 0.0
    for weight, value in items:
        if capacity <= 0:
            break
        take = min(weight, capacity)          # whole item, or whatever fits
        total_value += value * (take / weight)
        capacity -= take
    return total_value


# Densities: (10,60)=6.0, (20,100)=5.0, (30,120)=4.0. Capacity 50.
# Take all of item1 (10w,60v), all of item2 (20w,100v), then 20/30 of item3.
val = fractional_knapsack([(10, 60), (20, 100), (30, 120)], 50)
assert abs(val - 240.0) < 1e-9    # 60 + 100 + (2/3)*120 = 240
print(f"Fractional knapsack max value: {val}")
```

**Why greedy works here but not for 0/1.** Because fractions are allowed, there's never wasted capacity: if a higher-density item exists, swapping any unit of a lower-density item for it strictly improves the total. That's a clean exchange argument. In 0/1 knapsack you can't take fractions, so greedily grabbing the densest item can leave an awkward leftover gap that no remaining whole item fits well. The choice's value depends on what's left, and you need DP. Same problem, one small rule change ("fractions allowed"), and greedy flips from wrong to provably optimal. **Runtime:** `O(n log n)` for the sort, then `O(n)`.

## Huffman coding - the idea

Now the best-known greedy algorithm of all: **Huffman coding**, a foundation of data compression.

The problem: you have a stream of symbols (say characters of text) with known frequencies. You want to assign each symbol a binary code so the total encoded length is minimized. Two requirements:

1. **Prefix-free.** No symbol's code is a prefix of another's. This lets a decoder read bits left-to-right and know exactly when one symbol ends, no delimiters needed.
2. **Frequent symbols get short codes.** Like Morse code: `e` is one dot, `q` is long.

A prefix-free code is exactly a **binary tree** where symbols live at the leaves, and the path from root to leaf (left = `0`, right = `1`) is that symbol's code. The cost is `Σ frequency(symbol) × depth(symbol)`, the expected number of bits.

**Huffman's greedy rule:** repeatedly merge the **two least-frequent** nodes into a new parent whose frequency is their sum. Keep merging until one tree remains.

### Why the greedy merge is optimal

The intuition for correctness, again via an exchange argument: in *some* optimal tree the two lowest-frequency symbols, call them `x` and `y`, can be made **sibling leaves at the deepest level**. Why? If an optimal tree put a higher-frequency symbol deeper than `x`, swapping it with `x` would *decrease* total cost (you'd be giving the deeper, more expensive slot to the rarer symbol), contradicting optimality. So there's no penalty in assuming the two rarest symbols sit together at the bottom. Merge them into one combined symbol of frequency `f(x)+f(y)`, recurse on the smaller alphabet, and the optimal solution to the smaller problem extends to an optimal solution of the original. That's optimal substructure plus the greedy-choice property, the two ingredients again.

## Build it - Huffman coding from scratch

We'll build every piece: frequency table → min-heap → tree → code table → encode → decode.

```python
import heapq
from collections import Counter


class HuffNode:
    """A node in the Huffman tree. Leaves carry a symbol; internal nodes don't."""
    __slots__ = ("freq", "symbol", "left", "right")

    def __init__(self, freq, symbol=None, left=None, right=None):
        self.freq = freq
        self.symbol = symbol     # None for internal nodes
        self.left = left
        self.right = right

    # heapq needs a total order. Compare by frequency; that's all we need.
    def __lt__(self, other):
        return self.freq < other.freq


def build_frequency_table(text):
    """Count how often each symbol appears."""
    return Counter(text)


def build_huffman_tree(freq_table):
    """Greedy merge: pop two smallest, push their parent, repeat."""
    # Build a leaf for each symbol and heapify by frequency.
    heap = [HuffNode(freq, sym) for sym, freq in freq_table.items()]
    heapq.heapify(heap)

    # Edge case: a single distinct symbol. Give it a parent so it has a code.
    if len(heap) == 1:
        only = heapq.heappop(heap)
        return HuffNode(only.freq, left=only)

    while len(heap) > 1:
        a = heapq.heappop(heap)          # least frequent
        b = heapq.heappop(heap)          # next least frequent
        merged = HuffNode(a.freq + b.freq, left=a, right=b)
        heapq.heappush(heap, merged)

    return heap[0]                        # the root


def build_codes(root):
    """Walk the tree; left=0, right=1. Return {symbol: bitstring}."""
    codes = {}

    def walk(node, prefix):
        if node is None:
            return
        if node.symbol is not None:      # leaf
            codes[node.symbol] = prefix or "0"   # "0" handles single-symbol case
            return
        walk(node.left, prefix + "0")
        walk(node.right, prefix + "1")

    walk(root, "")
    return codes


def huffman_encode(text):
    """Return (encoded_bitstring, tree_root). Need the tree to decode."""
    if not text:
        return "", None
    freq = build_frequency_table(text)
    root = build_huffman_tree(freq)
    codes = build_codes(root)
    encoded = "".join(codes[ch] for ch in text)
    return encoded, root


def huffman_decode(encoded, root):
    """Walk the tree bit by bit; emit a symbol each time we hit a leaf."""
    if not encoded or root is None:
        return ""
    # Single-symbol tree: every bit maps to that one symbol.
    if root.symbol is not None:
        return root.symbol * len(encoded)

    out = []
    node = root
    for bit in encoded:
        node = node.left if bit == "0" else node.right
        if node.symbol is not None:      # reached a leaf
            out.append(node.symbol)
            node = root                  # restart from the top
    return "".join(out)
```

### Tests - round-trip and compression ratio

```python
def test_huffman_roundtrip():
    samples = [
        "abracadabra",
        "the quick brown fox jumps over the lazy dog",
        "aaaaaaaaaabbbbbccd",
        "x",                  # single distinct symbol
        "xxxxxxxx",           # single symbol repeated
        "mississippi",
    ]
    for text in samples:
        encoded, root = huffman_encode(text)
        decoded = huffman_decode(encoded, root)
        assert decoded == text, f"round-trip failed for {text!r}: got {decoded!r}"
    print("Huffman round-trip tests passed.")


def test_huffman_compression():
    text = "aaaaaaaaaabbbbbccd"          # very skewed frequencies
    encoded, root = huffman_encode(text)
    fixed_bits = len(text) * 8           # naive 8-bit-per-char baseline
    huff_bits = len(encoded)
    ratio = huff_bits / fixed_bits
    print(f"Original: {fixed_bits} bits, Huffman: {huff_bits} bits, "
          f"ratio: {ratio:.2%}")
    assert huff_bits < fixed_bits        # we actually compressed
    # 'a' is most frequent -> should get the shortest code.
    codes = build_codes(root)
    assert len(codes["a"]) <= len(codes["d"])
    print("Huffman compression test passed.")


def test_prefix_free():
    """No code is a prefix of another - the property that makes decoding work."""
    _, root = huffman_encode("the quick brown fox")
    codes = list(build_codes(root).values())
    for i, c1 in enumerate(codes):
        for j, c2 in enumerate(codes):
            if i != j:
                assert not c2.startswith(c1), f"{c1} is a prefix of {c2}"
    print("Prefix-free property holds.")


test_huffman_roundtrip()
test_huffman_compression()
test_prefix_free()
```

The compression ratio test shows the payoff: skewed data compresses hard because frequent symbols get 1-2 bit codes instead of 8. **Runtime:** building the tree does `n` heap operations of `O(log n)` each → `O(n log n)` where `n` is the alphabet size.

## The backtracking framework

Now the opposite mindset. Where greedy commits and walks forward, **backtracking explores**: it tries a choice, recurses, and if that path leads nowhere, it undoes the choice and tries the next one. It's a systematic, complete search of a **decision tree**.

The skeleton is always the same three moves: **choose / explore / un-choose**:

```python
def backtrack(state):
    if is_solution(state):
        record(state)
        return
    for choice in candidates(state):
        if is_valid(choice, state):     # PRUNE: skip doomed branches early
            make(choice, state)         # choose
            backtrack(state)            # explore
            undo(choice, state)         # un-choose (backtrack!)
```

Three things to internalize:

- **The decision tree.** Each node is a partial solution; each edge is a choice. Backtracking is a depth-first walk of this tree. A naive walk visits every leaf, which is exponential. Backtracking's power is that it doesn't have to.
- **Pruning is everything.** The `is_valid` check lets us cut off whole subtrees the moment a partial solution can't possibly extend to a full one. Good pruning turns an impossible brute force into something that finishes instantly.
- **Un-choosing must perfectly reverse choosing.** If `make` mutates shared state, `undo` has to restore it exactly, or sibling branches get corrupted. This is the #1 source of backtracking bugs.

## Build it - N-Queens

Place `N` queens on an `N×N` board so no two attack each other (no shared row, column, or diagonal). Classic backtracking.

**Key insight for pruning:** place exactly one queen per row, going row by row. Then you only have to check columns and the two diagonals. A queen at `(row, col)` shares a diagonal with another at `(r, c)` iff `row - col == r - c` (the `↘` diagonal) or `row + col == r + c` (the `↙` diagonal). We track occupied columns and diagonals in sets for `O(1)` conflict checks.

```python
def solve_n_queens(n):
    """Return all solutions. Each solution is a list where index=row, value=col."""
    solutions = []
    cols = set()          # occupied columns
    diag1 = set()         # occupied "row - col" diagonals
    diag2 = set()         # occupied "row + col" diagonals
    placement = []        # placement[row] = col

    def backtrack(row):
        if row == n:                      # placed a queen in every row: solved
            solutions.append(placement[:])
            return
        for col in range(n):
            # PRUNE: skip any column/diagonal already attacked.
            if col in cols or (row - col) in diag1 or (row + col) in diag2:
                continue
            # choose
            cols.add(col)
            diag1.add(row - col)
            diag2.add(row + col)
            placement.append(col)
            # explore
            backtrack(row + 1)
            # un-choose
            cols.remove(col)
            diag1.remove(row - col)
            diag2.remove(row + col)
            placement.pop()

    backtrack(0)
    return solutions


def count_n_queens(n):
    return len(solve_n_queens(n))


def render_board(solution):
    """Pretty-print one solution as a board of Q and ."""
    n = len(solution)
    rows = []
    for col in solution:
        rows.append("".join("Q" if c == col else "." for c in range(n)))
    return "\n".join(rows)
```

### Stepped trace - the 4-Queens decision tree

This is where backtracking clicks. Let's walk the search for `N=4` row by row, writing the board as four columns `0 1 2 3` and marking where we choose, where pruning cuts a branch, and where we backtrack (un-choose). Columns are 0-indexed.

```
ROW 0: try col 0.   choose (0,0).  board:  Q . . .
  ROW 1: col 0 ✗ same column
         col 1 ✗ diagonal of (0,0)        <- PRUNED, never recurse
         col 2 ✔ choose (1,2).  board:  Q . . . / . . Q .
    ROW 2: col 0 ✗ column ;  col 1 ✗ diag ;  col 2 ✗ column ;  col 3 ✗ diag
           NO legal column in row 2  ->  DEAD END
    BACKTRACK: un-choose (1,2)
         col 3 ✔ choose (1,3).  board:  Q . . . / . . . Q
    ROW 2: col 0 ✗ column ;  col 1 ✔ choose (2,1).  board: Q.../ ...Q / .Q..
      ROW 3: col 0 ✗ ; col 1 ✗ ; col 2 ✗ diag/col ; col 3 ✗
             NO legal column  ->  DEAD END
      BACKTRACK: un-choose (2,1)
           col 2 ✗ ; col 3 ✗   -> ROW 2 exhausted, DEAD END
    BACKTRACK: un-choose (1,3)  -> ROW 1 exhausted, DEAD END
  BACKTRACK: un-choose (0,0)

ROW 0: try col 1.   choose (0,1).  board:  . Q . .
  ROW 1: col 0 ✗ diag ; col 1 ✗ col ; col 2 ✗ diag ; col 3 ✔ choose (1,3)
    ROW 2: col 0 ✔ choose (2,0).  board: .Q../ ...Q / Q...
      ROW 3: col 0 ✗ ; col 1 ✗ ; col 2 ✔ choose (3,2)
             ROW == 4  ->  SOLUTION  [1, 3, 0, 2]
```

The first whole branch under `(0,0)` collapses into dead ends; backtracking patiently un-chooses each placement and rewinds to the previous fork, exactly like retracing steps in the maze. The `✗` lines marked *column*/*diag* are pruning: the `is_valid` check (`col in cols or (row-col) in diag1 or (row+col) in diag2`) refuses those placements before recursing, so the search never wastes time below them. Trying `col 1` in row 0 leads cleanly to the solution `[1, 3, 0, 2]`, queens at `(0,1),(1,3),(2,0),(3,2)`. By symmetry the only other solution is its mirror, `[2, 0, 3, 1]`, which is why `count_n_queens(4) == 2`.

## Build it - Sudoku solver

Sudoku is backtracking at its most satisfying. Fill a 9×9 grid so every row, column, and 3×3 box contains digits 1-9 exactly once. The empty cells are the decision points.

```python
def solve_sudoku(board):
    """
    board: 9x9 list of lists; 0 means empty. Solves IN PLACE.
    Returns True if a solution exists (board is filled), False otherwise.
    """
    empty = find_empty(board)
    if empty is None:
        return True                       # no empty cell left: solved
    row, col = empty

    for digit in range(1, 10):
        if is_valid_move(board, row, col, digit):   # PRUNE invalid digits
            board[row][col] = digit       # choose
            if solve_sudoku(board):       # explore
                return True
            board[row][col] = 0           # un-choose (backtrack)

    return False                          # no digit worked: dead end


def find_empty(board):
    """Return (row, col) of the first empty cell, or None if full."""
    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:
                return (r, c)
    return None


def is_valid_move(board, row, col, digit):
    """Can `digit` go at (row, col) without breaking Sudoku rules?"""
    # Row and column.
    for i in range(9):
        if board[row][i] == digit or board[i][col] == digit:
            return False
    # 3x3 box.
    box_r, box_c = 3 * (row // 3), 3 * (col // 3)
    for r in range(box_r, box_r + 3):
        for c in range(box_c, box_c + 3):
            if board[r][c] == digit:
                return False
    return True


def print_board(board):
    lines = []
    for r in range(9):
        if r % 3 == 0 and r != 0:
            lines.append("-" * 21)
        row_cells = []
        for c in range(9):
            if c % 3 == 0 and c != 0:
                row_cells.append("|")
            row_cells.append(str(board[r][c]) if board[r][c] != 0 else ".")
        lines.append(" ".join(row_cells))
    return "\n".join(lines)
```

## Build it - subsets and permutations

Two more classic backtracking exercises. Generating all subsets and all permutations is the same choose/explore/un-choose machinery, and seeing them side by side cements the pattern.

**Subsets.** At each index, make a binary decision: include this element or not. The decision tree has depth `n` and `2ⁿ` leaves, exactly the number of subsets.

```python
def generate_subsets(nums):
    """All 2^n subsets via include/exclude backtracking."""
    result = []
    current = []

    def backtrack(start):
        result.append(current[:])         # every node is itself a valid subset
        for i in range(start, len(nums)):
            current.append(nums[i])        # choose: include nums[i]
            backtrack(i + 1)               # explore the rest
            current.pop()                  # un-choose

    backtrack(0)
    return result
```

**Permutations.** At each position, choose which unused element goes here. A `used` flag set prunes already-placed elements. Depth `n`, `n!` leaves.

```python
def generate_permutations(nums):
    """All n! orderings via backtracking with a used-set."""
    result = []
    current = []
    used = [False] * len(nums)

    def backtrack():
        if len(current) == len(nums):      # filled every position
            result.append(current[:])
            return
        for i in range(len(nums)):
            if used[i]:                    # PRUNE: already placed
                continue
            used[i] = True                 # choose
            current.append(nums[i])
            backtrack()                    # explore
            current.pop()                  # un-choose
            used[i] = False
    backtrack()
    return result
```

## Worked example - Combination Sum (backtracking with reuse + pruning)

A backtracking problem that shows two extra wrinkles: **reusing elements** and **pruning a sorted candidate list**. **Combination Sum:** given distinct positive `candidates` and a `target`, find all unique combinations that sum to `target`. Each candidate may be used *unlimited* times.

Greedy can't touch this: we don't want one answer, we want all of them, and which combinations exist depends on global structure, not a local rule. So we backtrack. Two design choices make it clean and fast:

- Pass a `start` index into the recursion (and allow reusing the same index `i`, not `i+1`) so combinations don't repeat in different orders: `[2,2,3]` is generated once, never also as `[2,3,2]`.
- **Sort candidates**, so that once a candidate exceeds the remaining target we can `break` out of the whole loop, since every later candidate is even bigger. That's the pruning.

```python
def combination_sum(candidates, target):
    """All unique combos (with reuse) summing to target. Backtracking + pruning."""
    result = []
    current = []
    candidates = sorted(candidates)          # enables the break-prune below

    def backtrack(start, remaining):
        if remaining == 0:
            result.append(current[:])        # current[:] - copy, not the live list!
            return
        for i in range(start, len(candidates)):
            c = candidates[i]
            if c > remaining:                # PRUNE: sorted, so all later are bigger too
                break
            current.append(c)               # choose
            backtrack(i, remaining - c)     # explore - reuse i (unlimited use)
            current.pop()                   # un-choose

    backtrack(0, target)
    return result


def test_combination_sum():
    assert sorted(combination_sum([2, 3, 6, 7], 7)) == sorted([[2, 2, 3], [7]])
    assert sorted(combination_sum([2, 3, 5], 8)) == sorted(
        [[2, 2, 2, 2], [2, 3, 3], [3, 5]])
    assert combination_sum([2], 1) == []     # impossible
    # Every returned combination really sums to the target.
    for combo in combination_sum([2, 3, 6, 7], 7):
        assert sum(combo) == 7
    print("Combination Sum passed.")


test_combination_sum()
```

**Why backtracking is the right tool.** This is the "generate all solutions satisfying a constraint" signature, the giveaway for backtracking. The `start` index prevents permutation-duplicates, recursing on `i` (not `i+1`) permits reuse, and the sorted `break` prunes hopeless branches. The `current[:]` copy is essential: appending the live `current` list would store a reference that later `pop()`s mutate (the aliasing bug covered in Common Mistakes). **Runtime:** exponential in the worst case, roughly `O(N^(target/min_candidate))` nodes, which is unavoidable since the output itself can be exponentially large.

## Branch-and-bound (a high-level note)

Backtracking is built for constraint satisfaction: find any or all solutions that obey the rules. **Branch-and-bound** adapts the same tree search for optimization: find the best solution by some cost.

The new ingredient is a **bound**: at every partial solution, cheaply compute an optimistic estimate of the best complete solution reachable from here (an upper bound for maximization, lower bound for minimization). Keep track of the best *complete* solution found so far (the **incumbent**). Then:

> If a node's optimistic bound is no better than the incumbent, **prune the whole subtree**: it cannot possibly beat what we already have.

That's the same pruning philosophy as backtracking's validity check, but driven by *cost potential* instead of *feasibility*. It's how you tackle 0/1 knapsack, traveling-salesman, and other NP-hard optimization problems in practice: still exponential in the worst case, but the bound slashes the search dramatically on real inputs. The tighter and cheaper your bound, the more you prune. We won't implement it fully here, but recognizing the pattern (backtracking plus a bounding function on partial solutions) is the takeaway.

## Common mistakes

The bugs in this chapter are sneaky: the code looks right and often even passes a small test before falling over.

- **Assuming greedy is correct without proof: the coin-change trap.** Greedy feels obviously right, you ship it, and it silently returns suboptimal answers on inputs you didn't test. Coins `{1,3,4}` making `6` is the canonical landmine. **Fix:** before trusting any greedy, either prove the greedy-choice property (exchange argument) or compare against a brute-force/DP oracle on random inputs. If you can't prove it, don't trust it.

- **Wrong greedy sort key in interval problems.** Interval scheduling is provably optimal only when you sort by **finish time**. Sort by start time and you might pick a long early-starting interval that blocks everything; sort by length (shortest first) and a short interval straddling two others can wreck the count. The sort key is the algorithm; pick the wrong one and you've solved a different problem.

```python
def schedule_by_start(intervals):
    chosen = []; last = float("-inf")
    for s, f in sorted(intervals, key=lambda iv: iv[0]):   # WRONG key: start
        if s >= last:
            chosen.append((s, f)); last = f
    return chosen

# A long early interval starves out two short compatible ones.
bad = [(0, 10), (1, 3), (4, 6)]
assert len(schedule_by_start(bad)) == 1        # buggy: only (0,10)
assert len(interval_scheduling(bad)) == 2      # correct: (1,3) and (4,6)
print("Sort-key bug demonstrated:", schedule_by_start(bad), "vs", interval_scheduling(bad))
```

- **Forgetting to un-choose (corrupts sibling branches).** In backtracking, every `make`/`choose` must be matched by an `undo`/`un-choose` on the way back up. Forget the `current.pop()` or `cols.remove(col)` and the next sibling branch inherits your leftover state: phantom extra elements, false conflicts, and wrong answers that are maddening to trace. The choose and un-choose should look like mirror images right next to the recursive call.

- **`current` vs `current[:]`: the aliasing bug.** When you record a solution, append a copy: `result.append(current[:])`, not `result.append(current)`. The second stores a reference to the one live list you keep mutating; after the search finishes, every "solution" in `result` is the same (probably empty) list. This bug produces output like `[[], [], [], []]` and confuses everyone the first time.

```python
def subsets_BUGGY(nums):
    result = []; current = []
    def bt(start):
        result.append(current)             # BUG: stores a live reference
        for i in range(start, len(nums)):
            current.append(nums[i]); bt(i + 1); current.pop()
    bt(0)
    return result

# All entries alias the same list, which ends up empty -> garbage output.
assert subsets_BUGGY([1, 2]) == [[], [], [], []]   # NOT real subsets!
assert generate_subsets([1, 2]) != [[], [], [], []]  # the [:] version is correct
print("Aliasing bug:", subsets_BUGGY([1, 2]))
```

- **Weak or missing pruning → accidental exponential blowup.** Backtracking without an `is_valid` check still works but explores the entire tree. N-Queens without diagonal pruning, or combination-sum without the sorted `break`, can crawl from milliseconds to minutes. Prune as early and as cheaply as you can: kill a branch the instant it can't lead to a solution.

- **Not restoring shared state (sets, board cells, "visited" marks).** This is the same un-choose rule applied to mutable shared structures. In word search you mark a cell visited (`board[r][c] = "#"`) and must restore it before returning, or that cell is poisoned for sibling paths. The same goes for a `visited` set, a Sudoku cell reset to `0`, or a `used[i]` flag: restore everything you touched.

- **Infinite recursion from a missing/wrong base case.** Every backtracking function needs a base case that *stops*: `row == n`, `remaining == 0`, `index == len(s)`. Omit it, or write a base case the recursion can step past (e.g. checking `== target` while the sum overshoots), and you recurse forever: `RecursionError` if you're lucky, a hang if you're not. Make sure the recursion strictly moves toward the base case every call.

## On the job / interview angle

Greedy and backtracking are bread-and-butter technical-interview material; together they cover a huge slice of the medium/hard problem space. The skill being tested isn't the code, it's pattern recognition: naming the paradigm fast, then (for greedy) justifying it.

**Recognition cues, greedy:**
- "Find the maximum number of non-overlapping X" or "the minimum number of Y" (intervals, removals, jumps, platforms).
- Anything with intervals sorted by start or finish.
- You can articulate a one-line rule ("always take the earliest finisher") and prove it with an exchange/stay-ahead argument.
- A single forward sweep maintaining a running best (`farthest`, `last_finish`, a tank total) solves it.

**Recognition cues, backtracking:**
- "Generate all" or "find all" combinations, permutations, subsets, partitions.
- "Place items subject to constraints": the N-Queens / Sudoku / constraint-satisfaction family.
- The answer is a set of solutions (or "does any valid arrangement exist?"), and choices interact so you can't decide one in isolation.

**The big warning: greedy is risky.** In an interview, never assert a greedy solution is correct without either a proof sketch or a counterexample check. Interviewers love handing you a problem that looks greedy but isn't (coin change, 0/1 knapsack, longest increasing subsequence). The strong move: "Greedy by [rule], let me sanity-check it against a small case / convince myself with an exchange argument… if that fails, I'd fall back to DP." Showing you know greedy can be wrong is often worth more than the solution itself.

**Representative problems mapped to the right paradigm:**

| Problem | Paradigm | Key idea |
|---|---|---|
| Jump Game / Jump Game II | **Greedy** | track farthest reachable frontier |
| Merge Intervals / Insert Interval | **Greedy** | sort by start, sweep & merge |
| Non-overlapping Intervals | **Greedy** | sort by finish, count keepers |
| Gas Station | **Greedy** | reset start when tank goes negative |
| Subsets / Subsets II | **Backtracking** | include/exclude per index |
| Combination Sum / Permutations | **Backtracking** | choose/explore/un-choose |
| N-Queens / Sudoku Solver | **Backtracking** | place under constraints, prune |
| Word Search | **Backtracking** | DFS on grid, mark & restore cells |

Drill these until the paradigm is reflexive; the implementation is just the choose/explore/un-choose template or a sort-plus-sweep, both of which you've now built from scratch.

### Solutions

**1. Assign Cookies (greedy).**
*Rule:* sort both; give the smallest cookie that satisfies the least greedy remaining child. Wasting a big cookie on a small child is never better than saving it. Exchange argument: if an optimal assignment gives child a bigger cookie than needed, you could swap in a smaller sufficient one without losing anyone.

```python
def find_content_children(g, s):
    g = sorted(g); s = sorted(s)
    child = cookie = 0
    while child < len(g) and cookie < len(s):
        if s[cookie] >= g[child]:    # this cookie satisfies this child
            child += 1
        cookie += 1                   # either way, this cookie is used up
    return child

assert find_content_children([1, 2, 3], [1, 1]) == 1
assert find_content_children([1, 2], [1, 2, 3]) == 2
```
*Complexity:* `O(n log n + m log m)` for the sorts, then a linear two-pointer sweep.

**2. Non-overlapping Intervals (greedy).**
*Rule:* sort by **finish time** and keep every interval compatible with the last kept one; count the rest as removals. This is interval scheduling in disguise: maximizing keepers = minimizing removals. The earlier exchange-argument proof applies directly.

```python
def erase_overlap_intervals(intervals):
    if not intervals:
        return 0
    intervals = sorted(intervals, key=lambda x: x[1])   # by FINISH
    removals = 0
    last_end = float("-inf")
    for s, e in intervals:
        if s >= last_end:
            last_end = e          # keep it
        else:
            removals += 1         # overlaps -> must remove
    return removals

assert erase_overlap_intervals([[1, 2], [2, 3], [3, 4], [1, 3]]) == 1
assert erase_overlap_intervals([[1, 2], [1, 2], [1, 2]]) == 2
assert erase_overlap_intervals([[1, 2], [2, 3]]) == 0
```
*Complexity:* `O(n log n)`.

**3. Gas Station (greedy).**
*Rule:* if `sum(gas) < sum(cost)` it's impossible. Otherwise sweep once keeping a running tank; whenever it goes **negative**, no station up to here can be the start, so reset the candidate start to `i+1` and zero the tank. *Why correct:* if you run dry going from `start` to `i`, every station between them also fails (each had even less surplus to begin with), so jumping past them loses nothing, and a total surplus guarantees the surviving start completes the loop.

```python
def can_complete_circuit(gas, cost):
    if sum(gas) < sum(cost):
        return -1
    total = 0; start = 0
    for i in range(len(gas)):
        total += gas[i] - cost[i]
        if total < 0:             # can't reach i+1 from current start
            start = i + 1
            total = 0
    return start

assert can_complete_circuit([1, 2, 3, 4, 5], [3, 4, 5, 1, 2]) == 3
assert can_complete_circuit([2, 3, 4], [3, 4, 3]) == -1
```
*Complexity:* `O(n)` time, `O(1)` space.

**4. Task Scheduler (greedy / counting).**
*Rule:* the most frequent task dictates the skeleton. With `max_count` copies of the busiest task and cooldown `n`, lay them out as `(max_count - 1)` full frames of width `(n + 1)`, then a final frame holding every task that ties for `max_count`. The answer is `max(len(tasks), (max_count-1)*(n+1) + n_max)`, the `len(tasks)` guard covers the case where there are so many distinct tasks that no idling is ever needed.

```python
from collections import Counter

def least_interval(tasks, n):
    counts = Counter(tasks)
    max_count = max(counts.values())
    n_max = sum(1 for v in counts.values() if v == max_count)
    return max(len(tasks), (max_count - 1) * (n + 1) + n_max)

assert least_interval(["A", "A", "A", "B", "B", "B"], 2) == 8
assert least_interval(["A", "A", "A", "B", "B", "B"], 0) == 6
assert least_interval(["A", "A", "A", "C", "C", "C", "D", "D", "E", "E"], 2) == 10
```
*Complexity:* `O(total tasks)` to count, then `O(1)` arithmetic.

**5. Subsets II (backtracking, skip duplicates).**
Sort first so duplicates are adjacent; at each recursion level, skip a value equal to the previous one at the same level (`i > start and nums[i] == nums[i-1]`) to avoid generating the same subset twice.

```python
def subsets_with_dup(nums):
    nums = sorted(nums)
    result = []; current = []
    def bt(start):
        result.append(current[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue                       # skip duplicate at this level
            current.append(nums[i]); bt(i + 1); current.pop()
    bt(0)
    return result

got = subsets_with_dup([1, 2, 2])
assert sorted(got) == sorted([[], [1], [1, 2], [1, 2, 2], [2], [2, 2]])
```
*Complexity:* `O(n · 2ⁿ)` in the worst case (output size).

**6. Permutations II (backtracking, skip duplicates).**
Sort, track `used`, and skip a duplicate value unless its identical predecessor is already used in the current path (`nums[i] == nums[i-1] and not used[i-1]`). This forces duplicates to be placed in a fixed left-to-right order, killing repeats.

```python
def permute_unique(nums):
    nums = sorted(nums)
    result = []; current = []; used = [False] * len(nums)
    def bt():
        if len(current) == len(nums):
            result.append(current[:]); return
        for i in range(len(nums)):
            if used[i]:
                continue
            if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                continue                       # enforce order among duplicates
            used[i] = True; current.append(nums[i])
            bt()
            current.pop(); used[i] = False
    bt()
    return result

got = permute_unique([1, 1, 2])
assert sorted(got) == sorted([[1, 1, 2], [1, 2, 1], [2, 1, 1]])
```
*Complexity:* `O(n · n!)` worst case.

**7. Generate Parentheses (backtracking with constraints).**
Build the string char by char. Two rules keep it valid: only add `(` while `open < n`, and only add `)` while `close < open`. Hitting length `2n` records a solution.

```python
def generate_parenthesis(n):
    result = []; current = []
    def bt(open_count, close_count):
        if len(current) == 2 * n:
            result.append("".join(current)); return
        if open_count < n:
            current.append("("); bt(open_count + 1, close_count); current.pop()
        if close_count < open_count:
            current.append(")"); bt(open_count, close_count + 1); current.pop()
    bt(0, 0)
    return result

got = generate_parenthesis(3)
assert len(got) == 5                              # Catalan number C_3
assert "((()))" in got and "()()()" in got
```
*Complexity:* `O(4ⁿ / √n)` (the nth Catalan number), only valid strings are ever built.

**8. Palindrome Partitioning (backtracking).**
At each start position, try every prefix; if the prefix is a palindrome, fix it and recurse on the rest. Reaching the end of the string records one partitioning.

```python
def partition_palindrome(s):
    result = []; current = []
    def is_pal(t):
        return t == t[::-1]
    def bt(start):
        if start == len(s):
            result.append(current[:]); return
        for end in range(start + 1, len(s) + 1):
            piece = s[start:end]
            if is_pal(piece):
                current.append(piece); bt(end); current.pop()
    bt(0)
    return result

got = partition_palindrome("aab")
assert sorted(got) == sorted([["a", "a", "b"], ["aa", "b"]])
```
*Complexity:* `O(n · 2ⁿ)` worst case (up to `2^(n-1)` partitions, each costing `O(n)` to build/check).

**9. Word Search (backtracking on a grid).**
DFS from every cell. Mark the current cell visited (overwrite with a sentinel), recurse in the four directions, and restore the cell on the way back: the classic "mutate shared state, then un-mutate."

```python
def word_search(board, word):
    rows, cols = len(board), len(board[0])
    def bt(r, c, idx):
        if idx == len(word):
            return True
        if r < 0 or r >= rows or c < 0 or c >= cols or board[r][c] != word[idx]:
            return False
        tmp = board[r][c]; board[r][c] = "#"          # mark visited
        found = (bt(r + 1, c, idx + 1) or bt(r - 1, c, idx + 1) or
                 bt(r, c + 1, idx + 1) or bt(r, c - 1, idx + 1))
        board[r][c] = tmp                              # RESTORE (un-choose)
        return found
    for r in range(rows):
        for c in range(cols):
            if bt(r, c, 0):
                return True
    return False

grid = [["A", "B", "C", "E"], ["S", "F", "C", "S"], ["A", "D", "E", "E"]]
assert word_search([row[:] for row in grid], "ABCCED") is True
assert word_search([row[:] for row in grid], "SEE") is True
assert word_search([row[:] for row in grid], "ABCB") is False
print("Exercises 1-9 passed.")
```
*Complexity:* `O(rows · cols · 4^L)` where `L = len(word)`, four directions per step, depth `L`.

**10. Why general coin change isn't greedy.** Greedy "take the largest coin that fits" assumes the locally biggest coin is always part of an optimal solution, but a coin's real value depends on how cleanly the remainder can be made, a property of the future, not the present. With `{1,3,4}` making `6`, grabbing the `4` strands you at `2` (two pennies, total 3 coins) while skipping it gives `3+3` (2 coins). Because the choice interacts with the remaining subproblem, the greedy-choice property fails. **The fix is dynamic programming:** compute `best[a] = 1 + min over coins c of best[a-c]`, which does consider every first coin and remembers the best way to make every smaller amount: exactly the `optimal_coin_change` function from the top of this chapter.

## Mini-project - Meeting Room Scheduler

A second, self-contained mini-project that exercises two different greedy interval problems at once, including the heap-based "minimum rooms" variant. Given a list of meetings `(start, end)`:

1. **Max non-conflicting meetings in one room**: the classic earliest-finish greedy.
2. **Minimum rooms needed to host all meetings**: a different greedy using a min-heap of room end-times.
3. **An actual room assignment**: which meeting goes in which room.

```python
import heapq


def max_meetings_one_room(meetings):
    """Greedy by earliest finish: most meetings that fit in a single room."""
    chosen = []
    last_finish = float("-inf")
    for start, end in sorted(meetings, key=lambda m: m[1]):
        if start >= last_finish:
            chosen.append((start, end))
            last_finish = end
    return chosen


def min_rooms_needed(meetings):
    """
    Minimum rooms to host EVERY meeting. Greedy: process by start time, keep a
    min-heap of the end-times of rooms currently in use. Reuse the earliest-
    freeing room when possible; otherwise open a new room.
    """
    if not meetings:
        return 0
    in_use = []   # min-heap of end times
    for start, end in sorted(meetings, key=lambda m: m[0]):
        if in_use and in_use[0] <= start:
            heapq.heappop(in_use)        # earliest-ending room freed up; reuse it
        heapq.heappush(in_use, end)
        # heap size at any moment = rooms occupied simultaneously
    return len(in_use)


def assign_rooms(meetings):
    """Concrete assignment: {room_id: [meetings]}, using the same heap greedy."""
    in_use = []          # min-heap of (end_time, room_id)
    rooms = {}
    next_room = 0
    for start, end in sorted(meetings, key=lambda m: m[0]):
        if in_use and in_use[0][0] <= start:
            _, room_id = heapq.heappop(in_use)     # reuse the freed room
        else:
            room_id = next_room                    # need a brand new room
            next_room += 1
            rooms[room_id] = []
        rooms[room_id].append((start, end))
        heapq.heappush(in_use, (end, room_id))
    return rooms


def meeting_scheduler_demo():
    meetings = [(0, 30), (5, 10), (15, 20)]
    print("=== Meeting Room Scheduler ===")
    print("Meetings:", meetings)
    print("Max meetings in ONE room:", max_meetings_one_room(meetings))
    print("Min rooms to host ALL  :", min_rooms_needed(meetings))
    print("Room assignment        :", assign_rooms(meetings))
    return min_rooms_needed(meetings)


def test_meeting_scheduler():
    # min_rooms: (0,30) overlaps both others; (5,10) & (15,20) don't overlap
    # each other, so 2 rooms suffice.
    assert min_rooms_needed([(0, 30), (5, 10), (15, 20)]) == 2
    assert min_rooms_needed([(7, 10), (2, 4)]) == 1     # disjoint -> one room
    assert min_rooms_needed([]) == 0
    # max in one room: only one of the three pairwise-overlapping-with-(0,30)
    big = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9),
           (5, 9), (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
    assert len(max_meetings_one_room(big)) == 4

    # The room assignment must be internally conflict-free and cover everything.
    meetings = [(0, 30), (5, 10), (15, 20)]
    rooms = assign_rooms(meetings)
    assert len(rooms) == min_rooms_needed(meetings)     # uses minimum rooms
    for room_meetings in rooms.values():
        ordered = sorted(room_meetings)
        for i in range(1, len(ordered)):
            assert ordered[i][0] >= ordered[i - 1][1]   # no overlap within a room
    all_assigned = sorted(m for ms in rooms.values() for m in ms)
    assert all_assigned == sorted(meetings)             # every meeting placed once
    print("Meeting scheduler tests passed.")


test_meeting_scheduler()
meeting_scheduler_demo()
```

**Why both greedies are correct.** Max-meetings-one-room is exactly interval scheduling: earliest finish first, proven optimal earlier. Min-rooms works because, processing meetings in start order, the heap's size at any instant equals the number of meetings overlapping at that instant; the maximum such overlap is a hard lower bound on rooms (those meetings are pairwise simultaneous, so each truly needs its own room), and the algorithm only opens a new room when every existing room is still busy. So it hits the lower bound exactly. **Runtime:** both are `O(n log n)`: sorting dominates, and each meeting does `O(log n)` heap work.
